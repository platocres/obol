# Obol - Offensive Box Operations Ledger

Obol is a static, offline-capable browser workspace for OSCP-style labs, Active Directory practice, and CTFs. It combines target tracking, methodology guidance, command building, Evidence review, Next Steps, and report drafting without executing commands for the operator.

Live site: `https://platocres.github.io/obol/`

Current release: **v8.8**

Product hardening foundation: **v9.0**

Product hardening dashboard: `product-hardening.html`

Release history lives in [`CHANGELOG.md`](CHANGELOG.md). Architecture, source-accounting, Evidence, product-hardening, and release contracts live in dedicated engineering documents instead of being duplicated here.

## Use Obol

Obol is plain HTML, CSS, and JavaScript with no backend, no telemetry, and no automatic command execution. Engagement state stays in the browser unless the operator explicitly exports it.

**Human-run commands only.** Obol builds and explains commands, but the operator runs them externally in an authorized environment and returns output or a manual outcome back to Obol.

The normal loop is:

`Targets -> Evidence -> Next Steps -> operator runs command externally -> Evidence review or manual outcome -> Next Steps recalculation -> Report`

Command recognition is not success. Manual success can advance the workflow once implemented, but report-ready proof still requires supporting Evidence. Durable proof rules live in [`docs/PROOF-CONTRACT.md`](docs/PROOF-CONTRACT.md).

## v9 product-hardening phase

v9.0 begins the product-hardening phase. This is separate from the completed Orange queue. It tracks the engineering work needed to make Obol faster, cleaner, easier to extend, and more useful as a web app.

The product-hardening queue covers:

- critical correctness and version identity;
- runtime consolidation and asset manifest work;
- UI/UX repair;
- GUI command builders for every runnable tool/action;
- credential-mode support for passwords, hashes, tickets, certificates, keys, cookies, and tokens;
- manual outcome flow for success, failure, blocked, and skipped states;
- private notes integration from Brandon's HTB and OffSec Evernote exports;
- quiet offline/performance improvements through browser-native capabilities;
- browser, screenshot, contrast, and asset-reference QA.

The queue source of truth is `data/product-hardening/product-hardening-queue.js`. The standalone dashboard is `product-hardening.html`. Future work should integrate the dashboard into the current app after runtime consolidation rather than adding another brittle monkey-patch layer.
