# Obol v3.6

v3.6 advances the first priorities in the v3.5 README without changing Obol's human-run execution model.

## Rubeus workbench

Tool Library now owns a dedicated Rubeus workbench instead of leaving Windows Kerberos commands as isolated card snippets. The workbench maps each command back to the existing methodology card and uses the active Obol context as a default where appropriate.

Current actions:

- AS-REP Roast → `asrep-roast`
- Kerberoast → `kerberoast`
- Ask TGT → `kerberos-tickets`
- Pass the Ticket → `kerberos-tickets`
- S4U / Delegation → `delegation-abuse`

Controls cover action-specific user/domain/DC scope, output files, SPNs, ticket material, credential-material type, impersonation identity, alternate service, PTT behavior, and no-wrap behavior where relevant.

Copying from the workbench records the exact generated command as the latest historical command snapshot for the mapped methodology card. **Review output in Evidence** pre-fills that command and sends a lineage source into Evidence so approved artifacts and activity can retain the same command/card context.

Obol still does not run Rubeus, install it, or validate a target.

## Rubeus-aware Evidence

v3.6 adds command-intent handling for:

- `Rubeus.exe asreproast`
- `Rubeus.exe kerberoast`
- `Rubeus.exe asktgt`
- `Rubeus.exe ptt`
- `Rubeus.exe s4u`

Messy terminal text is normalized before terminal activity matching, including ANSI output and common copied shell prompts.

Outcome inference stays conservative:

- `$krb5asrep$` evidence can establish `kerberos.asrep_hash`
- `$krb5tgs$` evidence can establish `kerberos.tgs_hash`
- strong TGT/ticket-import or S4U success evidence can establish `kerberos.ticket`
- S4U does **not** imply `access.admin` merely because a service ticket was obtained

Existing browser-local activities can be repaired forward when their Rubeus command intent is unambiguous.

## Exact-command lineage

v3.5 used a conservative context-plus-time correlation for older intake/network producers. v3.6 adds a stronger first pass: when a producer has a preserved command and exactly one activity in the same context has that exact normalized command, the exact activity ID is attached regardless of nearby unrelated activity timestamps.

If the same command maps to multiple activities in the same context, Obol leaves the producer unresolved rather than guessing. Timestamp fallback remains available only when the producer has no preserved command and the older v3.5 uniqueness rule is satisfied.

## Methodology integration

The existing delegation methodology gains a Windows Rubeus S4U implementation using shared `impersonate` and `spn` parameters. The dedicated Tool Library workbench remains the richer builder for S4U-specific options.

Rubeus is also registered as a first-class tool family with upstream source/help metadata.

The Orange Cyberdefense 2025.03 Active Directory mindmap remains the project North Star and is linked from the workbench as a secondary methodology reference:

https://orange-cyberdefense.github.io/ocd-mindmaps/img/mindmap_ad_dark_classic_2025.03.excalidraw.svg

v3.6 does not claim the entire mindmap is complete. It advances the Kerberos/Rubeus interface explicitly called out by the README while preserving the remaining mindmap-driven backlog.
