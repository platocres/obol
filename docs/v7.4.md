# Obol v7.4

v7.4 completes source-depth accounting for the pinned Orange Cyberdefense `authenticated.md` family while preserving Obol's human-run, Evidence-first operator model.

## Scope

The release decomposes `authenticated.md` into nineteen meaningful atomic source units covering authenticated user enumeration, SMB share inventory, BloodHound Legacy and CE collection, LDAP and AD-integrated DNS inventory, AD CS and SCCM enumeration routing, automated AD posture assessment, Kerberoasting, four authenticated coercion families, Entra / AD Connect discovery, lateral-movement routing, and authenticated known-vulnerability routing.

All nineteen units are modeled and fidelity-complete against the North Star dimensions. Existing mature owners are reused where they already satisfy the Run -> Evidence -> Next Steps -> Report contract. New v7.4 owners are limited to the gaps that actually needed dedicated product behavior: classic authenticated enumeration, automated posture assessment, and authenticated coercion.

## Conservative Evidence boundaries

v7.4 deliberately keeps discovery, assessment, coercion, and exploitation consequences separate.

Authenticated enumeration output can establish user, share, directory, graph, or DNS inventory facts, but it does not establish writable control, execution, administrator access, or privilege. AD-miner, PingCastle, and adPEAS reports are posture evidence and candidate generators, not automatic vulnerability or compromise proof. File, WebDAV, RPC, and Kerberos coercion operations establish only the trigger/preparation state unless later listener or relay Evidence independently proves inbound authentication or a downstream consequence.

The known-vulnerability parent is implemented as routing to seven existing vulnerability-specific owners rather than as a generic exploit card. Each child retains its own detection, execution, access, privilege, and cleanup boundaries.

The release remains compatible with the established exact-head release workflow.
