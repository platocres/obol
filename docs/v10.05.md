# Obol v10.05

v10.05 is a product-hardening release for the authentication and enumeration Tool Builder batch.

## What changed

- Added schema-driven builders for Hydra, Kerbrute, smbclient, SMBMap, enum4linux-ng, ldapsearch, and Responder.
- Kept commands minimal by default. Required targets, identities, credential material, domain/base-DN inputs, or interfaces must be real before the corresponding mode becomes runnable; rate, thread, timeout, output, recursion, filter, capture, and escalation options remain explicit additions.
- Split smbclient and SMBMap into separate builders so share/session interaction and permission mapping do not collapse into one ambiguous workflow.
- Superseded legacy enum4linux with the enum4linux-ng builder rather than maintaining duplicate active command models.
- Wired the new builders into the current Tools/Card/Path runtime without adding execution. Obol continues to generate commands for human review and external execution only.

## Evidence and Next Steps

The batch ships executable Evidence ingestion in the same release. Hydra and Kerbrute distinguish credential hits, valid usernames, no-hit results, lockout conditions, and KDC/network/module failures. smbclient and SMBMap distinguish share discovery, session/authentication state, read/write/no-access results, and connection failures. enum4linux-ng and ldapsearch preserve enumeration, bind/query, denied, partial/referral, and transport states. Responder keeps passive analyze observations, listener state, name-resolution exposure, captured NetNTLM challenge-response material, failures, and shutdown separate.

Hydra and Kerbrute Evidence reconnects to the password-spray safety workflow. SMB, LDAP, enum4linux-ng, and Responder Evidence reconnects to the AD enumeration workflow. A valid username is not a valid password; a captured NetNTLM exchange is not a plaintext or reusable credential; a listed share is not write access; successful authentication does not manufacture administrative access, execution, or privilege.

## Queue hygiene

The Tool Builder queue is active work only. v10.03, v10.04, and v10.05 are complete and therefore intentionally absent from both the canonical Tool Builder build queue and the README active queue. The next unfinished batch is v10.06, followed by the v10.07 implemented-tool Evidence/cross-surface audit. Release history belongs here and in `CHANGELOG.md`, not above unfinished work in the active queue.

A permanent queue lifecycle rule now requires each completed Tool Builder batch to remove itself from the active queue in the same PR and requires focused release regression to reject stale completed headings.

## Validation

`tests/run-v10.05-tests.js` covers schema validity, inventory promotion/supersession, minimal command generation, required-field behavior, additive controls, conservative positive/negative/blocked/partial Evidence states, Intake-to-Next-Steps handoff, runtime wiring, and active-queue retirement. The v10.05 test is part of the current-product historical regression phase. Browser smoke remains the required live-route/UI gate.

## Compatibility

Obol remains a static, browser-local application. No backend, account system, telemetry, install prompt, or automatic command execution was introduced. Existing v10.04 pivot builders and Evidence semantics remain intact; v10.05 extends the same schema/Evidence contract to authentication and enumeration tooling.
