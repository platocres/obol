# Obol v6.4 — Orange source-fidelity dashboard accounting

v6.4 changes the North Star accounting model so a broad canonical owner can no longer stand in for all meaningful subordinate Orange branches.

## What changed

- Preserved the existing 127-section canonical denominator at 93 implemented / 34 partial / 0 gaps / 0 stale, 73% fully implemented, 100% represented.
- Added `data/orange-fidelity-v6.4.js`, a machine-readable atomic source-fidelity ledger tied to the pinned Orange 2025.03 commit and source-file hash.
- Atomized `adcs.md` first because it demonstrates the breadth-versus-depth problem clearly: seven broad AD CS canonical parents now expose 19 meaningful source units across enumeration and the ESC families/variants in the pinned source.
- Added separate Dashboard denominators for source files atomized, frozen partial baselines decomposed, atomic units inventoried, broad-owner coverage, atomic review/completion, and the North Star requirement matrix.
- Added an AD CS drill-down table with search and family/status filtering so the Dashboard can show exactly which subordinate source units remain unaudited.
- Extended Build Next so atomic fidelity audits outrank still-unatomized source-depth baselines after implemented-quality debt, mapped-delivery debt, and canonical gaps are zero.
- Kept source-fidelity accounting separate from operational Evidence. The new ledger cannot create credentials, access, privilege, execution, or compromise facts.

## v6.4 baseline

- Canonical breadth: 93 / 127 implemented, 34 partial, 0 gaps, 100% represented.
- Methodology source files atomized: 1 / 17.
- Frozen partial baselines decomposed: 7 / 34.
- Atomic source units inventoried: 19.
- Atomic units fidelity-complete: 0 / 19 at the initial v6.4 baseline.
- AD CS source families represented in the atomic ledger: 13 including enumeration plus ESC1, ESC2/3, ESC4, ESC5, ESC6, ESC7, ESC8, ESC9/10, ESC11, ESC13, ESC14, and ESC15.

## Why this matters

The Dashboard can now truthfully show the difference between "Obol has a broad owner for this Orange section" and "Obol has actually audited every meaningful subordinate path and translated it into the website's Run → Evidence → Next Steps → Report loop."
