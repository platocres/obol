# Obol v9.42 — Core ownership flattening

v9.42 continues the Runtime Layer Consolidation package by completing `runtime-core-flattening`.

This release is scoped to the core state and derivation ownership area. It replaces the exact-concatenation core owner with a generated semantic delta replay that preserves browser-local workspace migration, proof boundaries, applicability, ranking, progress accounting, and report readiness without executing the historical core fragment chain directly.

## What changed

- Added `tools/sync-core-current.js`, which regenerates `assets/obol-core-current.js` from the frozen 69-fragment core ledger by preserving the shared v2 base scope and replaying surviving release deltas inside isolated lexical blocks.
- Added `tools/validate-core-current-equivalence.js`, proving the generated owner exposes the same `OBOL_CORE` roots and `C.*` surface as the historical chain, preserves classic-script helper globals, exercises every per-release migration helper, and compares workspace migration/coercion, Evidence application, recommendation ranking, report readiness, project-model, search, network, sanitized-export, and Nmap-builder behavior.
- Updated `data/runtime-manifest.js` so the core area uses the `semantic-delta-replay` strategy and Node current runtime loads `assets/obol-core-current.js` instead of the 69 historical core fragments.
- Updated the runtime consolidation projection, Product Build Next queue, README, architecture docs, and Product Hardening docs to report 172 semantically flattened historical fragments, 125 still exact-owned fragments, and 30 retired Dashboard fragments.
- Closed `runtime-core-flattening` with an item-specific proof contract and v9.42 regression suite, while leaving application, Evidence parsing, and stylesheet flattening queued as separate ownership-area passes.

## Preserved boundaries

v9.42 preserves the v8.8 workspace/runtime schema identity, human-run command contract, Evidence/report proof boundaries, Product Hardening Dashboard ownership, frozen v9.5 historical ledger, and one-open-release-PR workflow.
