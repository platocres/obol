# Obol v9.25 — Notes Integration Foundation

v9.25 establishes the public-safe Notes Integration Foundation around the private `platocres/obol-source-notes` source repository.

## Scope

The release closes the six-item foundation package:

- `notes-enex-extraction`
- `notes-atomization-schema`
- `notes-field-panel`
- `notes-tool-influence`
- `notes-path-gap-influence`
- `qa-notes-ledger-test`

The separate `notes-disposition-burn-down` item remains live. v9.25 intentionally proves the ingestion, normalization, binding, and ledger system before attempting to disposition all 556 notes in one oversized release.

## Private-source boundary

Raw HTB and OffSec ENEX exports remain private. Public Obol stores only source-level counts and hashes, opaque note references, rewritten guidance, binding metadata, and disposition accounting. It does not ship raw note bodies, screenshots, flags, ENEX paths, or proprietary course text.

The private source inventory remains 352 HTB notes plus 204 OffSec notes, for 556 notes and 1,326 embedded resources total.

## Stable owners

`data/note-integration.js` is the stable non-versioned owner for:

- the sanitized private-source inventory projection;
- normalized atom kinds and disposition states;
- public-safe metadata atomization;
- aggregate ledger accounting;
- opaque lineage for modeled outputs;
- reviewed field-note outputs and their tool/Path bindings.

`data/field-notes.js` remains the stable public presentation contract. It now reads reviewed outputs from the note-integration owner dynamically instead of carrying a release-specific note list.

`assets/field-notes.js` lazily loads the note-integration owner only on field-note-bearing routes and renders collapsed contextual guidance on Cards, Tool pages, and Path.

## Initial reviewed outputs

v9.25 models four seed notes as rewritten Obol guidance. They cover credential-dump proof boundaries, pass-the-hash material routing, response-driven content discovery, and path-traversal proof sequencing. Their private source references are opaque IDs only.

These four modeled notes move the Notes Integration source ledger to 4/556 reviewed dispositions. The remaining 552 notes stay `pending-review`; they are not silently treated as modeled.

## Tool and Path influence

Tool-bound field notes appear on matching Tool pages, so note-derived lessons can influence command-builder choices and failure handling without adding bespoke execution code.

Path-bound notes appear as collapsed `Field-note branches` guidance. They may influence what the operator considers next, but they do not create facts, automatically reorder Evidence, execute commands, or become report proof.

## Validation

`tools/validate-note-integration.js` permanently checks the source totals, disposition reconciliation, public-safe atomization, opaque lineage, contextual tool/Path bindings, raw-source exclusion, and no-execution boundary.

`tests/run-v9.25-tests.js` adds release-level proof for all six atomic queue items and the v9.25 queue handoff.

```bash
node tools/validate-note-integration.js
node tools/validate-field-notes-ui.js
node tests/run-v9.25-tests.js
node tools/validate-product-hardening-queue.js
node tools/validate-asset-references.js
node tools/validate-current-release.js
node tools/sync-current-release.js --check
node tools/sync-product-build-next.js --check
node tools/validate-release-pr.js --repo-only
```

The exact final `[release-final]` head must pass smoke, preflight, and the complete historical regression chain before the PR is merge-ready.
