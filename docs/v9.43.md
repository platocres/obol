# Obol v9.43 — Application ownership area flattening

v9.43 continues the Runtime Layer Consolidation package by working `runtime-app-flattening`.

This release is scoped to the application ownership area: the report base, the shared v2 application prelude, and the historical workflow/UI overlays that the browser loads through `assets/obol-app-current.js`.

## What changed

- Retired the 21 superseded release-wave overlays `assets/app-v6.7.js` … `assets/app-v8.7.js` from live startup. The application ownership area now owns 43 exact-concatenation fragments instead of 64, and the frozen retired ledger grows from 30 to 51 fragments. `assets/obol-app-current.js` falls from 412,284 to 361,399 bytes — about 50 KB less JavaScript parsed on every operator page load. Request count is unchanged, because the browser already fetched one owner rather than one file per fragment; this release removes parse cost, not fetches.
- Added `tools/validate-app-current-equivalence.js`. It proves, structurally, that every retired overlay is inert under the shipped runtime rather than merely unused-looking.
- Added `tools/validate-app-dom-equivalence.js`. It is the browser-level counterpart: it renders every operator route with and without the retired overlays and requires byte-identical DOM.
- Updated `data/runtime-manifest.js`, the runtime consolidation projection, and README so every surface reports the same post-retirement figures: 276 consolidated fragments, 104 still exact-owned, 51 retired, and 215 historical scripts in operator startup (down from 236).
- Wired the structural proof into `tools/scope-check.js` and `tools/release-preflight.js`, and the browser proof into `.github/workflows/browser-smoke.yml`.
- Closed `runtime-app-flattening` with an item-specific proof contract and the v9.43 regression suite, leaving Evidence parsing and stylesheet flattening queued as separate ownership-area passes.

## Why these 21 overlays are superseded

Each retired overlay follows the same historical release-wave shape:

```js
function activeNN(){return typeof C!=='undefined'&&C.VERSION==='N.N.0';}
function decorateNN(){if(!activeNN())return; /* … dashboard wave panel … */}
const oldRouteNN=route;route=function(){oldRouteNN();for(const t of […])setTimeout(decorateNN,t);};
```

The workspace/runtime schema identity `C.VERSION` has been `8.8.0` since v8.8 and is deliberately frozen until an intentional storage migration changes it. Every `activeNN()` guard for `NN !== 88` is therefore permanently false, so `decorateNN()` returns before touching the DOM. What remains in each file is a `route` wrapper that only calls through, plus timers, `hashchange` listeners, and `MutationObserver`s that schedule that same short-circuited decorator.

`tools/validate-app-current-equivalence.js` re-derives all of this from source on every run — it reads the live `C.VERSION` out of the generated core owner, requires it to match none of the retired gates, and requires every top-level statement in every retired overlay to be one of the inert forms above. If a future release changes `C.VERSION`, or a retired file gains a real side effect, the validator fails instead of silently shipping a behavior change.

`assets/app-v8.8.js` is deliberately **not** retired: it is the one overlay whose guard matches the live `C.VERSION`, and it owns the current release bridge to `assets/workflow-current.js` and `assets/operator-route-current.js`.

## Why the retired set is exactly 21

Proving the retired fragments are dead is only half the argument; the other half is that nothing else in the area is. `tools/validate-app-dom-equivalence.js --audit-liveness` answers that by dropping each surviving fragment in turn and comparing the rendered DOM across every route.

Run against all 43 survivors, **every one changed the rendering of at least one route** — several of them every route. So the application area now contains exactly two kinds of fragment: 21 that provably cannot execute, and 43 that provably still do. No further fragment can leave this area without changing what the operator sees, which is why `runtime-app-flattening` closes here rather than leaving a residue of "probably unused" files.

The audit takes tens of minutes, so it is an on-demand tool rather than a CI gate. The fast proofs — structural inertness in Node, DOM equivalence in Chromium — run on every release and every browser-smoke run.

## Flattening by subtraction

Domain (v9.41) and core (v9.42) were flattened by *rewriting*: an authored semantic snapshot and a generated delta replay, each carrying its own equivalence proof because the shipped code changed. The application area is flattened by *subtraction* instead. No surviving line is rewritten — the owner is still the exact ordered concatenation of the fragments it keeps, byte for byte — so Evidence semantics, command behavior, recommendation logic, report lineage, and workspace compatibility have no way to move.

`docs/RUNTIME-COMPACTION.md` now records that preference: check for provable supersession before re-authoring an area. Retirement carries no rewrite risk, and this pass removed a third of the area without one.

## Preserved boundaries

v9.43 preserves the v8.8 workspace/runtime schema identity, the human-run command contract, Evidence and report proof boundaries, Product Hardening Dashboard ownership, the frozen v9.5 historical ledger (all 327 fragments remain on disk and reachable for regression), and the one-open-release-PR workflow.

The retirement removes files from *live startup only*. Nothing is deleted, and `manifest.scripts` still accounts for every historical fragment.

## Proving the proof, hermetically

`tools/validate-app-current-equivalence.js` exports its per-overlay proof as `proveOverlayInert(rel, source, liveVersion)` — a pure function of the fragment's source text — and runs it over the frozen files when invoked as a script. `tests/run-v9.43-tests.js` uses that export to mutate a retired overlay (give it a real top-level side effect, stop its decorator short-circuiting, un-stale its version gate) and require the shipped proof to reject each mutation. A proof that cannot fail proves nothing.

The mutations stay **in memory**. `tools/run-historical-contracts.js` executes suites concurrently and depends on every suite being hermetic, so a test that edited a tracked file in place — even briefly, even with a `finally` restore — would be observed by a sibling task as a genuine failure. Any future proof-of-a-proof in this repository should follow the same shape: export the pure decision, feed it mutated input, and never write into the working tree.
