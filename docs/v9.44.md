# Obol v9.44 — Evidence parsing ownership area flattening

v9.44 continues the Runtime Layer Consolidation package by working `runtime-evidence-flattening`.

This release is scoped to the Evidence parsing ownership area: the BloodHound ingest helpers and the versioned Intake parser overlays the browser loads through `assets/obol-evidence-current.js` when Evidence or Artifacts is opened.

## What changed

- Retired four Intake overlays — `assets/intake-v7.7.js`, `assets/intake-v7.8.js`, `assets/intake-v7.9.js`, `assets/intake-v8.2.js` — from the live runtime. The Evidence ownership area now owns 37 exact-concatenation fragments instead of 41, and the frozen retired ledger grows from 51 to 55 fragments. `assets/obol-evidence-current.js` falls from about 355 KB to 339 KB — roughly 16 KB less JavaScript parsed the first time an operator opens Evidence or Artifacts. (Request count is unchanged: the browser already fetched one owner rather than one file per fragment, so this removes parse cost, not fetches.)
- Added `tools/validate-evidence-current-equivalence.js`. It proves the retirement two independent ways: a **reachability** pass executes the whole frozen Intake chain fragment by fragment and confirms the four retired overlays never publish their `OBOL_INTAKE_*` global and never touch `OBOL_INTAKE_V21.analyzeTerminal`, while every surviving overlay does publish; a **differential** pass builds the Evidence runtime from the full frozen set and from the surviving set and requires byte-identical `OBOL_*` globals and `analyzeTerminal` output over a fixed operator transcript corpus.
- Filed `cc-evidence-chain-restore`: the four overlays were never dead-by-supersession, they were dead-by-defect, so the Evidence they were written to add is genuinely missing and is now tracked as its own queued correctness item rather than quietly written off.
- Updated `data/runtime-manifest.js`, the runtime consolidation projection, and README so every surface reports the same post-retirement figures: 272 consolidated fragments, 100 still exact-owned, 55 retired.
- Wired the equivalence proof into `tools/scope-check.js` and `tools/release-preflight.js`.
- Closed `runtime-evidence-flattening` with an item-specific proof contract and the v9.44 regression suite, leaving stylesheet flattening queued as the next separate ownership-area pass.

## Why these four overlays are dead code

The Intake overlays are a decorator chain. Every overlay reads the `analyzeTerminal` already published on an earlier `OBOL_INTAKE_*` global, wraps it, and writes the wrapper back onto `OBOL_INTAKE_V21`. The four retired overlays share one latent break:

- `intake-v7.6.js` reads `OBOL_INTAKE_V21`, decorates its `analyzeTerminal`, and publishes `OBOL_INTAKE_V76` carrying **helpers only** (`stage76`, `proof76`, …) — it never puts `analyzeTerminal` on `V76`.
- `intake-v7.7.js` hooks `const T=root.OBOL_INTAKE_V76` and guards `if(!C||!T||!T.analyzeTerminal||!M)return;`. Because `V76` has no `analyzeTerminal`, the guard is always true, so v7.7 returns immediately and never publishes `OBOL_INTAKE_V77`.
- `intake-v7.8.js` hooks `OBOL_INTAKE_V77` (undefined) → returns. `intake-v7.9.js` hooks `OBOL_INTAKE_V78` (undefined) → returns. `intake-v8.2.js` hooks `OBOL_INTAKE_V79` (undefined) → returns.

So in every load order the runtime actually produces, these four overlays run their guard and do nothing. Retiring them from the live runtime is observably inert, and `tools/validate-evidence-current-equivalence.js` proves it from real execution rather than from this reading.

The historical suite `tests/run-v7.7-tests.js` still passes because it constructs `OBOL_INTAKE_V76={analyzeTerminal:…}` by hand before loading v7.7 — it proves v7.7's proof logic in isolation, which is a legitimate historical contract and is preserved. It never asserted that v7.7 runs in the real runtime, and it does not.

## The behavior that was lost, and where it is tracked

Because the chain broke at v7.7, the Evidence these overlays were written to add never reached production: no-credentials DHCPv6/ARP poisoning and unauthenticated coercion beyond what `intake-v7.6.js` already owns, relay-SOCKS movement, WebDAV coercion, Windows local-exploit, and offline-cracking Evidence. This is a real defect, not a supersession. It is filed as `cc-evidence-chain-restore` (critical correctness): re-home that conservative Evidence onto the live chain — by correcting the hook target or re-authoring onto `OBOL_INTAKE_V21` — with proof boundaries intact, and add regression coverage that would have caught the broken link. v9.44 removes the dead files and files the gap; it does not restore the behavior, and it does not pretend the behavior was ever live.

## Compatibility

Retirement removes fragments from the live runtime only. Nothing leaves disk, the frozen 327-fragment v9.5 historical ledger stays complete, and browser-local workspace state, conservative Evidence interpretation, proof boundaries, command behavior, recommendation ranking, and report lineage are unchanged. The surviving 37-fragment chain is byte-identical to its frozen files, proven equivalent to the full frozen chain over the operator corpus.
