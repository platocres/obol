# Obol v10.14

## What changed

v10.14 is a product-hardening release that closes the operator scripts / LOTL track with a
**cross-surface audit and polish** pass. Builds v10.06–v10.13 restored script rendering, added the
exam-safe / LOTL metadata, put snippets on the Next Steps path, and read their output back as
Evidence. v10.14 fixes the Scripts UI so it reads correctly at any resolution, reformats the SQL
injection guidance into two focused operator tools, and adds a validator that keeps the four script
surfaces on one consistent model.

- **Scripts UI now reflows at any width.** The `.script-usage` rows used a fixed 64px label column,
  so long labels ("Exam-safe substitute for bloodhound-python, netexec", "Paste output back as
  Evidence") and the multi-child Evidence row wrapped one word per line. The when/where/how rows keep
  a bounded, wrap-safe two-column grid (single column under 520px), and the exam-safe substitute and
  Evidence callouts moved to a dedicated `.script-note` block layout with their own eyebrow label,
  accent rule, and a properly indented expectations list. The toolbar, card summary, badge row, and
  facet toggle now wrap instead of overflowing. Styling was added for the previously unstyled
  `.script-badges`, `.script-facet`, and `.script-evidence-expects` from Build B.
- **SQL injection is now two operator tools, not one wall of curl.**
  - New **SQLi login / auth bypass checklist** (`sqli-login`): a ready-to-fuzz list of
    authentication-bypass payloads for a username/password form — the common "there is a login page"
    case — with a curl replay and Burp Intruder guidance. A GUI builder sets the login endpoint,
    field names, and which field to inject.
  - The **Manual SQLi** snippet (`manual-sqli`) is reframed as a database-navigation tool with a
    GUI builder: pick the DB engine (MySQL / MariaDB, MS SQL Server, PostgreSQL) and the builder
    re-writes every stage in that dialect — fingerprint functions, schema → table → column
    navigation, string concatenation, error/blind fallbacks, and the RCE path — with the endpoint
    path, injected parameter, and loot table as engagement args and per-stage toggles. Its id,
    `substitutesFor: ['sqlmap']`, path metadata, and Evidence contract are unchanged, so the path
    proposal and output ingestion keep working.
- **New metadata contract validator** `tools/validate-script-metadata.js` (wired into the
  `v9-early-product` regression phase) fails the build when a script is structurally incomplete, when
  it claims `examSafe` / `substitutesFor` without the required `examSafeReason`, when a
  `pathProposable` script lacks `prereq` / `produces` / `lane`, when an `evidence` descriptor lists a
  fact outside `produces`, or when a builder profile exposes an invalid GUI control. This is the
  single guard that keeps the Tools / facet / Path / Evidence surfaces reading one model.

## Compatibility

Obol remains static and browser-local: no backend, telemetry, account system, or automatic command
execution. The scripts stay offline, human-run snippets; the new login checklist and the engine-aware
Manual SQLi builder generate text for the operator to run by hand and paste back — nothing is
executed and no fact is manufactured from command recognition. The workspace schema is unchanged
(v8.8). No new browser-loaded runtime asset was added (the new script and builder live in the
existing route-lazy `data/scripts.js` and `data/scripts-v2.5.js`; the validator is a Node tool), so
the request budget and ordinary startup are unaffected. The stylesheet change was made in the frozen
`obol-v2.3.css` fragment and re-flattened into `assets/obol-current.css` by the semantic cascade
generator.
