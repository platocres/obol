# Obol v9.20

v9.20 completes the canonical **curl Tool Builder** on the existing stable schema-driven Tool Builder platform. No new release-specific runtime layer is introduced.

## curl request surface

`tb-curl` gives the operator one explicit HTTP request builder for the common curl shapes used throughout Obol's web workflow:

- target URL and automatic, GET, HEAD, POST, PUT, PATCH, DELETE, or custom request methods;
- repeated request headers and cookie material;
- raw/form request data and JSON bodies;
- binary request bodies, direct file uploads, and multipart file fields;
- Basic and NTLM username/password authentication plus OAuth2 bearer-token input;
- HTTP proxy and optional proxy credentials;
- redirect following, TLS verification override, compressed responses, connect timeout, and total timeout;
- stdout, chosen-file, or remote-name response output;
- response-header capture, header inclusion, silent/error mode, verbose mode, fail-with-body behavior, and optional HTTP status output.

The implementation follows current upstream curl command-line contracts for request methods, repeated `-H/--header` values, `--user`, OAuth2 bearer authentication, multipart forms, `--upload-file`, and `--output`. Sensitive headers, cookies, body data, passwords, bearer tokens, and proxy passwords remain secret-bearing report-lineage inputs.

## Human-run and proof boundary

Obol still only generates, previews, and copies the command. It does not send the HTTP request, read upload files, or execute curl.

A generated command or manual success remains workflow activity. HTTP status, headers, response bodies, authentication results, redirect behavior, uploaded/downloaded files, and application-state claims become report-ready only after returned curl output or saved artifacts are reviewed as Evidence.

## Stable ownership

The existing owners remain unchanged:

- `data/tool-builder-schema.js`
