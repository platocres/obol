## Durable lessons added

### Upload acceptance versus impact

An accepted file is not impact by itself. Obol now reinforces a staged proof model covering stored name/location, reachability, server serving or processing behavior, and downstream effect.

### File-inclusion proof and scanning

File inclusion is decomposed into controllable target selection, reproducible read, transformed/source disclosure, remote retrieval where relevant, executable interpretation, and independent execution proof. Automated discovery starts from a known response signal and widens one dimension at a time rather than treating broad fuzzing output as proof.

### Cross-source inclusion chains

Upload-assisted and remote-file inclusion routes now emphasize that attacker control of a source, source reachability, target-side retrieval/inclusion, runtime interpretation, and command effect are separate Evidence boundaries.

### Remediation guidance

File-inclusion remediation favors fixed server-side mappings or strict allowlists, canonicalization before authorization, constrained readable paths, and least privilege rather than traversal-string filtering. XSS remediation emphasizes context-aware output encoding, safe DOM APIs, CSP as defense in depth, and hardened session cookies.

## Compatibility and proof boundary

Workspace/runtime schema remains v8.8. No v9.28 app/core/project-model/style mini-runtime is added. Obol remains browser-local, copy-only, human-run, and Evidence-gated. Note-derived guidance may influence operator choices, but it cannot execute commands, create Evidence facts, authenticate automatically, or become report-ready proof by itself.
