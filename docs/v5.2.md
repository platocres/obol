# Obol v5.2

v5.2 turns the v5.1 delivery-debt drill-down into a stronger development-quality model without changing engagement behavior or inflating canonical methodology completion.

## Release focus

- Adds **delivery-ready canonical accounting**. A canonical implemented or partial section is delivery-ready only when at least one tracked mapped workflow has all four established contracts: Run, explicit Evidence, explicit execution-side metadata, and reporting traceability.
- Adds an ordered **Build next** queue to the North Star Dashboard.
- Prioritizes implemented canonical sections with no delivery-ready mapped workflow before ordinary mapped delivery debt.
- Prioritizes remaining mapped delivery debt before new canonical gaps.
- Keeps the pinned 127-section methodology status unchanged at 52 implemented / 49 partial / 26 gaps / 0 stale.
- Keeps the delivery-readiness model diagnostic. It does not create facts, change applicability, mark success, or rewrite canonical section status.

## Information architecture

No primary navigation item is added. The five primary destinations remain Home, Targets, Evidence, Next Steps, and Report. Project-wide quality accounting remains owned by the North Star Dashboard under More.

## README structure

v5.2 implements the current README instruction that the project maintain one To-do section containing:

- North Star objectives;
- summaries of only the last three releases;
- the work that the next build should prioritize.

Verbose release history remains in `CHANGELOG.md`.

## Regression contract

The v5.2 suite checks current-version coercion, unchanged canonical coverage, delivery-readiness accounting, build-next ordering, README To-do structure, release wiring, and inherited sanitized-export redaction.
