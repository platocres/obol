# Obol v9.55

Product-hardening release for the Notes Impact and Source Re-mining package.

## What changed

v9.55 turns the next source-mining slice into actual operator-facing product behavior instead of another dashboard-only note disposition.

### AD and pivoting source re-mining

This release re-mines the AD and pivoting packet area from complete sequential private packets, not public summaries or old truncated review windows. The public output is rewritten Obol guidance only.

Added first-class Next Steps cards:

- `ad-sharphound-collection-review`
- `ad-bloodhound-edge-proof-review`
- `ad-domain-share-secret-triage`
- `ad-kerberoast-proof-boundary`
- `pivot-reachability-map-review`
- `pivot-socks-proof-chain`
- `pivot-traffic-confirmation`
- `winrm-lateral-validation`

These cards are inserted into the existing Active Directory and Lateral Movement / Pivoting path surfaces, not dumped into a generic source-notes panel. They use the same shared card UI as normal cards, so they retain queue controls, tried/succeeded controls, command explanations, evidence textarea, and card-scoped Intake flow.

### Proof boundaries added

The new cards preserve several source-mined proof boundaries:

- SharpHound collection is a scoped graph snapshot, not proof that a BloodHound path is exploitable.
- BloodHound edges become proof tasks with a required identity, right, target object, and cleanup boundary.
- Domain shares produce access, file, and candidate-secret facts separately.
- Kerberoasting separates SPN discovery, TGS capture, offline cracking, and validated service access.
- Pivoting separates route discovery, tunnel-up state, scan-through behavior, traffic confirmation, and authenticated internal service use.
- WinRM validation separates credential validity from useful lateral Windows control.

### UI and routing constraints preserved

This release carries forward the lessons from the v9.54 visual review fixes:

- No fake card fallback rendering.
- No developer-facing route explanation boxes.
- No source-mining provenance shown as operator card copy.
- Every command has a useful explanation, not a generic authorization warning.
- Card-originated evidence remains card-scoped through Intake.
- OS-scoped local privilege cards remain separated from cross-platform AD and pivot cards.

## Compatibility

Obol remains static and browser-local. No backend, telemetry, account system, install requirement, or automatic command execution is added. Operators still run commands externally in authorized environments and paste output back into Evidence/Intake.

Private source material remains private: no raw note prose, screenshots, course-specific target details, flags, credentials, or exact solution chains are published.
