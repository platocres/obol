# Obol v5.7

## Release focus

v5.7 consumes the highest-priority items from the generated v5.6 North Star Build Next queue. With implemented-quality and mapped-delivery debt already at zero, the release focuses on canonical gap reduction while preserving the pinned Orange Cyber Defense 2025.03 denominator and source commit.

The five completed gaps are:

- `acl.dns-admin`
- `authenticated.entra-connect`
- `know_vuln_auth.certifried`
- `know_vuln_auth.ms14-068`
- `know_vuln_auth.nopac`

Strict canonical completion moves from 67/127 to 72/127. Canonical gaps fall from 26 to 21. Partial coverage remains 34, stale remains zero, fully implemented coverage rises from 53% to 57%, and represented coverage rises from 80% to 83%.

## New delivery-ready owners

### DNSAdmins plugin DLL control

The DNSAdmins workflow verifies the relevant group relationship, records the prior DNS plugin setting, performs only the reviewed configuration change, makes the DNS service restart explicit, and includes cleanup guidance. Evidence stops at the configuration boundary. A successful `ServerLevelPluginDll` change does not automatically create SYSTEM or administrator-access facts.

### Entra ID / AD Connect discovery

The hybrid-identity workflow keeps the pinned MSOL-style directory discovery path and supplements it with Windows-native searches for MSOL_, AAD_, ADSync, Azure AD Connect, and Entra Connect indicators. Discovery establishes hybrid-identity context only and does not imply synchronization-secret recovery.

### Certifried

The Certifried workflow separates machine-account creation, Machine-template certificate issuance, certificate authentication, and cleanup. Saved PFX material is certificate evidence only; explicit returned ticket or hash material is recorded separately and no domain-admin claim is inferred.

### MS14-068

The legacy MS14-068 workflow keeps platform/uptime triage separate from actual ticket proof. Old operating-system context is not vulnerability proof. A saved ccache establishes Kerberos ticket material only until later service use is independently proven.

### noPac

The noPac workflow begins with the NetExec detection module and preserves positive versus negative findings. The authenticated ticket path is represented for authorized labs, but generated/imported ticket material is never promoted directly to administrator access.

The v5.5/v5.6 release-process hardening remains in force. Work is assembled on a non-release staging branch. `release/obol-v5.7` should only be moved after the coherent snapshot is ready. Release-branch pushes run `node tools/release-preflight.js`, while non-draft pull requests and `main` run the complete historical regression chain plus README synchronization.
