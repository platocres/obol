# Obol v9.1

v9.1 tightens the post-Orange product-hardening phase after v9.0 landed the initial queue and standalone dashboard.

## Summary

This release fixes three problems discovered immediately after the v9.0 merge:

- README version wording made v8.8 and v9.0 look like competing current releases.
- The live app dashboard still opened the completed Orange/North Star baseline instead of the active product-hardening Build Next queue.
- The product-hardening queue did not yet enforce item-specific test proof for future queue burn-down work.

## Product-hardening queue

The v9 queue remains the source of truth in `data/product-hardening/product-hardening-queue.js`. v9.1 adds `data/product-hardening/item-test-contracts.js`, which binds status-bearing queue items to acceptance criteria, validation commands, and proof files.

`tools/validate-product-hardening-queue.js` now fails if any queued item moves to `modeled`, `complete`, `superseded`, or `rejected` without an item-specific test contract.

## Private notes source

The private source-note boundary remains unchanged. Raw ENEX material stays in `platocres/obol-source-notes`; public Obol receives only normalized, derived guidance and implementation changes.

## Dashboard behavior

The in-app `#/dashboard` route now presents the Product Hardening Dashboard and Build Next queue as the active dashboard surface. The completed v8.8 Orange methodology/source accounting remains available as a baseline summary below the product queue, rather than occupying the primary dashboard as if it were still the current build phase.

Home also gains product-hardening status so users can see the v9 queue without hunting for the standalone `product-hardening.html` entrypoint.

## Validation added

v9.1 adds `tests/run-v9.1-tests.js` for:

- current-release README wording;
- completed Orange baseline wording;
- in-app product dashboard bridge wiring;
- product-hardening CSS embedding;
- item-specific test-contract enforcement;
- product queue validation, asset validation, README sync, and release-contract validation.

The existing v9.0 tests were also extended to prove status-bearing product-hardening items have item-specific test contracts.

## Compatibility

Obol remains static, browser-local, human-run, and no-telemetry. No backend, account system, automatic command execution, raw public note import, or fake v9 runtime overlay files are added.
