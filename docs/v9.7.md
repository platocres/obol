# Obol v9.7 - CSS Ownership Consolidation

v9.7 completes `runtime-css-consolidation` and permanently adopts the one-branch/one-normal-PR release workflow agreed after v9.6.

## Release workflow hardening

Release PRs are now opened non-draft as early as GitHub permits and remain the same PR throughout development. Required checks, not Draft status, prevent premature merge. A red check means continue building on the same PR. Agents must not close and recreate a healthy release PR merely to move between Draft and Ready states.

`[preflight]` and `[release-final]` keep their existing roles, and the exact final head must still pass smoke, preflight, the complete historical regression chain, release-contract validation, queue/current-release synchronization, and the PR required checks before the release is called merge-ready.

The release PR description carries the Product Hardening release-contract sections before exact-head validation is cut. Review-state mutation is never required to obtain or rerun those checks.

## One current stylesheet owner

Before v9.7, `data/runtime-manifest.js` directly exposed 69 historical versioned stylesheets as the executable current style list. v9.7 changes ownership without changing the preserved cascade:

- `data/runtime-manifest.js` exposes one executable stylesheet, `assets/obol-current.css`;
- the manifest retains the frozen v9.5 historical stylesheet list under `compatibility.historicalStyles`;
- `tools/sync-current-styles.js` generates `assets/obol-current.css` from that list;
- the generated stylesheet is a pure ordered `@import` projection and contains no independent style rules;
- `tools/validate-runtime-manifest.js` proves the imported fragments match the v9.5 stylesheet count and order fingerprint exactly;
- the existing script order, Node runtime subsets, v8.8 workspace schema, and historical source-observation projections remain unchanged.

This is an ownership consolidation, not a request-count claim. The historical CSS fragments still load through the stable owner so cascade behavior remains regression-compatible and easy to roll back. `perf-bundle-budget` remains queued for later physical bundling, request reduction, and parse-cost work.

## Historical regression future safety

The first non-draft full PR chain correctly exposed one v3.0 preservation test that treated `manifest.styles` as a permanent direct-owner list. That assertion was an implementation-shape lock, not a historical-behavior invariant. The v3.0 suite now checks the preserved compatibility stylesheet sequence through `compatibility.historicalStyles`, with a fallback for older manifests.

`tools/validate-historical-tests.js` now rejects this class of direct-current-owner assertion in older suites so future runtime consolidation cannot be blocked by silently reintroduced ownership-shape locks. The full non-draft PR regression chain passes after that migration.

## Permanent validation

The current stylesheet is generated and checked with:

```bash
node tools/sync-current-styles.js --check
```

Runtime equivalence remains protected by:

```bash
node tools/validate-runtime-manifest.js
```

The release regression suite is:

```bash
node tests/run-v9.7-tests.js
```

Product Hardening preflight runs the stylesheet synchronization check before runtime-manifest equivalence.

## Compatibility

Obol remains static, browser-local, and human-run. v9.7 adds no backend, telemetry, account system, install prompt, automatic command execution, public raw-note import, or workspace-schema migration. `C.VERSION` remains `8.8.0`. Historical CSS files remain in the repository and remain observable to historical regressions, while current executable ownership is stable and non-versioned.
