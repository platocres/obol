# Obol v5.5

v5.5 consumes the generated v5.4 Build Next queue rather than maintaining a separate release agenda.

## Implemented-quality cleanup

The ten implemented canonical sections at the front of the v5.4 queue are cleared by adding explicit v5.5 Evidence contracts and audited execution-side metadata to seven shared mapped owners:

- Nmap Command Builder
- Anonymous LDAP Enumeration
- User Enumeration
- AS-REP Roasting
- Kerberoasting
- Password Spraying
- BloodHound Collection & Analysis

A canonical section is considered delivery-ready only when at least one mapped owner has a runnable command, explicit Evidence profile, explicit execution-side metadata, and reporting traceability. v5.5 does not alter success state merely because these contracts exist.

## Canonical completion wave

Five previously partial sections gain dedicated end-to-end owners and move to implemented:

- Authenticated AD CS enumeration
- Kerberos delegation discovery
- Domain DPAPI backup-key collection
- LSASS credential extraction
- Token/session impersonation

The pinned denominator remains 127 sections. v5.5 raises the strict baseline from 57 implemented / 44 partial / 26 gaps to 62 implemented / 39 partial / 26 gaps, or 49% fully implemented and 80% represented.

## Proof boundaries

- AD CS enumeration does not prove certificate abuse or privilege.
- Delegation discovery does not create Kerberos tickets or access facts.
- Domain backup-key export does not imply that any user secret was decrypted.
- LSASS collection is separate from parsed credential recovery; plaintext is never inferred from a dump artifact.
- Token enumeration or elevation startup text does not imply SYSTEM. SYSTEM is recorded only from explicit post-transition identity output.

## README queue synchronization

`tools/sync-readme-build-next.js` now loads the v5.5 methodology and core layers, so the generated README agenda and the North Star Dashboard continue to share the same Build Next model. CI still rejects drift with:

```bash
node tools/sync-readme-build-next.js --check
```

## Compatibility

v5.5 remains additive, static, browser-local, and human-run only. Existing workspace state, Evidence, activity history, reporting, lineage, reachability, pivots, delivery-readiness accounting, and sanitized exports continue to forward-coerce into the current release.
