# Obol v4.4

Obol v4.4 makes the Orange Cyberdefense 2025.03 Active Directory data materially improve **Next Steps** instead of remaining only a project-coverage ledger.

The release is driven by the README North Star requirement:

> Make sure that the data being integrated from the Orange Cyber Defense mind map is improving "Next Steps" and that as users complete each step they are being properly led down the mind map's decision path.

The permanent North Star remains unchanged:

`https://orange-cyberdefense.github.io/ocd-mindmaps/img/mindmap_ad_dark_classic_2025.03.excalidraw.svg`

The pinned canonical source snapshot remains unchanged in `data/orange-ad-2025.03.js`, and the v4.3 live coverage reconciliation remains unchanged in `data/methodology-v4.3.js`.

## Purpose

v4.2 and v4.3 answered project-maintenance questions:

- what the pinned Orange methodology contains;
- what Obol already implements;
- what remains partial or missing;
- which live cards map to canonical Orange sections.

v4.4 adds the engagement-facing layer:

- where the active target/domain currently sits in a simplified Orange decision progression;
- which already-applicable Obol cards represent the current or next canonical stage;
- how successful operator-recorded activity advances that stage;
- how Orange guidance participates in ranking without becoming a new source of evidence.

## Decision stages

`data/methodology-v4.4.js` adds a deliberately small decision-stage model:

1. **Identify the environment**
2. **Obtain or validate credentials**
3. **Map authenticated AD**
4. **Test control paths**
5. **Move with proven access**
6. **Deepen host control**
7. **Assess domain-level control**
8. **Document persistence options**

The model does not attempt to flatten the Orange mindmap into one mandatory linear path. Real AD work branches. The stages provide a bounded progression signal while the existing prerequisites, facts, reachability, activity history, and operator context continue to decide what is actually applicable.

## Canonical mappings to decision stages

Existing `orange43` canonical provenance is reused rather than duplicated.

High-confidence card-level overrides keep broad cards in the stage where they are most useful. Examples include:

- `ad-dc-identify`, anonymous SMB/LDAP, Nmap, and username enumeration → identify the environment;
- password spraying, AS-REP roasting, Kerberoasting, GPP recovery, and Hashcat mode work → obtain or validate credentials;
- BloodHound, PowerView, .NET AD enumeration, SCCM reconnaissance, and trust enumeration → map authenticated AD;
- ACL, AD CS, relay, delegation, and machine-account readiness → test control paths;
- S4U payoff, lateral execution, ticket reuse, Kerberos tickets, and database movement → move with proven access;
- Windows privilege and credential-recovery workflows → deepen host control;
- DCSync/domain-replication workflows → assess domain-level control;
- Golden Ticket → document persistence options.

Un-overridden mapped cards receive a conservative stage from their canonical Orange section family.

## Context-safe progress

`C.orangeDecisionProgress44(state, lanes, ctx)` derives progress only from the active context.

A successful mapped activity can advance the decision stage. Successful activity on another host/domain does not advance the current context.

The stage also has a conservative fact floor so imported/reviewed evidence can place the operator appropriately even when the supporting activity came through a structured intake path rather than an expanded methodology card.

Examples of stage floors include:

- domain identity / scan evidence → identify;
- validated credential or ticket material → credential;
- graph/attack-path facts → authenticated mapping;
- control-path or certificate facts → control;
- foothold / lateral facts → movement;
- admin / SYSTEM facts → host control;
- NTDS / krbtgt facts → domain control.

No fact is created by this release.

## Ranking behavior

`C.orangeDecisionSignal44(state, card, ctx)` adds only a **small positive signal** to already-ranked, already-applicable cards:

- current stage: small continuation boost;
- immediately next stage: strongest Orange-path boost;
- one stage beyond that: small future-branch boost;
- earlier/later stages: no negative penalty.

Important constraints:

- Orange data does not make a card applicable;
- Orange data does not mark activity success;
- Orange data does not create facts;
- Orange data does not hide fallback cards;
- Orange data does not override reachability or evidence;
- Orange data does not replace the Kali/Windows `operatorSurface40` model;
- the existing ranking inputs remain authoritative.

This avoids turning the mindmap into a brittle forced script.

## Next Steps integration

`C.nextStepsOverview34(...)` now includes `orangeDecision44` with:

- current decision stage;
- next decision stage;
- recent mapped successful activity trail;
- completed canonical keys for the active context;
- a short queue of evidence-grounded Orange-mapped recommendations.

The queue contains only live Obol cards that the normal methodology engine already considers applicable. Canonical project gaps are not presented as engagement actions until Obol has a real mapped workflow for them.

## UI

`assets/app-v4.4.js` adds an **Orange 2025.03 decision path** panel to Next Steps.

It shows:

- the current stage;
- the next stage;
- evidence-grounded canonical directions;
- recent recorded Orange-path progress;
- a clear note that the signal is advisory only.

Recommendations that receive a positive Orange-path boost show the reason and boost magnitude.

Home also shows the active context's current Orange decision stage. Canonically mapped card pages show their decision stage beside the existing v4.3 canonical provenance.

No new primary navigation destination is added.

## Coverage accounting

v4.4 does **not** change the canonical implementation denominator simply because decision guidance improved.

The live project coverage remains the v4.3 baseline:

- **42 implemented**
- **39 partial**
- **46 gaps**
- **0 stale**
- **33% fully implemented**
- **64% represented**

This separation is intentional. User guidance and project implementation coverage are different metrics.

## Next work

With the decision-path bridge in place, future builds can work the remaining canonical gaps and immediately improve both project coverage and engagement guidance.

Priority areas remain SCCM beyond reconnaissance, persistence beyond Golden Ticket, trust abuse beyond enumeration, Windows low-access AppLocker/UAC/Kerberos-relay branches, deeper AD CS and delegation coverage, relay/coercion depth, and Evidence/full-session fixtures for the newer paths.

Future additions should attach to the existing canonical section and decision-stage model rather than introducing another independent pathway system.
