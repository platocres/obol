# Obol v4.9

Obol v4.9 implements the v4.8 README requirement that the project's Orange Cyberdefense methodology work, tool decisions, command UX, Evidence handling, Next Steps integration, execution context, and reporting readiness be visible from one website dashboard with hard numbers and percentages.

The release does not add another primary navigation destination. **Home** owns the project dashboard, while Methodology gets a compact link/summary back to the same source of truth.

## Why v4.9

By v4.8, Obol had several accurate but distributed audit models:

- canonical Orange 2025.03 completion and represented coverage;
- structured tool-choice review;
- explicit-vs-fallback execution-side metadata;
- Orange decision-stage mapping for Next Steps;
- run/Evidence operator-loop contracts;
- reporting traceability and proof readiness;
- SCCM and domain-persistence branch progress.

Those systems were useful individually, but the README now explicitly requires one dashboard with hard numbers and percentages. v4.9 composes the existing models instead of creating competing accounting systems.

## Dashboard engine

`assets/core-v4.9.js` adds `C.northStarDashboard49(state, lanes, context)` as the single project-dashboard model.

It composes existing live data rather than duplicating it:

- `C.mindmapCoverage42()` for canonical methodology completion;
- `C.orangeContractCoverage45()` for runnable cards, Evidence profiles, full operator-loop readiness, and GUI-adjustable command counts;
- a v4.9 broad execution audit across all Orange-mapped commands;
- `C.orangeReportCoverage47()` for report traceability;
- the v4.1 structured tool-choice audit for keep/supplement/replace/review accounting;
- the v4.4 decision-stage model for canonical path integration;
- v4.6 SCCM and v4.8 persistence progress for the active context;
- the current canonical file/section ledger for backlog concentration.

Additional reusable helpers are exposed for execution metadata, decision-path mapping, tool-review accounting, and canonical backlog sorting.

## Hard-number metrics

The Home dashboard shows live counts and percentages for:

- fully implemented canonical Orange sections;
- represented canonical sections;
- Orange-mapped cards with a complete Run → Evidence loop;
- mapped cards with explicit Evidence profiles;
- mapped commands with explicit execution-side metadata;
- live canonical sections connected to the Orange decision-stage model;
- mapped cards with reporting traceability contracts;
- structured tool-choice rows that are resolved versus still marked review.

It also exposes raw denominators so a percentage never appears without its count.

## Command UX accounting

The dashboard separates **GUI-adjustable commands** from **fixed commands**.

A fixed command is not automatically a defect. Some native or one-purpose commands are clearer when left fixed. The dashboard therefore reports the adjustable-command percentage as an informational UX metric while the stronger operator-loop metric is card-level: does the mapped workflow have runnable methodology and an Evidence profile?

## Active-context dashboard

The same dashboard includes a context-scoped working view:

- current Orange decision stage;
- next Orange decision stage;
- current evidence-grounded Orange queue size;
- mapped successful activity count;
- mapped report proof readiness;
- SCCM branch progress when that branch has been used;
- persistence lifecycle progress when that branch has been used.

Project coverage and active engagement progress remain separate. A user's successful activity does not change project methodology percentages.

## Backlog concentration

The dashboard ranks Orange source files by remaining gap and partial counts. Clicking a backlog row opens Methodology with that Orange source file selected.

This makes the canonical gap queue visible without requiring future agents or users to reconstruct where the remaining work is concentrated.

## Home consolidation

Older Home-only project-health cards are removed after the v4.9 dashboard renders so the user sees one consolidated source rather than several overlapping Orange/SCCM/persistence status cards.

Branch-specific detail remains available in Next Steps and the relevant methodology cards.

## Methodology integration

Methodology retains the full canonical ledger. v4.9 adds a compact dashboard summary above it with the current methodology, operator-loop, execution-metadata, and reporting percentages plus a link back to the single Home dashboard.

No new primary navigation destination is created.

## Future work

Use the dashboard as the normal starting point for project planning. Canonical technique work should reduce gap/partial debt; operator-loop work should improve Evidence/loop percentages; execution audits should reduce fallback classification; tool reviews should reduce pending-review rows; and reporting work should preserve full traceability.

Do not collapse those separate percentages into one flattering overall score. They measure different contracts and should remain independently auditable.
