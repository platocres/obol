# Obol v9.47 — Semantic application ownership

v9.47 corrects the remaining application-runtime ownership gap exposed after v9.46. Request consolidation and first-paint hiding did not make the application layer semantically current-owned: the browser still executed the surviving historical route/decorator chain behind `assets/obol-app-current.js`.

This release makes application execution ownership explicit. The target architecture is one stable current application/router owner that controls navigation and visible route commits while historical application fragments remain only as the frozen regression/equivalence ledger. Historical self-scheduling and repeated route repaint behavior must not control the visible application after current ownership is established.

The README, Product Build Next queue, Product Hardening Dashboard, runtime-compaction projection, architecture documentation, and item-specific proof are updated additively so the earlier request-flattening and v9.46 first-paint milestones remain historically true without being misrepresented as semantic application retirement.
