# Obol v9.76 - Cluster queue handoff repair

## Summary

v9.76 repairs the Product Build Next handoff after v9.75 so the generated README and dashboard queue follow the active source-note cluster ledger instead of falling back to stale blind old-rubric batch language.

## What changed

- Makes the Build Next queue hygiene owner aware of the v9.75 source-note cluster ledger.
- Promotes `source-note-cluster-web-upload-file-inclusion-001` as the concrete next notes item when the cluster ledger is complete.
- Keeps the note disposition burn-down gate active while routing the next work through whole-cluster mining.
- Updates generated Product Build Next rendering so cluster-review batches use `targetCount`, `sourceSelector`, and whole-cluster acceptance text.
- Prunes stale dynamic why-now boxes during same-page canonical card routing so demoted card aliases still expose exactly one operator-facing why-now section.
- Adds a v9.76 regression test that fails if Product Build Next regresses to blind old-rubric or pending slices after clustering.

## Why

After v9.75 merged, the current release and cluster ledger were present, but the generated Product Build Next block could still show stale old-rubric batch text because queue hygiene recomputed notes state without honoring the completed cluster ledger. That would steer future agents into the wrong next build.

The browser smoke also exposed a same-page card-routing edge case where dynamic why-now decoration could leave stale boxes behind during demoted-card canonicalization. v9.76 keeps that UI contract tight rather than weakening the Playwright check.

## Guardrails

- Do not resume blind 20-note batches once the cluster ledger is complete.
- Mine the complete private packet text for the selected cluster before terminally dispositioning its notes.
- A cluster still does not automatically become a primary card.
- New primary cards still require the v9.71 action spine and v9.72 uniqueness proof.
- Public output remains generalized and public-safe.
