# Obol v9.31

v9.31 starts the non-Dashboard runtime cleanup requested after the v9.29/v9.30 dashboard and notes work.

## What changed

- Added `assets/operator-route-current.js` as the stable current owner for operator routes that were still visibly layered.
- Added `assets/operator-route-current.css` for the current Path, Card, and Tools presentation.
- `#/path` now renders a current-owned Next Steps decision screen with best move, unlocks, queued intent, blockers, and a compact recommendation list.
- Card and Tools routes keep schema-driven current builders as the primary action surface.
- Historical raw command blocks are retained as supporting detail behind a single disclosure instead of competing with the guided builder UI.
- The v8.8 bridge lazy-loads the current operator route owner and re-applies compaction after current tool builders mount.

## What did not change

- v9.31 does not delete every historical runtime layer.
- Compatibility scripts still back behavior that has not yet received current-owner equivalence proof.
- The notes ledger remains at the v9.30 reviewed state: 76 of 556 reviewed, 32 public Field Notes, and the web upload/inclusion packet complete.
- The live Product Build Next item remains `notes-disposition-burn-down`.

## Acceptance contract

- Do not add `assets/app-v9.31.js` or another release-specific runtime layer for this work.
- Treat `assets/operator-route-current.js` as the current owner for Path/Card/Tools presentation.
- Preserve current guided builders as the primary surface.
- Preserve historical command content only as supporting detail until a later retirement build proves deeper equivalence.
- Keep README and Dashboard queue state generated from `data/product-hardening/product-hardening-queue.js`.
