# Obol v9.98

v9.98 turns the Card progressive-disclosure build into a card-owner consolidation build and makes the later deletion work explicit instead of vague.

## What changed

- The active **Post-mining Card progressive-disclosure cleanup** queue item now requires current-card-owner consolidation, not only visual collapsing.
- The Card cleanup acceptance criteria now require an integrated action-first card surface: why-now, primary action, card-scoped evidence paste-back, and outcome controls must appear before secondary detail.
- The acceptance criteria explicitly ban the known bad patterns from returning: the old v9.67 patch panel, duplicate why-now repair artifacts, source-mining/provenance copy, methodology-gap filler, UNKNOWN implementation rows, and release-bookkeeping labels.
- A concrete follow-up queue item now exists: **Post-mining Card wrapper and decorator retirement audit**.
- The retirement follow-up names the known owners that must be migrated, proven equivalent, and retired through the current-owner lifecycle: `assets/app-v2-cards.js`, `action-first-card-cleanup-stabilize-v9.67.js`, `note-card-disposition-reconciliation-v9.68.js`, `dynamic-why-now-v9.71.js`, and `dynamic-why-now-route-stabilizer-v9.77.js`.

## Intent

The point is not to delete wrappers blindly in the Card cleanup build. The point is to prevent "later" from becoming nowhere. Card cleanup should migrate useful behavior into the normal shared card structure. The follow-up retirement audit should then prove which old wrappers and decorators are redundant before removing them.

## Validation

- `node tests/run-v9.98-tests.js`

The test proves that Build Next still starts with Card progressive-disclosure cleanup, that the card cleanup item now carries current-owner consolidation acceptance, and that the card-specific wrapper/decorator retirement audit is queued immediately behind it.
