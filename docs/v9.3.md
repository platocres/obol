# Obol v9.3 - complete asset reference validation

v9.3 completes `cc-asset-validation`, the highest-priority live Product Build Next item after v9.2 completed the current-release authority. The completed Orange 2025.03 methodology/source queue remains closed and regression-protected.

## Asset graph validation

`tools/validate-asset-references.js` now treats Obol's HTML pages as entrypoints into a local asset graph instead of checking only double-quoted `src` and `href` values in two hard-coded files.

The validator now:

- discovers repository HTML entrypoints;
- parses quoted and unquoted `src`, `href`, `poster`, `data`, and `srcset` references;
- follows inline CSS and linked stylesheet `url(...)` and `@import` references;
- follows supported literal dynamic script/style loads and browser worker/service-worker registrations from reachable JavaScript;
- resolves HTML references relative to their entrypoint, CSS references relative to their stylesheet, and browser-created dynamic resources relative to the site root;
- ignores deliberate non-file references such as fragments, external URLs, and data/blob/mailto-style schemes;
- rejects references that escape the repository root;
- reports the owning file, reference kind, original reference, and resolved path when an asset is missing.

The validator remains dependency-free and exports its graph-validation helpers so the current regression suite can exercise realistic fixtures directly.

## CI and release gate

`tools/release-smoke.js` now consumes the same full asset validator, so ordinary release-branch pushes fail immediately when a reachable local asset disappears. The existing duplicate index-script/stylesheet check remains intact.

While tracing the required release flow, v9.3 also corrected a stale preflight assumption. `tools/release-preflight.js` previously required `core-vX.Y.js` and `project-model-vX.Y.js` for every current release, contradicting the v9 no-fake-runtime-layer rule. Preflight is now phase-aware: historical runtime releases retain the old wiring check, while Product Hardening releases validate the stable current-release authority, product queue contracts, full asset graph, generated Product Build Next, open-PR uniqueness, and current release suite without demanding fake v9 runtime files.

## Product-hardening disposition

`cc-asset-validation` is now `complete` with item-specific acceptance criteria, validation commands, and proof files in `data/product-hardening/item-test-contracts.js`. Critical correctness advances to 2/4 complete, and Product Build Next now begins with `cc-report-version` (`Normalize report version identity`).

The product release authority advances to v9.3 through `data/current-release.js`; the v8.8 workspace/runtime schema identity remains unchanged.

## Regression coverage

`tests/run-v9.3-tests.js` verifies the real repository asset graph and a temporary fixture that covers single-quoted and unquoted HTML attributes, `srcset`, inline and linked CSS, nested CSS assets, dynamic script/style loads, workers, and service-worker registration. The fixture then removes a nested asset and confirms validation fails, and separately proves repository-escaping references are rejected.

The release gate includes:

```bash
node tools/release-smoke.js
node tools/validate-asset-references.js
node tools/validate-current-release.js
node tools/sync-current-release.js --check
node tools/validate-product-hardening-queue.js
node tools/sync-product-build-next.js --check
node tools/validate-release-pr.js --repo-only --release-version=9.3
node tests/run-v9.3-tests.js
```

These checks supplement the historical-test future-safety validator, release-quality gate, retired Orange Build Next synchronization, preflight, and complete historical regression chain required by `BUILDING.md`.

## Compatibility

Obol remains static, browser-local, human-run, and free of backend, telemetry, account, install, or automatic-command-execution dependencies. v9.3 does not change Evidence/proof semantics, does not change the v8.8 workspace/runtime schema identity, does not reopen Orange source work, and does not add a versioned runtime overlay.
