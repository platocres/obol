# Obol v9.3 - complete asset reference validation

v9.3 continues the post-Orange Product Hardening queue with `cc-asset-validation`, the highest-priority live Product Build Next item after v9.2 completed the current-release authority.

## Release intent

- make local asset-reference validation comprehensive for Obol HTML entrypoints;
- fail CI when a referenced local script, stylesheet, image, icon, manifest, preload/module-preload target, media source, or other static asset is missing;
- resolve local references relative to the entrypoint that owns them and ignore only deliberate non-file references such as fragments, data/blob URLs, and external URLs;
- add item-specific tests proving missing references are rejected and supported reference forms are discovered;
- advance `cc-asset-validation` only after the item-specific contract and exact-head release gate pass;
- leave the completed Orange methodology/source queue closed and regression-protected.

## Compatibility

Obol remains static, browser-local, human-run, and free of backend, telemetry, account, install, or automatic-command-execution dependencies. v9.3 does not change the v8.8 workspace/runtime schema identity and does not add a versioned runtime overlay.
