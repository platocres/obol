# v9.54 card parity hotfix

This hotfix exists because source-mined/current-owner cards were visible as route data but still behaved like second-class cards in direct inspection.

The required behavior is simple: a source-mined card must render through the same Obol card UI as any other card. Direct card routes must preserve queue controls, tried/succeeded controls, intake evidence, evidence textarea, execution context, implementation selection, copy buttons, command options, success recording, and recent activity history.

A fake fallback inspector that only imitates the card body is not enough. If a card can appear in Next Steps, the normal `#/card/<card-id>` route must resolve it from the shared card index or live lane model and pass it through the shared `cardHTML()` renderer.

This pass also keeps the operator-route tool compactor off individual card pages. Card pages should show command blocks in the shared card layout with the evidence textarea and the `Analyze pasted evidence` action, not a `Tool action stack` or collapsed `Raw legacy commands` section.
