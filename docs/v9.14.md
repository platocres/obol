# Obol v9.14

v9.14 completes the original **Representative Tool Builder Set** on top of the stable schema-driven Tool Builder Platform. Nmap remains the v9.13 migration baseline; this release adds canonical NetExec / nxc, Hashcat, ffuf, and impacket-secretsdump builders without creating release-specific runtime layers.

Obol remains browser-local and human-run. Builders generate, explain, preview, and copy commands. They do not execute commands. Generated commands and manual outcomes remain workflow activity until reviewed Evidence supports report-ready facts.

## What shipped

### NetExec / nxc

The canonical `tb-nxc` builder covers:

- SMB, LDAP, WinRM, FTP, and MSSQL protocol selection;
- anonymous/null-session, username/password, username/NT-hash, and Kerberos-cache authentication shapes;
- target, domain, username, DNS-server, local-auth, and continue-on-success controls;
- common validation, share/user/group/password-policy/RID enumeration, share spidering, AS-REP roasting, Kerberoasting, BloodHound collection, LAPS, SAM/LSA/NTDS dumping, and command/PowerShell execution checks;
- conditional fields that only appear and become required for the selected authentication/action mode;
- secret-aware password/hash inputs and Evidence-first proof boundaries.

The builder is mounted in the existing Tools view and on relevant Card routes. Existing card text remains readable guidance and is not replaced as a second proof owner.

### Hashcat

The canonical `tb-hashcat` builder supports:

- pasted hashes or hash-file paths;
- confident detection of common structured lab formats including AS-REP, Kerberos TGS etype 23, MSCache2, bcrypt, sha512crypt, md5crypt, and NetNTLMv2;
- explicit operator confirmation/override of the selected Hashcat mode;
- straight and mask attacks;
- wordlist, rule, workload, optimized-kernel, output, and `--show` controls.

Hash detection is routing assistance only. It is not a claim that a password was recovered, and recovered material remains candidate material until independently validated where access is claimed.

### ffuf

The canonical `tb-ffuf` builder supports:

- URL/FUZZ placement and target-derived default URLs;
- wordlists and extensions;
- recursion and recursion depth;
- match codes and status/size/word filters;
- repeated headers, one `-H` argument per non-empty line;
- thread count, rate limit, and output file controls.

Reviewed response results, not the generated command or request count, remain the Evidence boundary for discovered content or virtual hosts.

### impacket-secretsdump

The canonical `tb-secretsdump` builder supports:

- remote username/password authentication;
- pass-the-hash with NT or LM:NT material;
- Kerberos-cache authentication;
- local SAM/SYSTEM/optional SECURITY hive parsing;
- domain, username, target/DC, DC-only, single-DC-user, and output controls.

The builder does not infer administrative or replication rights from command generation. Reviewed dump output is required before recovered credential or privilege facts become report-ready.

## Stable Tool Builder platform extensions

The existing stable owners remain in place:

- `data/tool-builder-schema.js`
- `assets/tool-builder-current.js`
- `data/tool-builder-inventory.js`
- `data/tool-builders.js`
- `tools/validate-tool-builder-platform.js`

v9.14 extends the stable schema/renderer behavior needed by the representative tools while retaining schema/renderer version `1.0.0`:

- conditional field visibility;
- conditional requiredness;
- conditional command tokens;
- repeated field expansion for values such as multiple ffuf headers;
- concatenated shell-safe command values for credential principals;
- field prefixes/suffixes where a CLI shape requires them;
- builder-scoped DOM field IDs so multiple builders can coexist on one card.

These are generic platform capabilities. They are not NetExec-, Hashcat-, ffuf-, or secretsdump-specific compiler branches.

## Browser integration

`assets/app-v8.8.js` remains the stable current bridge. It now resolves implemented tools through the inventory and schema registry, derives target/domain/user/wordlist/output/hashfile context from the active workspace, and mounts the canonical builder in Tool and relevant Card routes.

Targets keeps its dedicated Nmap launchpad and v3.1 Nmap Evidence ingestion compatibility. v9.14 does not introduce `app-v9.14.js`, `core-v9.14.js`, a v9.14 project model, or a release-specific stylesheet.
