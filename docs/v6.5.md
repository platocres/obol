# Obol v6.5 — AD CS source-fidelity delivery wave

v6.5 begins converting the atomized AD CS ledger introduced in v6.4 from broad-owner representation into verified end-to-end Obol workflows.

The first delivery wave targets the five highest-priority atomic source-fidelity items from the synchronized Build Next queue:

- AD CS enumeration and routing
- ESC8 web-enrollment relay
- ESC1 enrollee-supplied identity template
- ESC2 any-purpose template routing into ESC3
- ESC3 enrollment-agent / on-behalf-of request

The release keeps canonical breadth and source fidelity separate. It only credits an atomic unit as complete after tool suitability, command/GUI surface, execution side, conservative Evidence, Next Steps, reporting/lineage, cleanup, and terminal disposition are all explicitly accounted for.

Obol remains static, browser-local, and human-run. Certificate discovery, issuance, saved certificate material, relay setup, and authentication artifacts never silently become administrator, SYSTEM, or compromise facts.
