# Obol v9.23 — Credential Mode Coverage

v9.23 completes the nine-item Credential Mode Coverage work package on top of the stable Credential Material Platform introduced in v9.22.

## Scope

This release standardizes how saved credential material is handed into existing schema-driven Tool Builders without introducing another builder runtime or automatic execution path.

The completed queue items are:

- `cred-password`
- `cred-ntlm`
- `cred-netntlm`
- `cred-kerberos-hashes`
- `cred-mscache2`
- `cred-ccache-kirbi`
- `cred-pfx-cert`
- `cred-ssh-key`
- `cred-cookie-token`

The stable owner is `data/credential-modes.js`. It layers mode-specific normalization and guidance over `data/credential-material.js` and the existing Tool Builder schema/renderer.

## Credential-mode behavior

Password material prefills declared password authentication fields and preserves renderer-owned shell-safe quoting. NT and LM:NT material is normalized according to the target builder: NetExec can receive the full pair, while builders whose existing syntax expects the NT half receive only that half.

NetNTLMv1/v2, Kerberos AS-REP/TGS, and MSCache2 remain cracking inputs rather than direct authentication material. They route to the existing Hashcat and John modes already represented by the Tool Builder platform.

ccache and kirbi material receives explicit ticket handoff guidance. Obol may select compatible Kerberos modes and ticket fields, but it does not set `KRB5CCNAME`, convert tickets, launch a tool, or infer successful authentication.

PFX/certificate material can populate Certipy authentication inputs while keeping required passwords/private keys explicit. SSH-key material populates identity-file controls while leaving passphrase handling external. Cookie, bearer-token, and API-key material uses dedicated fields when available and otherwise falls back to explicit reviewable request headers.

## UI integration

`assets/credential-material-current.js` now delegates builder prefilling and mode-specific guidance to `OBOL_CREDENTIAL_MODES`. The Credential Material panel therefore shows the operator how the selected material will be used by the current builder before the generated command is copied.

The command remains human-run. Generated commands, selected material, cracking results, and manual outcomes remain workflow activity until independent reviewed Evidence supports an explicit access fact.

- Tool Builder schema/renderer identity: unchanged
- Credential Material schema identity: unchanged
- Credential Mode Coverage owner: stable non-versioned `data/credential-modes.js`
- No `app-v9.23.js`, `core-v9.23.js`, `project-model-v9.23.js`, or release-specific stylesheet is added.
