# Obol v9.1.1

v9.1.1 is a documentation and release-contract cleanup for the post-Orange product-hardening phase.

## Summary

This release streamlines `README.md` so it works as a future-agent handoff instead of carrying old Orange data-build clutter, historical build statistics, compatibility phrases, and release-history material that belongs in durable docs or the changelog.

It also makes the historical regression strategy phase-aware. Historical suites continue to protect the behavior and accounting they actually own, but they no longer get to freeze obsolete README wording or current-release state forever.

## README handoff

The README now focuses on:

- what Obol is;
- the current release and live site;
- the human-run/no-backend/no-telemetry product contract;
- the required future-agent quickstart;
- the required context map for build work;
- the active Product Build Next queue;
- core validation commands.

Completed Orange methodology/source accounting is referenced through `docs/NORTH-STAR.md` and `docs/ORANGE-SOURCE-DEPTH.md` instead of being duplicated in the README. The old methodology/source Build Next block and hidden compatibility stubs are absent while the Orange queue is complete.

`README.md` explicitly sends future agents to `BUILDING.md` and `docs/PRODUCT-HARDENING.md` before they build.

## Product-hardening queue

The active Product Build Next block remains generated from `data/product-hardening/product-hardening-queue.js`. The Product Hardening Dashboard remains available at `#/dashboard` and `product-hardening.html`.

No product queue item is burned down by this release. It improves the handoff, test, and governance surfaces so future agents can burn the queue down without reviving Orange-era release assumptions or creating new compatibility sediment.

`docs/PRODUCT-HARDENING.md` now records the broader v9 vision: runtime consolidation, one version authority, one quantified dashboard, schema-driven GUI tool builders, credential modes, manual outcomes, private-notes integration, quiet browser-side performance improvements, and browser/visual QA.

## Historical regression cleanup

The complete historical chain remains required. The change is what historical tests are allowed to demand from the current product surface.

- v8.8 continues to prove its 127/127 canonical, 17/17 source-file, 34/34 frozen-baseline, and 334/334 atomic-fidelity completion through its historical model and durable docs.
- v8.8 no longer requires the current README or current runtime version pointer to pretend v8.8 is still the active release.
- older README tests now assert the durable future-agent handoff and owned documentation instead of requiring retired Orange sections.
- `tools/validate-historical-tests.js` rejects stale README contracts and mutable current-release literals in historical suites.
- `tools/sync-readme-build-next.js` keeps the historical Orange projection reproducible for validation while allowing it to stay out of the README when that queue is empty.

This preserves real regression protection while letting the product architecture and documentation move forward.

## Validation added

v9.1.1 adds or strengthens validation for README handoff structure, removal of Orange-era README clutter, durable-doc ownership of Orange accounting, patch-version release validation, historical Build Next omission behavior, and historical-test future safety.

Relevant checks include:


## Compatibility

Obol remains static, browser-local, human-run, and no-telemetry. No backend, account system, install requirement, automatic command execution, raw public note import, fake runtime overlay, or product queue disposition change is added.
