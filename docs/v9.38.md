# Obol v9.38 — Reviewed-note mechanic backfill

v9.38 starts the corrective re-audit of the 127 note dispositions that predate the v9.36 mechanics-over-notebook rubric. The release intentionally does not close `notes-mechanic-backfill`; it establishes a durable audit artifact and completes the first coherent review wave so later builds can continue the same standard without pretending partial coverage is complete.

## Scope

The complete v9.28 wave is re-judged: 14 previously reviewed source rows now have explicit v9.38 backfill decisions. One source exposes a missed deterministic product mechanic, ten modeled sources are retained as contextual guidance with explicit reasons, and three private-reference-only sources are explicitly re-affirmed as private. That leaves 113 of the original 127 reviewed rows for subsequent backfill passes.

No private note body or copied walkthrough content is published. The public backfill ledger contains stable source IDs, review-wave identity, normalized disposition reasoning, and product proof references only.

## Product mechanic

The file-inclusion scanning lesson represented by `htb-penetration-tester-c234c00d18a235f3` is no longer treated as passive tool guidance only. The stable current Tool Builder owner now decorates the canonical ffuf builder with an **Auto-calibrate baseline noise (-ac)** checkbox.

When enabled, the generated ffuf command includes `-ac`, giving operators a reviewable signal-first control for recurring wildcard or noise responses before widening filters. When disabled, existing ffuf command generation is unchanged. Request volume or calibration itself remains workflow activity rather than proof; reviewed distinct result rows remain the Evidence boundary.

The earlier curl `--path-as-is` note-derived mechanic remains intact.

## Backfill contract

`data/product-hardening/note-mechanic-backfill-v9.38.js` records the first-pass audit independently from raw private notes. Its validator checks that every audited ID is already present in Obol's reviewed-disposition ledger, the original review wave has not drifted, decisions are unique and explicit, and every mechanic has concrete proof references.

The first-pass accounting is fixed at:

- 127 previously reviewed notes targeted by the corrective backfill
- 14 rows audited in v9.38
- 1 mechanic-backed conversion
- 10 explicitly justified guidance-only decisions
- 3 private-only dispositions re-affirmed
- 113 rows remaining

The stable `assets/tool-builder-current.js` owner applies the note-derived enhancement, matching the existing current-owner pattern.
