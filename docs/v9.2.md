# Obol v9.2

v9.2 completes the highest-priority Product Build Next item, `cc-version-authority`, without reopening the completed Orange methodology/source baseline or adding a fake v9 runtime overlay.

## Current release authority

`data/current-release.js` is the stable product-release identity owner. It exposes the current semantic version, visible release label, product-hardening phase label, and completed Orange baseline label. The v8.8 runtime/workspace schema remains a separate compatibility boundary.

The live product bridge consumes that authority for the header, browser title, settings identity, in-app Product Hardening Dashboard, report release metadata and footer, and workspace/export release metadata. The standalone Product Hardening Dashboard loads the same authority directly.

README release identity is synchronized from the same source with `tools/sync-current-release.js`; it is no longer intended to be manually maintained as a competing current-version literal.

## Queue disposition

`cc-version-authority` is complete. The critical-correctness track advances to 1/4 and Product Build Next now begins with `cc-asset-validation`.

The item-specific test contract records explicit acceptance criteria, validation commands, and proof files. Queue accounting remains owned by `data/product-hardening/product-hardening-queue.js`.

## Compatibility

The existing `C.VERSION === '8.8.0'` workspace/runtime schema contract remains intact so historical workspace migration, sanitized-export compatibility, current project modeling, and Orange regression behavior are not conflated with the product release label.

No backend, telemetry, account system, automatic command execution, raw note import, or v9 runtime overlay is introduced.
