## Proof boundaries added

- Reflected or unsafely encoded input is a candidate signal, not proof that JavaScript executed.
- DOM-based XSS may be driven entirely by client-side state, so server requests alone can miss the decisive source/sink behavior.
- Browser JavaScript execution does not prove server-side code execution, account access, session theft, authenticated reuse, privileged action, or compromise.
- Stored, reflected, and DOM describe different persistence, delivery, and trigger dimensions; actual victim trigger and observed execution remain separate Evidence.
- Script-readable cookie material, successful session reuse, and privileged application effects are separate proof states.
- `HttpOnly` can block JavaScript cookie reads without preventing the browser from sending that authenticated cookie on same-origin requests. `Secure` protects cookie transport over HTTPS; neither flag turns browser execution into proof of session compromise.
