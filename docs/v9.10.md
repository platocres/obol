# Obol v9.10 - Contextual Field Notes Disclosure

v9.10 completes the highest-priority Product Build Next item, `ux-progressive-notes`, by establishing a stable progressive-disclosure boundary for future normalized field-note guidance.

The release deliberately separates **presentation readiness** from **private-note ingestion**. Obol can now display reviewed note-derived guidance at the relevant card, tool, or Path context without copying raw course material into the public repository or pretending the 556-note integration ledger is complete.

## Stable normalized owner

`data/field-notes.js` is the stable public data owner for contextual field notes. It defines:

- normalized kinds for lesson, tool guidance, path guidance, troubleshooting, Evidence, report, and cleanup material;
- explicit `cardIds`, `toolIds`, `pathIds`, and normalized `tags` for contextual binding;
- optional opaque `sourceRefs` for private-ledger traceability;
- validation that drops malformed public records rather than presenting incomplete guidance;
- relevance matching that returns only records applicable to the current context.

The shipped `entries` array is intentionally empty. v9.10 does not invent public guidance and does not copy raw private content merely to demonstrate the UI. Later Notes Integration work must populate this owner with reviewed, rewritten Obol-owned records.

## Progressive disclosure

`assets/field-notes.js` and `assets/field-notes.css` provide the stable current UI owner.

When relevant normalized records exist, Obol renders a collapsed native `details` disclosure labeled **Field notes**. Card-bound notes appear immediately before the card action controls, while Path-bound notes can appear in the active Next Steps context. An empty relevant set renders nothing.

The design preserves the operator-first workflow:

- notes are contextual rather than globally dumped;
- disclosure is collapsed by default;
- card actions and primary recommendations remain visually dominant;
- the summary has explicit keyboard focus treatment;
- narrow-screen rules preserve readable density;
- note text is escaped before rendering.

## Route-gated loading

The stable v8.8 compatibility bridge now loads the field-note owners only for `card`, `path`, and `tools` routes. Home does not eagerly load the field-note data, renderer, or stylesheet.

This keeps the v9.9 startup-performance boundary intact while allowing future Tool Builder and Notes Integration work to reuse the same current field-note owner.

## Private source boundary

The private source repository remains:

```text
platocres/obol-source-notes
```

Raw ENEX files, walkthrough text, screenshots, flags, and proprietary notebook content remain private. Public field-note records must be normalized and rewritten as Obol-owned guidance. `tools/validate-field-notes-ui.js` rejects raw ENEX/path leakage in the public field-note owner and verifies the documented private-source boundary.

## Queue disposition

Completed in v9.10:

- `ux-progressive-notes`

UI / UX repair advances from **5/8** to **6/8 complete**. Overall Product Hardening advances from **18/632** to **19/632 complete**. The queue now has **55 queued** items and **9 modeled** foundation items.

The next highest-priority queued item is `ux-mobile-density` - **Review responsive density**. v9.10 includes narrow-screen behavior for the field-note component itself, but it does not claim the broader responsive-density audit complete because that item covers dashboard and builder surfaces beyond this release's field-note ownership boundary.

The Notes Integration items `notes-enex-extraction`, `notes-atomization-schema`, `notes-field-panel`, note influence, and the 556-note disposition burn-down also remain queued. Completing the presentation boundary is not equivalent to completing source ingestion.

## Permanent validation

The new deterministic validator is:

```bash
node tools/validate-field-notes-ui.js
```

It proves normalized context matching, malformed-record rejection, collapsed progressive disclosure, card-action placement, keyboard/narrow-screen styling, route-gated loading, no eager Home load, and the private raw-source boundary.

The release regression suite is:

```bash
node tests/run-v9.10-tests.js
```

The suite also verifies the v9.10 release authority, queue disposition, item-specific Definition of Done, empty-by-design shipped field-note ledger, README/product queue synchronization, asset integrity, and release contract.

## Compatibility

Obol remains static, browser-local, and human-run. v9.10 adds no backend, telemetry, account system, install prompt, automatic command execution, public raw-note import, or workspace-schema migration. `C.VERSION` remains `8.8.0`.

The release does not change Evidence proof semantics, recommendation ranking, report lineage, browser-local workspace storage, the v9.9 loading budget, or the frozen Orange baseline.
