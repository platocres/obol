# Obol v9.15

v9.15 continues Product Hardening through the next Tool Builder queue entry: John the Ripper.

## Shipped

- Added canonical schema-driven **John the Ripper** builder as `tb-john`.
- Added explicit common lab format selection for NT/NTLM, raw MD5, raw SHA1, md5crypt, sha512crypt, bcrypt, MSCache2, NetNTLMv1, NetNTLMv2, Kerberos AS-REP, and Kerberos TGS.
- Added wordlist, incremental, and `--show` actions.
- Added optional John rules, named rule sets, fork workers, session names, and pot-file controls.
- Reused the stable `workspace.hashfile` and `workspace.wordlist` context boundary.
- Marked the John inventory record implemented and advanced the Tool Builder track to 9/18.
- Advanced Product Hardening to 30/632 complete with gobuster / feroxbuster now at the top of Product Build Next.

## Architecture

v9.15 does not add a release-specific application runtime, renderer, schema, project model, or stylesheet. John is registered in the existing stable `data/tool-builders.js` owner and is mounted through the existing inventory-driven Tools/Card bridge.

The workspace schema remains v8.8. The Tool Builder schema and renderer remain version `1.0.0` because v9.15 requires no new generic token or field semantics.

## Human-run boundary

Obol generates and explains John commands only. It does not execute cracking commands. A selected format, generated command, or manual cracked outcome is workflow activity rather than proof. Reviewed John output is required before a recovered value becomes Evidence, and independent validation is required before claiming that recovered material grants access.

## Validation

v9.15 adds `tests/run-v9.15-tests.js`, which verifies:

- Product Hardening queue and Tool Builder accounting;
- John inventory and schema registration;
- required fields and common format coverage;
- deterministic wordlist, show, rule-set, and incremental command generation;
- conditional wordlist requirements;
- shell-safe option rendering;
- Evidence, manual-outcome, and report-lineage boundaries;
- inventory-driven browser mounting compatibility;
- current release identity and absence of fake v9.15 runtime overlays;
- permanent Tool Builder, queue, release, asset, and synchronization validators.

The final release head must pass smoke, Product Hardening preflight, and the complete historical regression chain under the existing `[release-final]` contract.
