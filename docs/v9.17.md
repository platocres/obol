# Obol v9.17

v9.17 continues the post-Orange Product Hardening phase with three completed Tool Builders, while keeping their conceptual boundaries explicit: `tb-getnpusers` and `tb-getuserspns` form the coherent Kerberos-roasting pair, and `tb-evilwinrm` is a separate Windows remote-access builder completed in the same stable Tool Builder pass.

## Scope

This release stays inside the stable non-versioned Tool Builder architecture. It does not add a release-specific runtime, renderer, project model, or stylesheet. Workspace schema compatibility remains v8.8.

Obol still generates, previews, and copies commands only. The operator runs them externally in an authorized environment and returns output to Evidence.

`GetNPUsers` and `GetUserSPNs` share a work package because both are Impacket Kerberos-roasting workflows with closely related domain/DC targeting, request/output handling, cracking handoff, and proof boundaries. Evil-WinRM is not treated as a Kerberos-only tool. It supports password, NT-hash, and Kerberos-ticket authentication and is modeled as its own remote-access surface.

## GetNPUsers

The canonical `impacket-GetNPUsers` builder supports:

- users-file and single-user sources;
- direct no-password AS-REP testing;
- password, NT-hash, and Kerberos-cache authentication when an authenticated flow is appropriate;
- domain, DC IP, and DC hostname context;
- `-request`, Hashcat/John output format selection, and output-file handling;
- deterministic shell-safe command generation;
- an explicit handoff from reviewed `$krb5asrep$` material to cracking tools without treating a generated request or recovered secret as proof of access.

The command surface was checked against the current upstream Fortra Impacket `GetNPUsers.py` parser, including `-request`, `-outputfile`, `-format`, `-usersfile`, `-hashes`, `-no-pass`, `-k`, `-dc-ip`, and `-dc-host`.

## GetUserSPNs

The canonical `impacket-GetUserSPNs` builder supports:

- password, NT-hash, and Kerberos-cache authentication;
- authentication domain and optional cross-trust target domain;
- list-only, request-all, request-user, and request-machine modes;
- optional users file, output file, and saved TGS tickets;
- `-no-rc4`, stealth, and machine-only controls;
- DC IP and hostname targeting;
- reviewed `$krb5tgs$` / ticket handoff to cracking without claiming a password or service login was proven.

The command surface was checked against the current upstream Fortra Impacket `GetUserSPNs.py` parser, including `-target-domain`, `-usersfile`, `-request`, `-request-user`, `-request-machine`, `-save`, `-outputfile`, `-no-rc4`, `-stealth`, `-machine-only`, `-hashes`, `-no-pass`, `-k`, `-dc-ip`, and `-dc-host`.

## Evil-WinRM

The canonical Evil-WinRM builder is an independent remote-access launcher. It supports:

- password and NT-hash authentication;
- Kerberos ticket/ccache authentication with realm and SPN controls;
- target, username, SSL, port, WinRM URL, PowerShell-script directory, C# executable directory, and session logging controls;
- explicit upload/download planning fields for the interactive shell boundary.

Upload and download fields are intentionally planning-only. Obol does not append interactive shell commands to the launcher and does not execute a transfer. A connection prompt, planned transfer, or generated launcher is not report-ready proof without reviewed output.

The launcher flags were checked against the current upstream Hackplayers Evil-WinRM CLI, including `-i`, `-u`, `-p`, `-H`, `-S`, `-P`, `-s`, `-e`, `-U`, `-r`, `-K`, `--spn`, and `-l`.
