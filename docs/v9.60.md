# Obol v9.60

## What changed

- Completed the next Product Build Next item after v9.59: `notes-remine-private-superseded`.
- Re-mined old `private-reference-only` and `superseded` note dispositions as a source-boundary class instead of leaving them as discarded private references.
- Added `data/product-hardening/private-only-superseded-remining-v9.60.js` to publish public-safe extraction mechanics without copying raw private note bodies, flags, exact targets, payload catalogs, screenshots, or walkthrough chains.
- Added four public-safe field-note mechanics for private-source redaction, recipe-catalog conversion, lab-outcome proof templates, and volatile tool-reference criteria.
- Marked `notes-remine-private-superseded` complete only through live queue/progress integration with a `private-only-superseded-remine` packet review marker.

## Product output

The new Product Hardening extension is `data/product-hardening/private-only-superseded-remining-v9.60.js`.

It publishes four public-safe field-note mechanics:

- `note-private-source-redaction-boundary` — private material can still produce public-safe mechanics.
- `note-recipe-catalog-to-control-axes` — recipe catalogs become builder/control axes, not copied commands.
- `note-lab-outcome-to-proof-template` — lab-specific outcomes become generic proof templates.
- `note-volatile-tool-reference-boundary` — volatile tool lists become selection criteria and fallback logic.

## Evidence and Next Steps boundary

This release does not add a new operator command, exploit path, proof-control UI, terminal-output analyzer, or path item that expects pasted lab output.

Because it does not introduce a new pasted-output shape, no new Evidence ingestion parser is required for v9.60 itself. The output is source-mining governance and field-note guidance: it tells future builds how to convert private recipes, lab answers, volatile catalogs, and superseded material into safe product mechanics.

The v9.58 Evidence rule still applies. If a future build uses this v9.60 guidance to add a command, builder toggle, proof control, analyzer, or Next Steps branch, that build is incomplete until pasted Evidence creates the expected activity and outcome facts.
