# Dashboard freshness gate and sidebar fix

This follow-up closes the post-v9.61 dashboard regression path without changing Product Build Next data, generated README output, note-progress data, Evidence parsing, or runtime queue data.

## What changed

- `data/current-release.js` can defer Product Hardening extension auto-loading when the dashboard owner needs to load base note-progress data first.
- `assets/dashboard-route-current.js` loads base data, dynamic current-release Product Hardening extensions, queue hygiene/projections, and the dashboard renderer in one ordered chain.
- The dashboard route no longer creates a route-owned `#side-details` wrapper around the entire Parameters/Facts rail. That wrapper made `Context Details` behave like a second rail-collapse control.
- The dashboard now leaves the app-level rail collapse behavior as the only whole-panel collapse path, while tagging the rail as `data-obol-dashboard-sidebar="panel-only"` for dashboard-specific styling.
- `assets/product-hardening-dashboard.css` no longer contains `#side-details` collapse styling.
- The v9.61 dashboard regression test and full browser smoke now forbid the duplicate route-owned sidebar collapse wrapper.

## Validation contract

PRs run the full browser dashboard freshness proof so dashboard update breakage is caught before merge. Older historical browser-equivalence proofs stay on `main`, scheduled/manual runs, and explicit full-regression release pushes.

Expected checks:

```bash
node tests/run-v9.61-dashboard-tests.js
node tools/release-smoke.js
node tests/playwright-smoke.js
```
