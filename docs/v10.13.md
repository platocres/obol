# Obol v10.13

## What changed

v10.13 is a product-hardening release that closes the operator scripts / LOTL track by making
**script output advance the Next Steps path**. v10.06 restored script rendering, v10.11 added the
exam-safe / LOTL metadata, and v10.12 put the snippets on the path; v10.13 reads what the operator
pastes back after running a snippet and recalculates the path from the observed facts — the same
paste-back model the Tool Builders already use.

- Added a conservative script-output Evidence analyzer, `assets/script-output-evidence-current.js`
  (`window.OBOL_SCRIPT_OUTPUT_EVIDENCE_CURRENT`), that mirrors the Tool Builder Evidence analyzers.
  It wraps `OBOL_INTAKE_V21.analyzeTerminal` and appends a **card-scoped** activity so a paste
  preserves its source and the Path/Card surfaces recompute from it. It also patches
  `OBOL_TOOL_BUILDER_EVIDENCE_CURRENT` with `analyzeScript`/`detectScript` for symmetry.
- The analyzer recognizes the output of the path-proposable snippets and emits a fact **only** when
  the output carries a strong success signal, never from mere command recognition
  (`docs/PROOF-CONTRACT.md`):
  - **manual SQLi** → `web.sqli_confirmed` on a SQL error / version echo / a recorded true-vs-false
    difference; `db.creds` on extracted `user:hash` rows; `foothold.webshell` on a command result
    echoed back from the written webshell (`uid=…`, a `whoami` line) — not the `INTO OUTFILE` /
    `xp_cmdshell` request itself.
  - **bash `/dev/tcp` sweep** and **PowerShell port sweep** → `scan.internal` only from an "open"
    result line, never from a finished loop with no output.
  - **LDAPSearch** and the **LDAPSearch cookbook** → `ad.user_list` from returned directory entries
    and `ad.base_dn` from a revealed `DC=…,DC=…` distinguished name.
- Every fact a snippet can emit is a subset of that snippet's `produces`, and each emitted fact is a
  real Orange lane fact, so a confirmed paste moves the path (SQLi confirmation unlocks the manual
  UNION / schema-dump / file-ops cards; `ad.user_list` feeds the AD lane) while negative, blocked,
  partial, or command-only output records nothing and the path stays put.
- Declared each path-proposable snippet's paste-back expectations in `data/scripts.js` as an
  `evidence` descriptor (`card`, `expects`, `facts`), and surfaced those cues on the snippet in the
  Scripts library (`assets/tools-library-current.js`) with a deep link to Evidence intake, so the
  operator sees exactly what output advances the path.
- Refined the v10.12 `produces` on the proposable snippets to the concrete facts the analyzer emits
  (`manual-sqli` now also lists `web.sqli_confirmed`; the LDAPSearch snippets list
  `ad.user_list`/`ad.base_dn`), keeping the path proposal labels and the ingestion contract aligned.

## Compatibility

Obol remains static and browser-local: no backend, telemetry, account system, or automatic command
execution. The analyzer reads text the operator pastes by hand and proposes facts for review; it runs
nothing and manufactures no fact from command recognition. The workspace schema is unchanged (v8.8).
Script data and the analyzer stay route-lazy (the Evidence-parsing bundle), so ordinary startup is
unaffected. This build reads script output into Evidence; it adds no new lane cards or tools.
