## New product guidance

### Object authorization

Obol now distinguishes predictable or discoverable object identifiers from actual authorization failures. The workflow encourages proving one unauthorized differential read or action before widening enumeration and keeps guessed identifiers below the impact/proof boundary.

### Command injection

Wave 2 does not publish private obfuscation or bypass recipe sheets. It instead adds durable reasoning guidance for characterizing filters one constraint at a time and separating likely command sinks, backend request delivery, shell interpretation, and execution proof.

### File uploads

Upload handling is modeled as layered validation and proof:

- browser-side validation;
- extension and stored filename handling;
- content type and file-signature interpretation;
- server-side classification;
- storage and reachability;
- serving/handler behavior;
- downstream parsers and processors;
- executable interpretation and command effect.

Accepted storage is not code-execution proof.

### Remediation

Upload remediation guidance emphasizes positive server-side validation, controlled non-executable storage, server-owned names, authorized download mediation, isolation, least privilege, resource limits, safe errors, and malware inspection where appropriate.
