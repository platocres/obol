# Obol v3.9

v3.9 is an Evidence-normalization and full-session regression release built directly from the priorities carried forward in the v3.8 README.

The release keeps Obol human-run and review-first. It does not execute tools, run scans, exploit targets, or infer success merely because a tool name appears in pasted output. Instead, it improves the part Obol owns: understanding operator-provided transcripts, mapping commands to the right methodology activity, and attaching only the facts the evidence actually proves.

## v3.8 README priorities advanced

v3.9 materially advances these carried-forward priorities:

- expand Evidence normalization and activity-intent coverage beyond the already mature NetExec, Certipy, and Rubeus paths
- add more complete operator-session regression fixtures instead of relying only on isolated output strings
- improve Impacket Kerberos and credential-dumping coverage
- improve PEASS-ng transcript classification without turning scanner output into privilege claims
- improve database/web transcript coverage with conservative SQLmap outcome handling
- keep the v3 information architecture small
- preserve the Orange Cyberdefense 2025.03 Active Directory mindmap North Star

The North Star remains unchanged:

`https://orange-cyberdefense.github.io/ocd-mindmaps/img/mindmap_ad_dark_classic_2025.03.excalidraw.svg`

## Broader high-confidence command intent

The v3.9 Intake overlay adds explicit intent profiles for command families whose generic matcher can otherwise be ambiguous inside large terminal transcripts.

### Impacket Kerberos

Recognized command families now include:

- `impacket-GetNPUsers` / `GetNPUsers.py` → `asrep-roast`
- `impacket-GetUserSPNs` / `GetUserSPNs.py` → `kerberoast`
- `impacket-getTGT` / `getTGT.py` → `kerberos-tickets`

Outcome inference remains evidence-bound:

- `$krb5asrep$` can establish `kerberos.asrep_hash`
- `$krb5tgs$` can establish `kerberos.tgs_hash`
- explicit saved-ticket output can establish `kerberos.ticket`

A recognized command by itself remains an attempt, not a successful finding.

## secretsdump intent separation

`impacket-secretsdump` is no longer treated as one undifferentiated activity when the command itself establishes a more specific maneuver.

- normal remote/local secretsdump usage maps to `dump-secrets`
- `-just-dc`, `-just-dc-user`, and `-just-dc-ntlm` map to `dcsync`

Canonical secretsdump hash rows can establish `hash.ntlm`. A canonical `krbtgt` row on the DCSync path can establish `hash.krbtgt`.

Obol does not infer administrative access merely because secretsdump was launched.

## Impacket remote execution

The transcript matcher recognizes:

- `impacket-psexec`
- `impacket-wmiexec`
- `impacket-smbexec`
- `impacket-atexec`
- corresponding example-script names

These map to the existing `lateral-exec` methodology activity.

Weak startup text, SMB dialect banners, or an Impacket version line do not prove a foothold. Explicit `NT AUTHORITY\\SYSTEM` output is strong enough to establish the corresponding Windows foothold/SYSTEM facts.

## PEASS-ng classification without privilege inflation

v3.9 recognizes common operator command shapes for:

- `linPEAS` → `linux-enum`
- `winPEAS` → `windows-enum`

These are intentionally classification-first profiles.

PEASS-ng output is broad and heuristic. Seeing scanner sections, warnings, colored findings, or generic local-enumeration text does not automatically establish root, SYSTEM, or a working privilege-escalation path. The operator still reviews the concrete lead and records the later validating activity separately.

## SQLmap conservative evidence

The existing `sqlmap-automation` methodology card is now easier for Evidence to recover from pasted terminal sessions.

An activity is promoted to supported only when SQLmap explicitly reports evidence such as:

- a parameter that appears injectable
- an identified backend DBMS

That can establish `web.sqli_confirmed`.

It does not automatically establish database credentials, OS command execution, a shell, or a webshell. Those require their own explicit output and later activity evidence.

## Mixed-session segmentation

v3.9 adds a supplemental command segmenter for the newly covered tool families. It is designed for copied sessions where several commands and outputs appear in one terminal paste.

The segmenter finds high-confidence command starts, associates following output with that command until the next recognized command, merges those segments with the inherited terminal segmentation, and deduplicates by normalized command.

The inherited v3.5/v3.6 NetExec, Certipy, and Rubeus intent layers remain in force.

## Evidence coverage transparency

The Evidence page gains a compact **Evidence intent coverage** panel.

It explains which tool families have explicit v3.9 profiles and, importantly, what those profiles are allowed to claim automatically. The panel also summarizes covered historical tool families already recorded in the active context.

This is deliberately not another primary navigation destination. Evidence remains the single owner of transcript review.

## Full-session regression expansion

The v3.9 suite adds complete mixed-session fixtures that exercise several command families in one transcript rather than only one parser string at a time.

Coverage includes:

- Impacket AS-REP roasting
- Impacket Kerberoasting
- Impacket TGT acquisition
- secretsdump versus DCSync intent separation
- Impacket remote execution without privilege overclaiming
- linPEAS and winPEAS classification-only behavior
- SQLmap explicit SQLi confirmation
- one mixed PEAS + SQLmap + Impacket operator session with separate activities and separate outcomes
