# Obol v9.0.1 - Product-Hardening Definition of Done Contract

v9.0.1 adds the missing burn-down rule for the post-Orange product-hardening queue. It does not implement the next functional queue item. It makes future functional queue work harder to fake.

## Summary

This release strengthens the v9 foundation by requiring product-hardening queue items to carry item-specific acceptance criteria, validation commands, required tests, proof files, risk notes, and status notes before they can move beyond `queued`.

## Product-hardening queue

`data/product-hardening/product-hardening-queue.js` now exposes a `definitionOfDone` schema and applies Definition of Done metadata to the foundation items that were already modeled in v9.0. The live queue totals remain unchanged: 74 queued items, 9 modeled foundation items, and 632 total track units including the 556-note integration denominator.

## Private notes source

The private source boundary remains unchanged. Raw ENEX exports stay in `platocres/obol-source-notes`. Public Obol receives only normalized, derived guidance and implementation changes.

## Dashboard behavior

The standalone Product Hardening Dashboard remains the v9 dashboard surface. This release does not add a new dashboard layer or a new runtime overlay.

## Validation added

New and strengthened checks:

```bash
node tools/validate-product-hardening-queue.js
node tests/run-v9.0.1-tests.js
node tools/validate-release-pr.js --repo-only --release-version=9.0.1
```

The product-hardening validator now fails if a modeled, implemented, tested, complete, superseded, or rejected item lacks the required Definition of Done fields. Items marked implemented, tested, or complete must name a concrete test or validator in `required_tests`.

## Compatibility

Obol remains static, browser-local, and human-run. No backend, telemetry, install prompt, account system, command execution, raw note import, or fake v9 runtime overlay is added. The completed Orange source-fidelity denominators stay closed.
