# Obol v9.56

Product-hardening release for note re-mining dashboard schema tracking and dashboard readability.

## What changed

v9.56 works the selected Product Build Next item `notes-remine-dashboard-schema`: the dashboard now treats note re-mining as its own first-class tracking surface instead of burying it inside a long general-purpose dashboard.

### Re-mining dashboard schema tracking

The dashboard and README now surface the same re-mining concepts from the same queue/projection sources:

- old-rubric reviewed count;
- full-spectrum re-mined count;
- old-rubric-only remaining count;
- negative finding outcome counts;
- invalid or missing negative-proof red flags;
- extraction dimensions for Path bindings, tool cards, GUI controls, scripts, one-liners, command templates, terminal analyzers, Evidence expectations, path movement, lesson boxes, examples, troubleshooting, cleanup, report guidance, product mechanics, product gaps, and additive Orange-baseline preservation.

The `notes-remine-dashboard-schema` item is considered complete only when the high-level dashboard and generated README handoff can both explain the re-mining state without relying on the giant detail tables as the first thing a user has to parse.

### Dashboard readability and drill-down organization

The Product Hardening Dashboard now favors a 1920x1080 overview first:

- a wider dashboard shell that uses available desktop width instead of trapping everything in a narrow centered column;
- a compact top summary for release, product-hardening progress, source re-mining, red flags, first-pass pending notes, mechanic conversion, and queued work;
- a Build Next section that stays near the top and remains synchronized with the README;
- drill-down sections for re-mining schema details, queue/package details, source-note impact, runtime/QA appendix data, and full ledgers;
- long tables moved into contained scroll areas instead of making the whole dashboard feel endless.

This keeps the dashboard useful at a high level while preserving the detailed auditability needed for source re-mining, negative-proof review, and future-agent handoff.

### Queue and README sync preserved

The generated Product Build Next block remains the README-facing version of the same queue/projection model the dashboard renders. The sync tool now includes compact re-mining lines so agents can see the old-rubric count, re-mined count, remaining count, negative-proof outcomes, red flags, and extraction dimensions directly from the README without the dashboard becoming the only source of that state.
