# Obol v9.63 visible re-mined card routes

## Why this exists

v9.61 and v9.62 added useful source re-mining output, but the new card IDs used by those releases were not registered as normal live cards. Opening routes such as `#/card/web-proxy-transform-proof-chain` therefore produced `Unknown card`.

That was a UI wiring miss: the notes and analyzers existed, but the operator-facing card pages did not.

## What changed

v9.63 adds `data/product-hardening/visible-remine-cards-v9.63.js`.

The extension registers visible cards for the note-derived proof-chain IDs that were already being used by Evidence and field-note metadata:

- `credential-dump-proof-chain`
- `web-proxy-transform-proof-chain`
- `web-client-controls`
- `encoded-parameter-review`
- `tool-generated-http-review`

These cards use the normal Obol card route and renderer. They appear as guidance/proof-boundary cards with expected evidence signals, report metadata, relevant tools, and note lineage. They intentionally do not add copied private lab commands, targets, answer strings, flags, cookies, hashes, or exact solution chains.

## Source boundary

This is a UI repair for the already-public-safe v9.61 and v9.62 outputs. It does not mine a new private note and does not advance the old-rubric re-mining count.

The public cards are derived from the public-safe field notes already added in:

- `data/product-hardening/credential-dump-remining-v9.61.js`
- `data/product-hardening/web-proxy-transform-remining-v9.62.js`

## Validation

Added `tests/run-v9.63-tests.js` to prove that the live card IDs resolve through the same card registry behavior used by Obol routes.

Focused checks:

```bash
node tests/run-v9.63-tests.js
node tools/scope-check.js
```

The release pointer now includes the visible-card extension so these routes load on the live website after merge and GitHub Pages deployment.
