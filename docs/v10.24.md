# Obol v10.24

This product-hardening build completes the AD/SMB/remote-access Tool Builder family repair. It brings smbclient, smbmap, enum4linux-ng, ldapsearch, rpcclient, Responder, Evil-WinRM, Certipy, and the Impacket exec builders up to the same operator-surface standard as ffuf, with an extra GUI command-control gate so buttons and toggles have to produce real commands with the expected options.

## What changed

- Added `data/product-hardening/ad-smb-remote-guidance-current.js` as the current owner for the AD/SMB/remote-access repair. The owner patches the canonical schema records, not a render-time shadow surface, so direct Tools routes now carry grouped fields, outcome-labelled action cards, visible presets, Reading-the-output guidance, and honest missing-field command states.
- Repaired thirteen implemented builders as one family: `tb-smbclient`, `tb-smbmap`, `tb-enum4linux-ng`, `tb-ldapsearch`, `tb-ad-rpcclient`, `tb-responder`, `tb-evilwinrm`, `tb-certipy`, `tb-impacket-psexec`, `tb-impacket-wmiexec`, `tb-impacket-smbexec`, `tb-impacket-dcomexec`, and `tb-impacket-atexec`.
- Added a dedicated GUI command-control regression, `tests/run-tool-builder-ad-smb-command-controls-tests.js`. It proves mode-card buttons map to real select values, preset buttons render from schema-owned visible fields, checkbox toggles emit flags, and representative commands include the expected options. This covers `ldapsearch -H` and `-ZZ`, `rpcclient -U`, `--password=...`, `-W`, and `-N`, Responder `-w`/`-F`/`-v`, Evil-WinRM auth/SSL/script flags, Certipy request flags, and Impacket exec share/service/object/silent/output controls.
- Corrected command models where the GUI exposed stale behavior. `ldapsearch` now generates the documented LDAP URI option form (`-H ldap://host`) instead of placing the URI as a bare positional argument, and `rpcclient` now exposes a visible Domain / workgroup field and emits authenticated vs null-session options deliberately.
- Added AD/SMB Evidence ingestion in the same family owner. Share listings and permissions, enum4linux/RPC/LDAP directory facts, Responder NetNTLM captures, Evil-WinRM sessions and transfer output, Certipy AD CS/certificate/hash/shadow/account output, and Impacket remote-execution artifacts/output/cleanup map to conservative outcome facts and positive/negative/blocked/partial states with secrets redacted.
- Patched the Evidence route lazy list so AD/SMB output recognition loads even when the operator opens Evidence without first visiting the full Tools schema.
- Corrected the implemented-builder audit classifier so `rpcclient`, `evilwinrm`, and the Impacket exec builders audit under `ad-smb-remote-access` instead of being split across network/service or miscellaneous buckets.
- Marked `tb-surface-ad-smb` complete against the real Definition of Done and advanced the Product Build Next queue to `tb-surface-network`.

## Operator-visible surfaces

- Direct Tools routes for the repaired family now show the usable app first: action buttons, generated command preview, grouped controls, visible presets, and output-reading guidance.
- `#/tools/ldapsearch` now generates LDAP search commands with `-H` host URI handling and StartTLS toggles.
- `#/tools/rpcclient` now separates null-session and authenticated command generation, including domain/workgroup handling and password emission.
- `#/tools/impacket-psexec`, `#/tools/impacket-wmiexec`, `#/tools/impacket-smbexec`, `#/tools/impacket-dcomexec`, and `#/tools/impacket-atexec` are loaded before the AD/SMB guidance repair so their surfaces and command controls are patched in compact Tools loading too.

## Proof boundary

Command generation remains activity, not proof. A share, LDAP entry, RPC result, captured NetNTLM response, certificate finding, WinRM shell, or remote-execution result becomes a fact only from reviewed output pasted into Evidence. Cleanup and durable access are separate Evidence states.
