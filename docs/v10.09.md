# Obol v10.09

v10.09 is a product-hardening release that burns down the first concrete slice of the remaining modeled Tool Builder backlog after the v10.08 implemented-builder audit.

## What changed

- Promoted WhatWeb, Nikto, httpx, wfuzz, and OWASP ZAP handoff from modeled inventory to implemented Tool Builder coverage.
- Added schema-driven web discovery/scanning builders with minimum viable commands, supplied or Evidence-derived prefill, additive GUI controls, and fake-placeholder refusal.
- Added executable web Evidence ingestion for fingerprint observations, scan findings, live endpoint probes, fuzz results, ZAP alerts/reports, failure, blocked, and partial states.
- Wired the web builder pack into current runtime loading so Tools and Card routes load it alongside the tunnel, Ligolo, authentication/enumeration, and helper builder packs.
- Kept the remaining modeled Tool Builder implementation backlog active and descriptive instead of falsely closing the full backlog.

## Delivered

- Promotes **WhatWeb**, **Nikto**, **httpx**, **wfuzz**, and **OWASP ZAP handoff** from modeled inventory to implemented Tool Builder coverage.
- Adds `data/tool-builders-web-scan-current.js` with schema-driven builders for the five web discovery/scanning tools.
- Adds `assets/tool-builder-web-evidence-current.js` with executable Evidence ingestion for the five builders.
- Wires the web builder pack into the current runtime so Tools/Card routes load it alongside tunnel, Ligolo, authentication/enumeration, and helper builders.
- Keeps commands operator-reviewed only. Obol still does not execute tools.

## Command contract

Each new builder starts from the minimum viable command for its selected mode, populated only from supplied target/workspace state, parsed Evidence-style state, collected material, or safe tool defaults.

The new builders intentionally do not invent fake runnable values such as `10.10.10.10`, `10.10.14.9`, `domain.local`, `user`, `Password123!`, fake NT hashes, or fake `hashes.txt`.

Optional behavior is additive and explicit:

- WhatWeb adds aggression, headers, cookies, proxy, color suppression, and JSON output through controls.
- Nikto adds port, SSL, tuning, plugin/evasion selection, proxy, timeout, noninteractive mode, and output through controls.
- httpx adds list mode, ports, status/title/technology enrichment, redirects, silent/JSON output, proxy, retries, and output through controls.
- wfuzz adds custom FUZZ URL mode, filters, status/word/char controls, headers, cookies, proxy, threads, and output through controls.
- ZAP adds baseline/quick mode, spider minutes, AJAX spider, reports, config, proxy, and debug controls.

## Evidence contract

The new Evidence owner recognizes decision-relevant output without overclaiming:

- WhatWeb can support technology/header/title/fingerprint observations.
- Nikto can support scan findings, metadata, summary, and failure/block states.
- httpx can support live endpoint, status/title/technology, redirect/auth, and failure observations.
- wfuzz can support discovered content leads, baseline/filter summaries, and failure observations.
- ZAP can support PASS/WARN/FAIL alert summaries, report production, scan stage, and failure/block states.

These are conservative leads and observations. They do not prove exploitability, authentication bypass, data access, code execution, or compromise without follow-up Evidence.

## Queue handoff

The modeled Tool Builder backlog remains active. v10.09 only completes the web discovery/scanning slice for WhatWeb, Nikto, httpx, wfuzz, and ZAP.

Remaining modeled groups still include network/host discovery, DNS/SNMP/AD collectors, remote execution/lateral movement, credential relay/capture helpers, pivot transports, privilege-escalation helpers, cloud/container/database/service tooling, and controlled CVE/PoC wrappers.

## Validation

- Adds `tests/run-v10.09-tests.js` for web builder registration, inventory promotion, minimum viable command generation, placeholder refusal, Evidence ingestion, v10.08 audit compatibility, and queue handoff.
- Wires the v10.09 test into the current-product phase of `tools/run-historical-contracts.js`.
- Keeps the generated changelog and current application owner synchronized with the v10.09 release authority instead of adding fake legacy release files.

## Compatibility

Obol remains static and browser-local: no backend, telemetry, account system, install prompt, or automatic command execution. Commands remain human-reviewed guidance for authorized labs and engagements; Evidence remains the proof layer.
