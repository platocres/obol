# Obol v10.22

This product-hardening build repairs the credentials, authentication, and cracking Tool Builder surfaces as a versioned release. It corrects the earlier shadow-surface implementation by making the repaired builders schema-owned records, restores the shared guard assertions that protect the broader Tool Builder surface, and adds live browser proof for every repaired credential/auth route.

## What changed

- Repaired the credential/auth/cracking Tool Builder family for Hashcat, John, Hydra, Kerbrute, CeWL, crunch, hashid, name-that-hash, NetExec, secretsdump, GetNPUsers, and GetUserSPNs.
- Added `data/product-hardening/credential-auth-guidance-current.js` as the current owner for credential/auth operator guidance and schema-record enrichment.
- Added `OBOL_TOOL_BUILDER_SCHEMA.replace(builder)` so current repair owners can replace an existing builder record through the same schema validation path used by registration.
- Moved field groups, presets, snippets, and operator guidance onto the real builder records returned by `schema.get()`, instead of synthesizing a second surface at render time.
- Preserved tool identity while adding outcome-labelled mode cards, grouped all-visible fields, useful presets, textarea snippets where appropriate, Reading-the-output proof guidance, and honest missing-field command states.
- Restored the shared Tool Builder surface guard assertions for Tools library owner behavior, DOM marker preservation, CSS surface rules, and fabricated-value rejection, including `domain.local`.
- Settled the compact Tools route after ordered compact Tool Library extensions finish loading so direct `#/tools/<tool>` routes repaint from the repaired schema records without changing full product-hardening card-route load behavior.
- Bumped the visible release identity to v10.22 and loads the credential/auth repair through the current compact Tool Library extension plan.

## Operator-visible surfaces

- `#/tools/hashcat`, `#/tools/john`, `#/tools/hydra`, `#/tools/kerbrute`, `#/tools/cewl`, `#/tools/crunch`, `#/tools/hashid`, `#/tools/name-that-hash`, `#/tools/nxc`, `#/tools/secretsdump`, `#/tools/getnpusers`, and `#/tools/getuserspns` now render as structured operator surfaces instead of bare or under-guided builders.
- The direct Tools route remains a command-generation and decision surface. A human can select a mode and generate a command without prior Evidence; Evidence gates proof claims and Next Steps movement only after command output is pasted back.
- Credential-risk language is explicit on risky/dangerous actions such as online auth testing, spraying, dumps, NTDS extraction, and roast material handling.

## Proof boundary

This build changes presentation, operator guidance, schema ownership, and tests. It does not make Obol execute commands, authenticate anywhere, or infer credential validity by itself. Command generation remains activity. Credential validity, recovered passwords, roastable material, dumps, or account discovery become facts only from reviewed tool output pasted into Evidence.

## Historical-test compatibility

The surface contract test is strengthened, not weakened. It still protects the ffuf golden reference, the web-family repair, the universal one-heading/no-fabricated-IP/no-dead-chip baseline, renderer capability checks, schema guard checks, Tools library owner checks, and Tool Builder CSS rules. The new credential/auth block adds schema-owned guide enforcement so a future build cannot hide another shadow surface behind render-time patching.
