# Obol v9.11 - Responsive Density Pass

v9.11 completes the highest-priority Product Build Next item, `ux-mobile-density`, with a stable responsive-density contract for the current workspace and Product Hardening Dashboard.

The release targets narrow laptops, split-screen/exam-like layouts, tablet widths, and mobile-width stress cases without changing the operator workflow, Evidence semantics, report lineage, or workspace schema.

## Stable responsive owner

`assets/responsive-current.css` is the stable current workspace owner for responsive-density corrections layered after the historical stylesheet projection. The v8.8 current bridge loads it directly rather than creating a fake versioned `obol-v9.11.css` runtime layer.

The owner concentrates narrow-width behavior for:

- workspace and card minimum-width containment;
- Home metrics, quick actions, and current workflow summaries;
- Next Steps summary and recommendation layouts;
- card headers, badges, action groups, and command option controls;
- long command output and copy-button clearance;
- credential and flag rows;
- lane tabs, phase ribbons, and other intentionally wide strip controls;
- tracker tables with local horizontal overflow;
- report previews, toasts, and dynamic-viewport modals;
- short-height laptop layouts where fixed overlays need independent scrolling.

The contract deliberately does **not** use global `overflow-x:hidden` or `overflow-x:clip` on the page to hide layout defects. Inherently wide controls get local scroll boundaries instead.

## Product Dashboard density

`assets/product-hardening-dashboard.css` now uses dedicated responsive breakpoints at 1080, 820, 600, and 420 CSS pixels.

At narrower widths:

- the score/track hero stacks before the score card or progress bars become cramped;
- dashboard two-column cards collapse to one column;
- Build Next queue rows move their status pill below the copy when three columns no longer fit;
- long queue titles and details wrap instead of forcing width;
- detailed ledgers preserve readable columns inside their own horizontal scroll boundary;
- shell/card padding and heading scale reduce on mobile without removing visual hierarchy.

The same dashboard CSS serves both `#/dashboard` and `product-hardening.html`.

## Field-notes narrow-width repair

The v9.10 field-note disclosure already stacked its summary on narrow screens, but its absolute expand/collapse affordance lacked a positioned summary owner. v9.11 makes the summary `position:relative`, reserves mobile padding for the affordance, and anchors it inside the disclosure. This keeps the progressive disclosure control attached to the component at mobile widths.

## Canonical viewport contract

`tests/fixtures/responsive-v9.11-viewports.json` freezes four representative viewport classes for responsive review and future browser automation:

- 1280x800 - narrow laptop;
- 1024x768 - exam-like or split-screen laptop;
- 768x1024 - tablet portrait;
- 390x844 - mobile-width stress case.

Representative routes include Home, Targets, Evidence, Next Steps, an Nmap Tool view, Report, and Product Dashboard. `docs/visual-qa/responsive-density.md` records the composition checks for those surfaces.

The separate `qa-playwright-smoke` item remains queued. When implemented, it should consume this fixture rather than creating another viewport/route policy.

## Permanent validation

The new deterministic validator is:

```bash
node tools/validate-responsive-layout.js
```

It verifies responsive viewport metadata, stable owner wiring, workspace breakpoints, local overflow containment, dashboard reflow, field-note affordance anchoring, canonical viewport/route fixtures, and the no-fake-v9.11-runtime-layer rule.

Product Hardening preflight now runs this validator permanently. The release regression suite is:

```bash
node tests/run-v9.11-tests.js
```

The v9.11 suite is written as a future-safe historical boundary. It protects the responsive implementation and durable queue disposition without freezing a mutable future README release label or future queue totals.

The dedicated preflight snapshot passed before the final release marker. Merge readiness remains tied to smoke, Product Hardening preflight, the complete historical regression chain, and the ready-PR regression run on the exact `[release-final]` head.

## Compatibility

Obol remains static, browser-local, and human-run. v9.11 adds no backend, telemetry, account system, install prompt, automatic command execution, workspace-schema migration, or public raw-note import. `C.VERSION` remains `8.8.0`.

The release does not change Evidence proof semantics, recommendation ranking, report lineage, browser-local workspace storage, the v9.9 loading budget, the v9.10 field-note data contract, or the frozen Orange baseline.
