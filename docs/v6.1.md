# Obol v6.1

v6.1 consumes the next five items from the synchronized v6.0 Build Next queue after confirming that implemented-quality and mapped-delivery debt remain zero.

## Canonical methodology

This release completes five canonical gaps:

- PXE / NAA credential path (`no_creds.md`)
- TimeRoasting (`no_creds.md`)
- PXE / NAA credential recovery (`sccm.md`)
- Child-to-parent trust paths (`trusts.md`)
- External / forest trust paths (`trusts.md`)

The pinned 127-section denominator is unchanged. Strict methodology advances from **87 implemented / 34 partial / 6 gaps / 0 stale** to **92 implemented / 34 partial / 1 gap / 0 stale**. Fully implemented coverage rises from **69% to 72%** and represented coverage rises from **95% to 99%**.

The only remaining canonical gap after v6.1 is **Parent-to-child trust paths** (`trusts.md`).

## Delivery owners

The shared PXE owner maps both the no-credential PXE branch and the SCCM PXE/NAA recovery section so the operator gets one coherent workflow rather than duplicated command surfaces.

## Evidence boundaries

- PXE discovery establishes SCCM/PXE context only.
- Protected PXE material remains an offline hash until separately cracked.
- Network Access Account credentials require explicit username/password output.
- TimeRoast output is offline SNTP-MS material, not authenticated access.
- A cracked TimeRoast value remains credential material until separately validated.
- Trust enumeration, recovered trust or krbtgt material, forged/saved Kerberos tickets, and successful cross-domain service access remain distinct proof boundaries.
- Ticket creation never silently becomes administrator, Enterprise Admin, SYSTEM, or other privilege.

## Release workflow

v6.1 keeps the tiered release contract introduced in v6.0:

- ordinary release-branch commits run lightweight smoke validation
- `[preflight]` runs current-release preflight
- `[release-final]` runs smoke, preflight, and the complete historical regression chain on the exact release head

Historical regression suites remain protected by the future-safety validator so old tests cannot hard-code mutable current-release values.

## Compatibility

v6.1 remains additive, static, offline-capable, browser-local, review-first, and human-run only. Existing workspaces, Evidence, activity history, reports, Next Steps, canonical mappings, SCCM state, trust state, execution context, lineage, reachability, and sanitized exports remain forward-compatible.
