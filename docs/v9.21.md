# Obol v9.21

v9.21 completes the remaining representative **Tool GUI Builders** by shipping one canonical chisel builder and one shared SSH / plink forwarding builder on the existing schema-driven, copy-only Tool Builder platform.

## Tunneling work package

The release treats `tb-chisel` and `tb-ssh-plink` as one coherent tunneling engineering package because both surfaces revolve around listeners, forward/reverse direction, execution context, connectivity proof, and cleanup. The queue items remain independently testable and independently accountable.

### chisel

`tb-chisel` exposes both server and client roles. Server controls cover listen host/port, reverse and SOCKS enablement, single-user or auth-file authentication, key/backend controls, TLS certificate/key and optional client CA, keepalive, and verbose logging.

Client controls cover normal SOCKS, reverse SOCKS, TCP or UDP forward and reverse-forward remotes, explicit SOCKS/listener ports, server authentication, server fingerprint pinning, repeated transport headers, HTTP/SOCKS proxying, Host/SNI overrides, TLS CA and optional mutual-TLS certificate/key, transport verification override, keepalive, retry bounds, and verbose logging.

The generated command follows current chisel ordering rules: client options are emitted before the server address, followed by one explicit remote. Normal SOCKS requires a server started with `--socks5`; reverse remotes require a server started with `--reverse`.

### SSH / plink

`tb-ssh-plink` uses a declared executable selector for OpenSSH `ssh` and PuTTY `plink`; free-form executable text is not accepted. The shared surface covers local (`-L`), remote (`-R`), and dynamic (`-D`) forwarding with optional bind addresses, listener ports, destination host/port, SSH server port, username, agent/key/password modes where supported, forward-only mode, compression, OpenSSH forward-failure and host-key policy controls, and Plink batch/host-key pinning controls.

The Plink password field is intentionally secret-bearing activity because `-pw` places the credential in the generated command. OpenSSH password mode leaves password entry to the external client prompt rather than embedding a password in the command.

## Browser integration

The tunnel definitions live in the stable non-versioned `data/tool-builders-tunnels.js` pack and register into the same `data/tool-builder-schema.js` registry as the existing builders. `assets/runtime-current.js` hydrates that pack only on Targets/Card/Tools routes after the existing Tool Builder base has initialized. The pack extends the current inventory and concrete-builder projections without changing schema or renderer identity.

No v9.21 app/core/project-model/style overlay is introduced. Workspace schema compatibility remains v8.8.

## Human-run and Evidence boundary

Obol still does not establish a tunnel, start a listener, authenticate to SSH, or run chisel/plink/ssh. It only renders, explains, and copies commands for the operator to run externally.

A generated command or manual success does not prove that a listener bound, a remote connected, a SOCKS proxy works, a destination is reachable, a reverse listener is exposed, or a process was cleaned up. Those facts require reviewed runtime Evidence. When cleanup matters, stop the external process and verify the relevant listener/tunnel is gone.
