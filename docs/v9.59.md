# Obol v9.59

## What changed

v9.59 fixes a stale Product Build Next handoff after the v9.58 proof/auth work landed. The generated README had advanced to `notes-remine-linux-privesc`, but Linux privilege escalation had already been mined into the public-safe Linux packet and current note guidance.

This release adds a Product Hardening reconciliation extension that treats `notes-remine-linux-privesc` as complete only when the Linux privilege-escalation packet is already complete and the expected public Linux privilege-escalation guidance owners are present.

This release also builds `ux-audit-rubric` instead of doing duplicate Linux work. The new `docs/visual-qa/ui-quality-audit-rubric.md` gives future UI fixes a repeatable per-screen checklist covering hierarchy, density, consistency, affordance, state feedback, accessibility, Evidence movement, and source boundary.

The result is that Product Build Next should stop sending agents back into already-completed Linux privilege-escalation work, mark the UI quality audit rubric complete, and advance to the real next remaining source re-mining item: `notes-remine-private-only-superseded`.

## Product Build Next queue sync

Queue correction is product work because the README and dashboard are the agent handoff. A stale top queue item sends future agents into duplicate work and makes the build loop less trustworthy.

v9.59 loads both `data/product-hardening/linux-privesc-remine-reconciliation-v9.59.js` and `data/product-hardening/ui-quality-audit-rubric-v9.59.js` through `data/current-release.js` so release/runtime Product Build Next sync can evaluate both corrections before rendering the generated queue block.

## UI quality audit rubric

The UI rubric makes visual QA fileable and repeatable instead of hand-wavy. It defines the primary routes to audit, a 0-2 scoring model, severity levels, and a finding template that forces each issue to name the screen, viewport, rubric dimension, observed behavior, expected behavior, evidence, suggested owner, and queue implication.

The rubric includes an explicit Evidence movement dimension so command, proof-control, analyzer, and path-movement UI work cannot be treated as complete if pasted output has nowhere to go.

## Evidence and Next Steps boundary

The Linux reconciliation does not add a new operator command, tool card, proof control, or terminal analyzer. It also does not add a new path item that expects pasted terminal output. It is a queue/progress reconciliation over existing Linux privilege-escalation public guidance owners, so no new Linux Evidence parser is required.

The UI audit rubric is a QA/governance artifact, not an operator command surface. It does not consume pasted lab output directly, but it explicitly requires future audit findings to document Evidence ingestion behavior whenever the affected UI surface expects pasted output.

The existing v9.58 guard remains intact: when a future release adds a command, tool-card, proof-control, analyzer, or path item that expects pasted output, Evidence ingestion and outcome facts are part of the Definition of Done.

## Source boundary

No private note body, course prose, target, flag, credential, screenshot, exploit recipe, callback/listener mechanic, or exact solution chain is copied into public Obol.

The reconciliation cites only public-safe owner IDs and the complete Linux privilege-escalation packet state already represented by Obol.
