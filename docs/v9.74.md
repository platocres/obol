## Cluster-first mining pass

The batch groups the 20 selected notes into these product clusters before row disposition:

- `command-injection-filter-boundaries` - filter identification, blacklisted character/word handling, transform boundaries, and evidence deltas.
- `command-injection-execution-proof` - source/sink reasoning, operator semantics, front-end bypass evidence, command-output proof, and negative controls.
- `upload-validation-stack` - client-side validation, blacklist/whitelist checks, Content-Type, MIME or magic-byte checks, storage, and retrieval boundaries.
- `limited-upload-active-content-parser` - SVG/XML/metadata/parser behaviors, XXE/XSS/SSRF style boundaries, and report-only handling for destructive ideas.
- `upload-reporting-and-mitigation` - upload finding report language and missing-control mitigation guidance.
- `webshell-execution-boundary` - accepted upload versus retrieval, interpretation, command context, reverse-shell fallback, and cleanup/report proof.

Each cluster records:

- selected note IDs
- owner card
- public output IDs
- product shape
- product decision
- non-primary-card rationale
- future gap IDs when a bigger feature is justified later

This prevents the pending-note phase from becoming disposition-accounting theater. The batch must show what was extracted, where it landed, why no duplicate primary card was created, and what future product gap remains if the cluster is too large for the current build.
