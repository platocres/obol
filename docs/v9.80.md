# Obol v9.80

## What changed

Obol v9.80 mines the Product Build Next source-note cluster `source-note-cluster-xss-client-session-and-csp`, covering XSS context classification, client-side session behavior, CSP and browser controls, scanner triage, and browser-proof boundaries.

The build re-reads the complete private packet route for `data/review-packets/htb-penetration-tester-07.json` and `data/review-packets/htb-penetration-tester-08.json`, totaling 745,120 complete cleaned review-text characters. Public Obol receives only generalized, re-authored mechanics. Course prose, lab targets, credentials, flags, screenshots, exact answers, and solution chains remain private.

## Existing-card integration

The v9.80 cleanup folds the mined mechanics into the stable `web-authz-boundaries` card. It does not leave a separate XSS, client-session, or browser-control card layer for later consolidation.

The release explicitly removes or prevents these wrapper/demoted cards from remaining in the runtime surface:

```text
xss-browser-proof-boundary
web-client-session-proof-chain
web-client-controls
```

The stable `web-authz-boundaries` card now owns the public-safe XSS/browser/session/CSP proof mechanics:

- inert reflection-marker checks before any execution claim;
- context classification for reflected, stored, and DOM paths;
- browser DevTools proof using harmless execution markers;
- Burp/ZAP replay guidance that keeps scanner alerts as leads until manually proven;
- DOM source/sink review guidance;
- CSP/header and browser-control checks;
- cookie, storage, CSRF, and session-impact boundary wording;
- report/remediation guidance that keeps execution, exposure, and state-change proof separate.

## Cluster reconciliation

v9.80 applies the generate-clusters-as-you-go rule during the build. While mining the active browser-side cluster, the remaining proxy/fuzzing queue showed two different product spines:

1. browser cookie/session/hash-transform fuzzing and response-delta proof, which needs its own next cluster; and
2. generic Burp/ZAP proxy request mutation, payload-position, encoding, and transform workflows.

The release therefore creates the public-safe generated queue item `source-note-cluster-browser-client-cookie-transform-workflows` and leaves `source-note-cluster-web-proxy-fuzzing-and-transform-workflows` focused on proxy/request-transform mechanics. Pending-note totals remain conserved.

## Source boundary

The accepted source route is the complete sequential packet fallback:

```text
platocres/obol-source-notes@agent/review-packets:data/review-packets/manifest.json
```

The relevant packet windows are:

```text
data/review-packets/htb-penetration-tester-07.json
data/review-packets/htb-penetration-tester-08.json
```

No raw private note text, raw ENEX path, lab host, credential, flag, screenshot, copied walkthrough prose, exact payload recipe, or solution chain is published in this release.
