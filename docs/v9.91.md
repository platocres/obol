# Obol v9.91

## What changed

v9.91 mines the `source-note-cluster-pivoting-tunneling-and-route-proof` queue item from the complete private review-packet route into public-safe pivoting, tunneling, proxying, and route-proof mechanics.

The release folds the cluster into the existing `rdp-socks-tunnel-workflow` and `metasploit-resource-pivot-workflow` owner cards instead of adding duplicate SSH, chisel, proxychains, socat, netsh, or generic pivot wrapper cards. Those cards now keep route state, listener side, tunnel transport, proxied tool output, and cleanup as separate proof boundaries.

The new route-proof spine covers SSH local, remote, and dynamic forwarding; Windows `plink.exe` and OpenSSH tunnel syntax; chisel reverse SOCKS; proxychains service checks; socat single-port relays; Windows `netsh interface portproxy` plus firewall rule cleanup; sshuttle subnet pivots; DNS tunneling handoff; and the required teardown proof.

The Evidence analyzer recognizes route tables, interface output, SSH forwarding modes, chisel client/server output, Windows portproxy and firewall rules, proxychains-driven tooling, service connectivity states, and cleanup signals. It redacts hosts, secrets, flags, and lab-specific names, and it does not treat command recognition as success.

Four public Field Notes explain the durable operator lessons from the cluster: route state comes first, SSH forwarding mode is chosen by listener side, Windows and HTTP pivots need listener/reachability/cleanup proof, and proxied scans need scoped service output plus teardown.

The Product Build Next queue advances to `source-note-cluster-metasploit-resource-post-exploitation-and-cleanup`, leaving 57 pending notes in four public-safe cluster review items.

## Compatibility

Obol remains static and browser-local. This release does not add a backend, account system, telemetry, install prompt, or automatic command execution. Commands remain copy-only guidance for authorized environments, and pivoting facts are created only from supported pasted Evidence, not command recognition alone.
