# Obol v5.6

## Release focus

v5.6 consumes the synchronized v5.5 North Star Build Next queue in its displayed priority order. The release first closes the remaining mapped-workflow delivery debt, then advances five mature partial canonical branches.

The pinned Orange Cyber Defense 2025.03 denominator and upstream commit remain unchanged.

## Delivery-contract completion

v5.6 supplies explicit Evidence profiles to every remaining mapped workflow that lacked one. High-impact workflows receive technique-specific proof boundaries, while any residual mapped card uses a conservative expected-output fallback that records completion without creating outcome facts.

The seven workflows that also lacked explicit execution-side metadata are audited in v5.6 so Kali, Windows, and target-local command context is explicit rather than inferred.

The live Build Next model is expected to leave zero implemented-quality debt and zero mapped-delivery debt after this release.

## Five canonical completions

The following previously partial sections move to implemented with delivery-ready owners:

- `acl.shadow-credentials`
- `acl.gmsa`
- `delegation.s4u2self`
- `mitm.ntlm-relay`
- `low_hanging.weak-services`

This raises strict canonical completion from 62/127 to 67/127, or 49% to 53%, while represented coverage remains 80%.

## Conservative Evidence boundaries

- Shadow Credentials requires an explicit key-credential write plus generated certificate material. Listing keys is not success.
- NTLM relay requires explicit successful relayed authentication. Listener startup and inbound connections alone are not success.
- MachineAccountQuota is a readiness fact only. A value above zero does not prove RBCD and a value of zero is still a successful check.
- S4U/getST ticket creation proves ticket material only. Administrator access requires separate service-use evidence.
- MySQL and PostgreSQL authentication are kept separate from file-write and operating-system execution proof.
- Web reachability/fingerprinting never becomes a vulnerability fact by itself.
- ACL enumeration can establish a control relationship without establishing administrator access.
- Zerologon remains detection-only. A patched result records a negative check and creates no vulnerability fact.
- gMSA managed-password material does not become plaintext; reusable hash material requires explicit parsed output.
- Ticket import proves a ticket is present, not that a protected service accepted it.

## CI and release process

The v5.5 release-process hardening remains permanent. Release-branch pushes run `node tools/release-preflight.js`; non-draft pull requests and `main` run the complete historical regression chain. v5.6 also makes preflight verify that the README Build Next generator is actually wired through the current release and rejects historical tests that hard-code a current README release token.

The README Build Next block remains generated from the same live repository model as the North Star Dashboard.
