# Obol v9.45 — Stylesheet ownership area flattening

v9.45 completes `runtime-style-flattening`, the last live item in the Runtime Layer Consolidation package.

This release keeps `assets/obol-current.css` as the single stable, non-versioned stylesheet owner, but changes what that owner is. The v9.40 owner was an exact formatted concatenation of all 69 historical CSS fragments. The v9.45 owner is a generated semantic cascade snapshot that removes declarations which are provably superseded by later declarations for the exact same selector, property, and grouping-at-rule context.

## What changed

- Added `tools/style-cascade-current.js`, a conservative CSS cascade reducer. It parses the frozen 69-fragment stylesheet ledger, keeps selector and at-rule order, and removes only declarations that cannot win for an identical selector/property inside an identical grouping context. Shorthand/longhand interactions are left alone, differing grouping contexts never compete, and vendor/fallback-looking declaration chains are preserved instead of being guessed away.
- `tools/sync-current-styles.js` now generates the semantic owner rather than an exact fragment concatenation. The shipped snapshot reduces 1,817 source style rules / 5,524 declarations to 1,809 rules / 5,496 declarations: 8 fully superseded rules and 28 superseded declarations leave the live current stylesheet. The historical fragments remain unchanged on disk.
- Added `tools/validate-style-current-equivalence.js`. It requires the current owner to match the generator exactly, verifies the complete 69-fragment compatibility ledger and its stable owner metadata, requires real reduction to occur, and mutation-tests the reducer's ordinary cascade, `!important`, vendor/fallback, and grouping-context safety rules.
- Added `tools/validate-style-visual-equivalence.js`. In Chromium it renders representative operator routes at desktop and mobile widths twice: once with the shipped semantic stylesheet and once with the exact historical 69-fragment cascade substituted for `assets/obol-current.css`. It compares layout geometry plus a broad computed-style surface for every rendered element and visible pseudo-element. The browser-smoke workflow owns this proof.
- Updated the runtime manifest, Product Hardening Dashboard, queue/test contracts, runtime documentation, scope/preflight validation, and historical v9.40 stylesheet assertion so the old release keeps protecting its one-request ownership contract without forcing the retired exact-concatenation delivery shape back into current architecture.

## Why this reduction is conservative

CSS can be dangerous to deduplicate mechanically because different selectors can overlap, shorthand properties can interact with longhands, media/support conditions can overlap, fallback value chains can be intentional, and source order participates in the cascade. v9.45 therefore does not attempt a general CSS optimizer.

A declaration is eligible for replacement only when all of these are identical:

- the trimmed selector source;
- the property name;
- the full ordered grouping-at-rule context, such as the same `@media` / `@supports` chain.

Within that narrow set, normal cascade order and `!important` choose the winner. Vendor-prefixed properties and differing vendor/fallback-looking values are retained. Unknown block at-rules, keyframes, font-face/page-style rules, and opaque declarations are preserved verbatim. The real-browser equivalence gate is the second, independent proof that this conservative source transformation did not alter current rendering.

## Compatibility

The frozen v9.5 stylesheet ledger remains 69 files in the same manifest order with the same path-order fingerprint. Existing browser-local workspaces, JavaScript runtime ownership, Evidence/proof semantics, command generation, recommendation logic, reporting, accessibility owners, responsive overrides, and the one-request stylesheet budget are unchanged.

The semantic owner may be larger than the historical source text because it is deliberately formatted for generated readability rather than minified. v9.45 is ownership/cascade flattening, not minification. The meaningful reduction is that dead/superseded cascade declarations no longer participate in the current owner, while the historical source remains available as the regression baseline.

With `runtime-style-flattening` complete, Runtime Layer Consolidation has no live items. Product Build Next advances to `cc-evidence-chain-restore`, the critical-correctness defect exposed during v9.44 Evidence ownership retirement.
