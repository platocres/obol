# Obol v9.8 - Dashboard and User Workflow Rebalance

v9.8 completes the **Dashboard and User Workflow Rebalance** Product Build Next package. The release keeps project/product accounting in the single Product Hardening Dashboard while making Home, navigation, and Next Steps visibly engagement-first.

## Stable current workflow owner

`assets/workflow-current.js` is the new stable non-versioned owner for current Home composition, secondary Product Dashboard navigation, the in-app dashboard handoff, and the current Next Steps decision brief.

`assets/app-v8.8.js` remains the v8.8 workspace/runtime compatibility bridge for current release identity, report/export normalization, accessibility loading, and lazy Product Hardening assets. It no longer renders its own Product Hardening Home status panel or competing dashboard content.

`data/runtime-manifest.js` registers the stable workflow owner in the Product Hardening lazy asset group so asset validation continues to see it.

## One Product Hardening Dashboard

`assets/product-hardening-dashboard.js` is now the sole current project/product progress renderer for both:

- `#/dashboard` inside the main Obol app;
- `product-hardening.html` as the standalone dashboard entrypoint.

The embedded form returns to Home rather than linking back to itself. Historical Orange project-status panels remain available only as historical runtime/regression material and no longer compete in the live current dashboard route.

## User-first Home

Home is rebuilt around the active engagement rather than the software build. Its prime scan path now shows:

- active target/context;
- known facts and typed artifacts;
- queued operator intent;
- Evidence attention and direct Evidence review access;
- the best evidence-ranked next move and unlock count;
- broken/unverified path and credential-validation blockers;
- recent activity;
- report proof readiness.

Product Hardening and Orange source-accounting totals are removed from Home. A quiet Product Dashboard link keeps build/project metrics discoverable without occupying the operator workspace.

## Navigation and Path clarity

The five-item primary navigation remains unchanged:

`Home -> Targets -> Evidence -> Next Steps -> Report`

Product Dashboard is added to the secondary More menu so it is easy to find without cluttering the primary operator loop.

Next Steps keeps the established `C.nextStepsOverview34(...)` evidence-ranked recommendation model. The stable current workflow adds a compact decision brief that places these together immediately after the top recommendation:

- best next move;
- downstream unlock count;
- queued operator intent;
- blocker count and breakdown.

## Permanent validation

The new ownership boundary is checked by:

```bash
node tools/validate-current-workflow.js
```

The validator proves that:

- the v8.8 bridge delegates to the stable current workflow;
- Product Hardening is the single current dashboard owner;
- Home contains the required engagement-first surfaces and no project-build accounting;
- Product Dashboard is secondary navigation, not a sixth primary workflow destination;
- Next Steps exposes best move, unlocks, queued intent, and blockers from the existing recommendation context;
- all five v9.8 queue items remain complete.

Product Hardening preflight runs this validator permanently. The release regression suite is:

```bash
node tests/run-v9.8-tests.js
```

The full non-draft PR regression chain passed before the coherent preflight snapshot. Historical v9.1 and v9.7 suites were also made future-safe where they had frozen superseded current UI or queue ownership shapes rather than durable release milestones.

## Compatibility

Obol remains static, browser-local, and human-run. v9.8 adds no backend, telemetry, account system, install prompt, automatic command execution, public raw-note import, or workspace-schema migration. `C.VERSION` remains `8.8.0`.

The release does not replace the evidence-ranking model, Evidence proof semantics, workspace storage, report lineage, or historical runtime chain. It changes current UI ownership and information hierarchy only, with permanent validation around that boundary.
