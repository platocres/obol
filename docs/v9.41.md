# Obol v9.41 — Domain ownership flattening

v9.41 completes `runtime-domain-flattening`, the first semantic pass after v9.40’s request consolidation.

The browser and Node current runtimes now execute `assets/obol-domain-current.js` as an authored semantic snapshot instead of directly executing the 103 versioned domain fragments that accumulated lane data, methodology overlays, Orange source-fidelity records, project-model adapters, report metadata, and signatures. Those historical files remain on disk and in the frozen ledger; they are now the build-time equivalence source rather than live startup code.

## What changed

- `data/runtime-manifest.js` now declares per-area current-owner strategies. The domain area is `semantic-snapshot`; core, app, Evidence parsing, Nmap, report overlays, and tool reference data remain `ordered-fragment-concatenation`.
- `tools/sync-domain-current.js` executes the frozen domain ledger at build time and emits the stable domain owner as a deterministic graph reconstruction.
- `tools/validate-domain-current-equivalence.js` compares the historical chain and semantic owner in isolated VM contexts, proving the same `OBOL_*` root order, enumerable graph, shared identities, cycles, mutability flags, RegExp metadata, and function signatures.
- The validator separately exercises the six authored live functions: tool alias normalization, Rubeus defaults, Rubeus command building, audited operator-surface classification, Orange stage placement, and report-contract generation.
- `tools/current-runtime.js` and the browser loader use the semantic domain owner directly, while preserving the historical domain list as an inert source-observation projection and fixture ledger.
- The runtime consolidation projection, Product Hardening Dashboard, README Product Build Next block, and item-test contracts now distinguish semantically flattened fragments from fragments that still execute through exact owners.
- The Tool Builder inventory now includes explicit modeled dispositions for additional runnable identities surfaced by the semantic domain graph; v9.41 does not add new builders for them.

## Current runtime accounting

- 103 domain fragments are semantically flattened.
- 194 fragments still execute through exact current owners: core, app, Evidence parsing, Nmap, report overlays, and tool reference data.
- 30 Dashboard data/presentation fragments remain retired to the frozen ledger.
- Operator startup remains 5 JavaScript/CSS requests: one Dashboard compatibility prelude, three startup owners, and one stylesheet owner.

## Preserved boundaries

v9.41 does not change the v8.8 workspace/runtime schema, browser-local storage, human-run command model, conservative Evidence interpretation, report proof boundaries, current route ownership, request budget, frozen v9.5 order fixture, or exact-head release validation. It also does not flatten core, app, Evidence, or CSS; those remain separate Product Build Next items with their own equivalence surfaces.

## Validation

The release adds and wires the domain proof into the existing product-hardening gates:

```sh
node tools/sync-domain-current.js --check
node tools/validate-domain-current-equivalence.js
node tools/sync-runtime-bundles.js --check
node tools/validate-runtime-bundles.js
node tools/validate-runtime-manifest.js
node tools/validate-runtime-loading.js
node tools/validate-runtime-consolidation-sync.js
node tests/run-v9.41-tests.js
```

`node tools/release-preflight.js` runs the new domain synchronization and semantic-equivalence checks before the current release suite.
