# Obol v5.3

v5.3 is the first implementation pass driven directly by the v5.2 **Build next** ordering. It does not raise the canonical methodology count. Instead, it repairs delivery debt on already-implemented or implementation-bearing workflows so strict methodology completion does not outrun operator usability.

## Repair set

The release targets eight mapped workflows:

- Anonymous SMB Enumeration
- DNS Enumeration & Zone Transfer
- Kerberos Ticket Hygiene
- LAPS Local Admin Password Read
- Local Enumeration Sweep
- SeImpersonatePrivilege
- DPAPI Credential Decryption
- Stored Credential Hunting

Each receives an explicit v5.3 Evidence profile and audited execution-side metadata for commands that were still relying on fallback inference.

## Conservative Evidence rules

v5.3 adds explicit copy/paste proof handling for the repair set.

- Anonymous SMB succeeds only when output explicitly lists accessible shares.
- DNS zone transfer succeeds only when output explicitly shows transferred records and a completed transfer.
- Kerberos ticket hygiene succeeds only when a saved or active ticket cache is shown.
- LAPS succeeds only when a non-empty LAPS password value is shown. It does not create an administrator-access fact.
- Windows local enumeration can establish only a privilege-escalation lead from explicit output.
- SeImpersonatePrivilege does not become SYSTEM merely because the privilege is enabled; explicit `NT AUTHORITY\\SYSTEM` output is required.
- DPAPI credential recovery requires explicit decrypted username/password fields.
- Stored Credential Hunting distinguishes a saved credential candidate from an explicitly exposed plaintext password.

These rules continue the existing Obol proof model: command recognition is intent, not success.
