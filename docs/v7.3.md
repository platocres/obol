The release decomposes the broad listening and relay concepts into explicit operator branches, preserves one obsolete source branch as a superseded historical route, and moves the live queue into the remaining authenticated source-depth baselines.

## Source inventory

- credential and hash listening;

- NTLM relay to LDAP(S);

## Evidence boundaries

The release deliberately keeps these states separate:

1. listener active;
2. inbound authentication observed;
3. successful relay authentication;
4. a specific directory or service-side mutation;
5. hash, credential, certificate, or ticket material;
6. authenticated service use;
7. execution;
8. administrator/SYSTEM access;
9. privilege or domain-control consequence;
10. cleanup/restoration.

Responder startup does not create a captured-hash fact. An ntlmrelayx listener does not prove relay success. A successful relay does not prove that a requested LDAP write succeeded. Certificate material is not authenticated access. A SOCKS session is not MSSQL sysadmin or command execution. DCSync consequence requires explicit replication output.

`assets/intake-v7.3.js` enforces these conservative terminal-Evidence boundaries for the new v7.3 owners.
