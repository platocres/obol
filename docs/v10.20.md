## Operator-visible surfaces

- `#/tools` now places modeled and implemented tools in the same operator-facing taxonomy instead of rendering the remaining modeled inventory as one giant unstructured chip wall or a second backlog category.
- Tool chips remain clickable/selectable. `modeled` means the builder contract is still pending, not that the tool has no place.
- `#/tools/mysql`, `#/tools/psql`, `#/tools/redis-cli`, `#/tools/odat`, and `#/tools/impacket-mssqlclient` now start with operator guidance and working action presets instead of leaving the human to infer which command mode is appropriate.
- Empty database accessory cards are hidden when no useful recommendations exist, legacy examples stay below the guided builder surface, and database route compatibility landmarks no longer present fake clickable preset chips.

## Proof boundary

This build organizes and exposes the remaining modeled backlog. It does not promote a modeled tool to implemented unless that tool has the full Tool Builder contract: schema-driven minimum viable command or guided handoff generation, real supplied or Evidence-derived prefill, additive controls, executable Evidence ingestion, conservative proof boundaries, cleanup/report guidance, and Next Steps movement or blocking where supported.

The shared plumbing helper owns repeated mechanics only. It must not own tool judgment. Tool-specific profiles remain responsible for purpose, nearest-neighbor distinction, modes, controls, Evidence patterns, proof boundaries, cleanup guidance, and Path movement rules.

The operator-guidance repair and web discovery and HTTP guidance repair add a stricter human-facing requirement: command generation alone is not enough. The route must teach what the tool is for, what to try first, what the selected action proves or does not prove, what risky actions require, and what output belongs in Evidence.

The implemented-builder audit ledger makes that requirement testable for every registered implemented builder. It also preserves Brandon's direct Tools-page rule: do not proof-gate command generation. Missing command-construction fields may invalidate a preview, but prior Evidence must not be required before a human can select an action and generate the command.

## Historical-test compatibility

Older Tool Builder and note-derivation regression suites were adjusted only where they encoded obsolete README delivery shape. They still require the Tool Builder contract, Product Build Next handoff, note-source boundaries, and changelog discipline, but they no longer force the duplicated README Tool Builder queue section back into the entrypoint.

The follow-up correction preserves the public `groupForTool()` taxonomy IDs used by Tool Builder planning tests while mapping those IDs onto the canonical Tool Library section IDs at render time, so stylesheet-equivalence checks do not see duplicate operator categories.
