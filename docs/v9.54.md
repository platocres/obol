# Obol v9.54

v9.54 converts the first Linux privilege-escalation source re-mining batch into public-safe, contextual path behavior instead of leaving the findings as future gaps, broad-lane append cards, or a generic Path page panel.

## What changed

- Added the first Linux privilege-escalation re-mining batch to the current note-progress projection without claiming raw Git LFS access from this agent runtime.
- Re-read four already-reviewed Linux privilege-escalation sources from the complete packet fallback and published per-note, per-dimension audit rows for service-footprint review, user-trail secret hunting, cron execution chains, and sudo authorization.
- Built the mined Linux findings into actual Next Steps ownership:
  - added `linux-user-trail-secret-review`, gated by Linux foothold state;
  - added `linux-process-traffic-secret-review`, gated by Linux foothold or privilege-escalation lead state;
  - added `linux-sudo-list-review`, gated by Linux foothold or privilege-escalation lead state;
  - added `linux-cron-proof-chain`, gated by Linux foothold or privilege-escalation lead state;
  - added `candidate-credential-validation`, gated by candidate credentials plus a reachable service;
  - added `credential-pattern-wordlist-helper`, gated by candidate material, web vocabulary, domain context, or looted files;
  - enhanced the existing `online-brute` Hydra item with source-mined candidate-validation guidance.
- Re-audited the latest Claude note-mechanic backfill branch as a clue for which review set needed inspection, but did not rely on Claude's older reduced note material as source. This pass re-mined the complete HTB packet 03 material from `platocres/obol-source-notes@agent/review-packets:data/review-packets/htb-penetration-tester-03.json`.
- Converted that robust web re-mine into contextual path behavior:
  - enhanced `website-discovery` with backend language/routing checks before upload or inclusion payload decisions;
  - enhanced `file-upload` with separate accepted, stored, reachable, interpreted, and executed proof states;
  - enhanced `lfi-probe` with parameter discovery, file-read proof, wrapper/source disclosure, remote retrieval, and execution boundaries;
  - enhanced `web-shells` with upload-to-include readback proof before shell claims;
  - added `web-parameter-fuzzing`, inserted after content discovery and before LFI testing;
  - added `file-inclusion-proof-chain`, inserted after LFI probing;
  - added `php-wrapper-source-review`, inserted after file-inclusion proof;
  - added `upload-to-include-chain-review`, inserted near upload/web-shell flow;
  - added `file-upload-proof-boundary`, inserted beside the upload card.
- Updated `data/product-hardening/note-mechanic-backfill-v9.38.js` from Claude's older mechanic/guidance-only backfill into a complete-packet robust re-mine record with per-note reread outcomes, packet proof, contextual card IDs, changed owners, and proof refs.
- Fixed direct inspection for the dynamically inserted source-mined cards. The card data was present in the live lane model, but `#/card/<card-id>` could still render `Unknown card` because the card route used its earlier card index. `assets/source-mined-card-route-current.js` now resolves those card IDs from live lane data after the source-mined card owner loads.
- Cleaned the direct inspection view so it shows operator-facing inspection content only: title, hypothesis, placement, gates, produced facts, commands with purpose explanations, failure routing, and defender view. No implementation-plumbing explanation is shown to users.
- Removed weak card UI scaffolding from the source-mined direct inspector. Cards should not show generic boxes such as `When to use this`, labels such as `Tool action stack`, collapsed `Raw legacy commands`, or notes that merely repeat authorization boilerplate instead of explaining what a command is for.
- Added `docs/CARD-UI-STANDARD.md` to make the card rule explicit: every card command needs a useful explanation of what the command does and how to interpret its output, and user-visible cards must not expose developer artifacts.
- Updated the dashboard path so the v9.54 Linux rows are recorded as contextual mined additions with `added` outcomes, exact card IDs, owner refs, and path proof instead of unresolved product gaps.
- Tightened `docs/AGENT-WORKFLOW.md` around the mine-then-use rule: agents must attach useful mined findings to existing Next Steps items when possible. When no existing item is the right owner, agents must analyze the surrounding lab path and prove the new gated item’s lane, ordering behavior, preceding evidence, neighboring cards, downstream unlocks, failure routing, and produced facts. Generic `#/path` panels and broad-lane append cards are explicitly not enough.
- Added direct-route proof to the workflow rule: dynamically inserted or current-owner cards must be inspectable from `#/card/<card-id>`, and a PR is not complete if the public route still renders `Unknown card`.
- Added card-UX proof to the workflow rule: user-visible cards must stay free of developer-facing artifacts such as runtime plumbing, route fallback explanations, startup index details, dashboard accounting notes, source-mining provenance, and any copy that explains why the UI component exists instead of what the operator should do.
- Preserved existing Linux Field Notes, web path cards, and Orange-derived path bindings additively rather than replacing earlier public guidance or publishing private recipe material.
- Added `tests/run-v9.54-tests.js` to assert the expanded re-mining projection, complete-packet lineage, contextual path-card conversion, direct source-mined card route inspection, operator-facing card copy, robust Claude-backfill re-mine, existing-card enhancement, and the permanent audit validator.
