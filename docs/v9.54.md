# Obol v9.54

v9.54 converts the first Linux privilege-escalation source re-mining batch into public-safe, contextual path behavior instead of leaving the findings as future gaps, broad-lane append cards, or a generic Path page panel.

## What changed

- Added the first Linux privilege-escalation re-mining batch to the current note-progress projection without claiming raw Git LFS access from this agent runtime.
- Re-read four already-reviewed Linux privilege-escalation sources from the complete packet fallback and published per-note, per-dimension audit rows for service-footprint review, user-trail secret hunting, cron execution chains, and sudo authorization.
- Built the mined findings into actual Next Steps ownership:
  - added `linux-user-trail-secret-review`, gated by Linux foothold state;
  - added `linux-process-traffic-secret-review`, gated by Linux foothold or privilege-escalation lead state;
  - added `linux-sudo-list-review`, gated by Linux foothold or privilege-escalation lead state;
  - added `linux-cron-proof-chain`, gated by Linux foothold or privilege-escalation lead state;
  - added `candidate-credential-validation`, gated by candidate credentials plus a reachable service;
  - added `credential-pattern-wordlist-helper`, gated by candidate material, web vocabulary, domain context, or looted files;
  - enhanced the existing `online-brute` Hydra item with source-mined candidate-validation guidance.
- Fixed direct inspection for the dynamically inserted source-mined cards. The card data was present in the live lane model, but `#/card/<card-id>` could still render `Unknown card` because the card route used its earlier card index. `assets/source-mined-card-route-current.js` now resolves those v9.54 card IDs from live lane data after the source-mined card owner loads.
- Cleaned the direct inspection view so it shows operator-facing inspection content only. It now explains when to use the step, the placement, gates, produced facts, commands, failure routing, and defender view; no implementation-plumbing explanation is shown to users.
- Updated the dashboard path so the v9.54 Linux rows are recorded as contextual mined additions with `added` outcomes, exact card IDs, owner refs, and path proof instead of unresolved product gaps.
- Tightened `docs/AGENT-WORKFLOW.md` around the mine-then-use rule: agents must attach useful mined findings to existing Next Steps items when possible. When no existing item is the right owner, agents must analyze the surrounding lab path and prove the new gated item’s lane, ordering behavior, preceding evidence, neighboring cards, downstream unlocks, failure routing, and produced facts. Generic `#/path` panels and broad-lane append cards are explicitly not enough.
- Added direct-route proof to the workflow rule: dynamically inserted or current-owner cards must be inspectable from `#/card/<card-id>`, and a PR is not complete if the public route still renders `Unknown card`.
- Added card-UX proof to the workflow rule: user-visible cards must stay free of developer-facing artifacts such as runtime plumbing, route fallback explanations, startup index details, dashboard accounting notes, source-mining provenance, and any copy that explains why the UI component exists instead of what the operator should do.
- Preserved existing Linux Field Notes and Orange-derived path bindings additively rather than replacing the v9.50 Linux packet or publishing private recipe material.
- Added `tests/run-v9.54-tests.js` to assert the expanded 19-row re-mining projection, complete-packet lineage, contextual path-card conversion, direct source-mined card route inspection, operator-facing card copy, existing-card enhancement, and the permanent audit validator.
