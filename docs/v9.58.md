## Built proof/auth controls

The XSS proof-mode selector exposes four public-safe proof styles without publishing payload recipes:

- dialog proof;
- DOM marker proof;
- console marker proof;
- harmless callback proof.

The cleanup reminder is tied to marker-style and callback-style proofs. It reminds the operator to remove temporary markers or callback plumbing where possible and to record cleanup status separately from browser-execution proof.

The credential-validation safety slot keeps the following fields beside auth-capable builders: material class, protocol scope, service scope, identity scope, lockout policy, attempt cadence, failure scope, and success scope.

The auth-material scope analyzer conservatively separates challenge-response captures, reusable hash material, Kerberos tickets, SSH keys, web tokens, plaintext candidates, scoped authentication success, and scoped authentication failure. It warns against promoting challenge-response captures into pass-the-hash access without separate proof.

## Evidence ingestion

The v9.58 Evidence ingestion bridge is part of the actual build, not a later follow-up. It attaches to `OBOL_INTAKE_V21.analyzeTerminal` when the Evidence route loads and emits activities for:

- `xss-proof-mode-selector`;
- `xss-proof-cleanup-reminder`;
- `credential-validation-safety-slot`;
- `auth-material-scope-analyzer`.

Those activities produce Next Steps movement facts for reviewed browser execution, proof cleanup, validation-scope readiness, auth-material classification, proof-state classification, scoped validation success, and scoped validation failure.

The parser stays conservative. It does not turn challenge-response captures into pass-the-hash access, does not treat one failed login as global invalidation, and does not turn one scoped authentication success into broad admin, server execution, or session-compromise proof.

## Product Build Next queue sync

Queue update is part of this release's Definition of Done, not a manual follow-up.

The v9.58 extensions mark `notes-remine-xss-session`, `notes-remine-credentials-auth`, `gap-xss-proof-mode-selector`, `gap-xss-proof-mode-cleanup-reminder`, `gap-auth-validation-safety-slot`, and `gap-auth-material-scope-analyzer` complete when Product Hardening data is evaluated.

The Product Build Next generator now loads both merged runtime re-mining extensions and the current release's declared Product Hardening extensions before it renders the generated queue block. That keeps stale XSS, credentials/auth, and same-surface proof/auth items from remaining at the top of the README/dashboard handoff after the release is synced.

After generated sync, Product Build Next should advance to the next real remaining package rather than showing the just-built XSS/auth control work.

## Same-surface gap parking guard

`docs/SAME-SURFACE-GAP-PARKING-GUARD.md` is now part of the release contract. Buildable work that belongs to the same ownership area and same live surface must be built in the current pass or explicitly justified with a real blocker.

The PR template now requires a no-gap-parking checkbox, and `tools/validate-live-integration-done-gate.js` validates the guard so this does not rely on agent memory.

## Source boundary

This release uses the complete private review-packet route at `platocres/obol-source-notes@agent/review-packets` and keeps raw source text private. Public Obol receives only rewritten, generalized guidance and product metadata.

The release intentionally excludes raw secrets, captured values, ticket-injection recipes, relay or capture setup mechanics, target names, private keys, passphrases, flags, and course-specific replay steps.
