## What changed

- Re-mined the reviewed credentials/auth source lane into public-safe live guidance cards for provenance, protocol scope, challenge-response proof boundaries, validation safety, and protected-secret lineage.
- Added `data/product-hardening/credentials-auth-remining-v9.58.js` with per-source findings, 16-dimension re-mining audit rows, field-note outputs, queued product gaps, and live integration hooks.

- Updated `tools/sync-product-build-next.js` so the generated Product Build Next handoff loads runtime-discovered and release-declared re-mining extensions before computing queue totals, next items, and dashboard/README text.
- Updated `.github/workflows/sync-release-artifacts.yml` so generated release artifact sync runs `node tools/sync-product-build-next.js --write` whenever Product Hardening data or the queue generator changes.
- Added `tests/run-v9.58-tests.js` to prove the release identity, extension loader, source metadata, live card IDs, per-dimension audit coverage, queue mutation, queue-sync workflow gate, note helper behavior, progress update, and obvious unsafe-public-material guardrails.

## Product Build Next queue sync

Queue update is part of this release's Definition of Done, not a manual follow-up.

The v9.58 artifact marks both `notes-remine-xss-session` and `notes-remine-credentials-auth` complete when the Product Hardening bundle is evaluated, then inserts the new auth follow-up gap items as concrete queued work.

The Product Build Next generator now loads both merged runtime re-mining extensions and the current release's declared Product Hardening extensions before it renders the generated queue block. That keeps stale XSS or credentials/auth entries from remaining at the top of the README/dashboard handoff after the release is synced.

The generated v9.58 README handoff now starts with the queued UI/UX proof-mode work, then the credential-validation and auth-material analyzer follow-ups, then Linux re-mining. That proves the XSS and credentials/auth re-mining items no longer remain as stale top-of-queue entries after sync.

The release sync workflow now runs Product Build Next sync on product-hardening changes, so future releases cannot rely on an agent remembering to update the queue by hand.

## Source boundary

This release uses the complete private review-packet route at `platocres/obol-source-notes@agent/review-packets` and keeps raw source text private. Public Obol receives only rewritten, generalized guidance and product metadata.

The release intentionally excludes raw secrets, captured values, ticket-injection recipes, relay or capture setup mechanics, target names, private keys, passphrases, flags, and course-specific replay steps.
