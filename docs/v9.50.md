# Obol v9.50 — Linux privilege-escalation notes packet

v9.50 continues the Notes Impact and Themed Burn-down work package with the Linux privilege-escalation packet.

## Packet scope

The private source review was curated to eight reusable Linux local privilege-escalation sources. Seven are modeled into public-safe Obol guidance and one exploit-specific source remains private-reference-only. Raw course prose, targets, flags, credentials, screenshots, exploit recipes, and review packet bodies remain outside the public repository.

The packet advances the current public-safe projection from 127/556 reviewed to **135/556 reviewed**:

- **102 modeled**
- **28 private-reference-only**
- **5 superseded**
- **0 rejected**
- **421 pending-review**

The seven new public Field Notes cover:

- Linux local privilege-enumeration triage;
- privileged service/process observation versus access proof;
- shell history, environment, dotfile, and configuration secret-hunting boundaries;
- cron and other privileged execution preconditions;
- sudo authorization and effective-identity proof;
- SUID/capability boundaries;
- kernel exploit compatibility, stability risk, and post-attempt proof.

## Notes-to-product decision

Every newly modeled source records an explicit `guidanceOnlyReason`. The reviewed Linux packet did not expose a missing command-builder control, Path primitive, Evidence parser rule, report generator behavior, or workflow state that justified another code-level mechanic. Existing human-run Linux enumeration and privilege-escalation surfaces can represent the actions; the durable product improvement is stricter sequencing, precondition reasoning, and proof boundaries.

This is deliberately not a copied GTFOBins, sudo, SUID, cron, or kernel-exploit recipe catalog. Obol continues to guide authorized operator reasoning without automatically executing commands.
