# Obol v9.16

Obol v9.16 continues the post-Orange Product Hardening phase with the canonical Gobuster / Feroxbuster content-discovery Tool Builder.

## Shipped scope

v9.16 completes Product Hardening item `tb-gobuster-ferox` on the stable Tool Builder platform. Gobuster and Feroxbuster now resolve through one shared schema-driven builder rather than separate custom mini-apps.

The builder exposes:

- Gobuster `dir`, `vhost`, and `dns` modes;
- Feroxbuster recursive and non-recursive discovery with optional maximum depth;
- target and workspace wordlist context;
- extensions;
- allowlist or filter status-code handling;
- response-size filtering;
- repeated headers;
- thread controls;
- redirect, TLS-validation, and trailing-slash options where supported;
- Feroxbuster request-rate control;
- output-file handling.

The current browser bridge seeds the shared builder to Gobuster or Feroxbuster from the active Tool or Card route, so a Feroxbuster command reference opens the canonical shared builder in Feroxbuster mode rather than defaulting to Gobuster.

## Stable platform extension

The stable Tool Builder schema and renderer remain version `1.0.0`. v9.16 adds one generic command-model capability: `command.executable` may be a declared selector whose choices map a schema field to a fixed executable literal.

This exists so one canonical builder can represent sibling tools with the same controls and proof model without duplicating the builder. Executable values are not free-form operator input. The schema validates a fixed safe command-literal allowlist, the renderer resolves only a declared choice, and unknown executable selections fail command generation.

This is a reusable platform feature, not a Gobuster/Feroxbuster compiler branch.

## Proof boundary

Obol still generates, previews, and copies commands for the operator to run externally. It does not execute Gobuster, Feroxbuster, or any other generated command.

A generated command, request count, or manually declared discovery result remains workflow activity. Paths, hosts, subdomains, and response facts become report-ready only after returned tool output is reviewed through Evidence.
