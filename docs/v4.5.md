# Obol v4.5

Obol v4.5 is the **Orange operator-loop contract** release.

v4.4 made the Orange Cyberdefense 2025.03 decision path materially influence Next Steps. The v4.4 README also contains a stricter follow-on requirement: the tools used at each path step should have usable GUI command controls, and Obol should understand copy/pasted terminal evidence well enough to improve subsequent decisions.

v4.5 builds infrastructure for that requirement without changing Obol's human-run architecture.

Obol still does not execute commands, install tools, scan targets, authenticate to systems, create pivots, or mark a technique successful merely because a command exists. The operator runs commands externally and pastes output into Evidence.

## Run / evidence contract model

Orange-mapped methodology cards now expose a reusable contract containing:

- command count;
- number of commands with semantic GUI controls or a dedicated builder;
- fixed-command count;
- whether a high-confidence copy/paste evidence profile exists;
- evidence family and parser source;
- the limited fact types that profile is allowed to establish.

`assets/core-v4.5.js` exposes:

- `C.orangeContractFor45(card)`
- `C.orangeContractCoverage45(LANES)`
- `C.orangeQueueReadiness45(state, LANES, context)`

`nextStepsOverview34()` now carries an `orangeContracts45` payload alongside the existing v4.4 decision-path payload.

The contract model is diagnostic. It does not change applicability or ranking.

## GUI command-control improvements

v4.5 closes concrete control gaps identified during the Orange-path audit.

### SCCMHunter

Existing `sccmhunter.py` discovery commands now expose an optional **Debug output** GUI control. The base command remains the minimum useful action and the debug switch stays opt-in.

### Impacket MSSQL

The connection-form `impacket-mssqlclient` command gains semantic controls for:

- Kerberos cache authentication (`-k`)
- no-password mode (`-no-pass`)
- hash authentication (`-hashes`)
- protocol/debug output (`-debug`)

SQL statements represented as methodology commands are intentionally not given connection switches, because those statements are entered after the client is already connected.

### Existing builders remain authoritative

v4.5 does not duplicate mature control surfaces already present in earlier releases:

- Nmap keeps the Targets-owned scan builder;
- Rubeus keeps the dedicated v3.6 workbench;
- NetExec, LDAP, Hashcat, Kerbrute, Certipy, and major Impacket families retain their existing semantic options;
- fixed native commands remain visible as fixed commands rather than receiving meaningless toggles.

## Copy/paste terminal evidence profiles

`assets/intake-v4.5.js` adds explicit command intent and conservative proof handling for Orange workflows that previously relied mainly on generic command matching.

### Hashcat Active Directory modes

Recognized audited AD modes include:

- 3000
- 1000
- 5500
- 5600
- 13100
- 19600
- 19700
- 18200
- 2100
- 31300
- 19850

Only explicit `Status........: Cracked` output can establish `credential.plaintext` through this v4.5 profile.

### BloodHound collection

Recognized forms include:

- `bloodhound-python`
- `SharpHound.exe`
- NetExec LDAP collection with `--bloodhound`

Only explicit archive/completion output establishes `ad.graph.collected`. Merely launching a collector does not establish attack paths.

### SCCM discovery

Recognized SCCMHunter discovery commands map to `sccm-enum`.

Explicit site-code, management-point, SMS-provider, or SCCM-site output can mark the reconnaissance activity supported. v4.5 deliberately adds **no automatic credential or administrative-access facts** from SCCM discovery text.

### Trust enumeration

Recognized forms include:

- `nltest /domain_trusts`
- `nltest /trusted_domains`
- `Get-DomainTrust`
- `Get-DomainTrustMapping`

Explicit trust relationship output can establish `ad.trusts`.

### GPP recovery

Recognized forms include:

- `gpp-decrypt`
- `Get-GPPPassword.py`

Only explicit decrypted/password material can establish `credential.candidate`.

### AD CS enumeration

Recognized forms include:

- `certipy find`
- `Certify.exe find`

Only explicit ESC/vulnerability output can establish `adcs.vulnerable`.

### MSSQL access

Recognized `impacket-mssqlclient` / `mssqlclient.py` sessions map to `mssql-access`.

An interactive SQL prompt or explicit Microsoft SQL Server response can establish `db.mssql_access`. It does not automatically establish OS command execution or a foothold.

### Golden Ticket creation

Recognized `impacket-ticketer` / `ticketer.py` sessions map to `golden-ticket`.

Only explicit saved `.ccache` output can establish `persistence.domain` through this profile.

## Inherited evidence contracts

v4.5 also catalogs mature inherited evidence handling so the audit can distinguish real parser coverage from gaps.

Examples include:

- Nmap completion handling from v2.1
- anonymous LDAP workspace repair from v3.5
- Rubeus intent and ticket handling from v3.6
- Impacket roast, ticket, secretsdump, DCSync, and remote-execution handling from v3.9

The audit records the source release rather than pretending v4.5 implemented those parsers from scratch.

## Next Steps UI

Next Steps gains a **v4.5 operator loop audit** panel.

For current Orange-mapped recommendations it shows:

- whether the card has adjustable GUI-controlled commands;
- whether the command is intentionally fixed;
- whether a copy/paste Evidence profile exists.

This sits beside the v4.4 Orange decision-path panel. The two concerns are separate:

- v4.4 answers **where does this fit in the decision path?**
- v4.5 answers **can the operator run it through a usable Obol command surface and feed the result back into Evidence?**

## Evidence UI

Evidence gains an Orange copy/paste profile summary that shows how many decision-path cards have explicit evidence profiles.

The percentage is a parser-contract metric, not the Orange methodology completion percentage from v4.2/v4.3.

## Methodology-card visibility

Orange-mapped card pages now show a compact **Run / evidence contract** line containing:

- command count;
- commands with GUI controls;
- evidence-profile family when available.

This makes missing command or evidence contracts visible during normal methodology use rather than hiding the audit only in tests.

## Coverage semantics remain unchanged

v4.5 improves command/evidence contracts. It does not implement new canonical Orange techniques merely by adding controls or parser coverage.

The strict live Orange baseline therefore remains:

- 42 implemented
- 39 partial
- 46 gaps
- 0 stale mappings
- 33% fully implemented
- 64% represented

## Future work

Use the v4.5 contract audit together with the canonical Orange gap queue.

A future technique should ideally land with all of the following in the same release:

1. a real methodology card mapped to the canonical Orange section;
2. correct Kali / Windows / target-local execution metadata;
3. semantic GUI command controls where switches are meaningful;
4. a conservative copy/paste terminal evidence profile;
5. regression fixtures covering successful, failed, partial, and malformed output;
6. coverage-state updates only after the workflow is materially complete.

Priority methodology gaps from v4.4 remain SCCM depth, domain persistence, trust abuse, Windows low-access branches, AD CS depth, relay/coercion depth, delegation/ACL breadth, Kerberos relay, and carefully selected authenticated historical-vulnerability workflows.
