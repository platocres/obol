# Obol v3.7

v3.7 advances the multi-host planning, reachability, lineage, and full-session regression priorities carried forward from the v3.6 README.

The release does not add another primary navigation destination. It deepens the existing owners:

- **Next Steps** gets target-specific reachability context.
- **Evidence Lineage** gets multi-hop compromise-path navigation.
- **Reachability & pivot lifecycle** gets verification-freshness semantics.
- Existing activity/artifact history gets conservative consumer-side activity-ID repair.

Obol remains static, browser-local, review-first, offline-capable, and human-run only.

## Target-specific reachability

Earlier reachability ranking could correctly distinguish direct, pivot-reachable, observed-only, and broken-path state, but same-service observations in a larger engagement could still be summarized too broadly.

v3.7 keeps the service-level methodology model while carrying the actual observed destination addresses into the ranking signal.

For a service-oriented recommendation, Obol now retains a target list containing:

- observed address
- service family
- direct / pivot / observed state
- covering path when one exists
- path verification freshness
- matching broken path when one exists

The recommendation UI surfaces grounded target chips so a service recommendation is tied to the addresses it actually applies to.

## Pivot verification freshness

An active path is not automatically treated as equally trustworthy forever.

v3.7 classifies active paths as:

- **fresh** — verified within 30 minutes
- **aging** — verified within four hours
- **stale** — older than four hours
- **unverified** — active but never explicitly verified
- **broken / inactive** — lifecycle state remains authoritative

Fresh pivot coverage receives the strongest target-specific recommendation boost. Aging paths receive a smaller boost and an explicit re-verification hint. Stale or never-verified pivot state remains recorded but no longer receives a full service-reachability boost.

This does not silently deactivate or delete a path. The operator still owns lifecycle state.

## Multi-hop compromise paths

The existing dependency graph already conservatively linked artifacts when one preserved artifact was consumed by a methodology card that later produced another preserved artifact.

v3.7 turns those edges into navigable multi-hop chains.

Evidence Lineage can now derive chains such as:

`artifact → methodology → artifact → methodology → artifact`

Chains are bounded, cycle-safe, context-scoped, and derived only from recorded producer/consumer relationships. Candidate-secret values remain masked.

The Lineage overview shows the longest grounded chains first, with a configurable traversal depth. Selecting an artifact also shows its upstream and downstream neighborhood so the operator can move through the recorded compromise path without losing the exact artifact timeline.

## Consumer-side exact activity lineage repair

Producer activity-ID repair was strengthened in v3.5 and v3.6. v3.7 extends conservative repair to artifact consumers.

A consumer record missing an activity ID can be repaired only when:

- the consumer has a methodology card ID
- consumer and activity share the same context
- timestamps are within five seconds
- exactly one activity for that card matches the window

If multiple activities qualify, the consumer remains unresolved rather than guessing.

## Full-session regression coverage

v3.7 adds a mixed Active Directory operator-session regression instead of testing only isolated strings. The fixture includes anonymous NetExec LDAP enumeration followed by Rubeus AS-REP roasting and verifies that the two commands remain separate methodology activities with conservative outcomes.

This starts the broader full-session fixture work called out in the README while keeping the existing isolated parser regressions for precise failure diagnosis.

## UI integration

Next Steps adds grounded target chips underneath recommendations when target-specific service observations exist.

Reachability & pivot lifecycle adds freshness badges and warns when an active path is stale or has never been verified.

Evidence Lineage adds:

- Compromise paths on the overview
- configurable chain depth
- upstream/downstream artifact neighborhoods on artifact detail pages
- direct links back to methodology cards and artifact timelines

The primary v3 information architecture remains unchanged.

## Regression focus

The v3.7 suite covers:
