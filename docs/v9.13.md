# Obol v9.13

v9.13 begins the representative Tool Builder migration on top of the stable v9.12 platform. The first completed migration is Nmap, because target discovery is the earliest high-value command-building surface in the normal Obol workflow.

## Canonical Nmap Tool Builder

`data/tool-builders.js` now registers `tb-nmap` through the stable `data/tool-builder-schema.js` registry. The builder exposes the existing discovery-oriented profiles plus explicit target, port scope, custom ports, timing, minimum rate, retry, default-script, version-detection, OS-detection, reason, DNS, and `-oA` output controls.

The generic `assets/tool-builder-current.js` renderer remains the only current Tool Builder renderer. It generates a deterministic command for the operator to review and copy. It does not execute Nmap or any other command.

The historical v3.1 Nmap profile behavior remains the compatibility baseline. v9.13 preserves the canonical command shapes for host discovery, quick TCP, full TCP, service/script, and top-UDP profiles while allowing explicit overrides without duplicating the profile port scope.

## Targets integration

`assets/app-v8.8.js` lazily loads the stable concrete builder registry on the Targets route and mounts `tb-nmap` inside the existing discovery surface. The old bespoke command controls are hidden only after the schema-driven builder mounts successfully.

The historical Nmap paste/intake path remains in place. The new form mirrors its current values into the compatibility controls so pasted Nmap output continues through the established parser, target-discovery, Evidence, and Next Steps flow rather than introducing a second Evidence owner.

This is an incremental ownership migration rather than a historical-layer rewrite. The parser and intake compatibility boundary can be retired only after equivalent Evidence behavior is independently consolidated and regression-protected.

## Platform refinement

The stable schema now permits a choice token to intentionally emit no command argument. That small backward-compatible capability lets generic builders represent states such as "no default port scope" or "DNS resolution enabled, therefore omit `-n`" without adding tool-specific compiler branches.

`tools/validate-tool-builder-platform.js` now loads concrete builder definitions and requires every inventory record marked `implemented` with a queue item to resolve to a registered schema-driven builder. Nmap profile and override behavior is protected by both the permanent platform validator and `tests/run-v9.13-tests.js`.

## Product contract

Obol remains browser-local and human-run:

- command generation is activity, not proof;
- copied commands are run externally by the operator in an authorized environment;
- manual success does not create host or service facts;
- reviewed Nmap output remains the Evidence boundary for report-ready host/service claims;
- no v9.13 `app`, `core`, project-model, or stylesheet overlay was added.
