# Obol v10.19 — privilege-helper modeled-tool slice

This is a compact Tool Builder current-owner continuation under the route-aware Tool Library plan. It burns down the visible privilege-escalation helper slice without changing Obol's browser-local execution boundary.

## What changed

- Implements pspy, accesschk, and searchsploit as schema-driven Tool Builders.
- Preserves linpeas and winPEAS as existing canonical helper builders instead of duplicating their route ownership.
- Adds `data/product-hardening/privesc-helper-tool-builders-current.js` as the compact owner for the new privilege-helper slice.
- Promotes the visible privilege-helper modeled tools to implemented inventory dispositions.
- Adds conservative Evidence recognition for process observations, permission leads, exploit-reference hits, no-hit states, blocked/failure states, partial helper output, and cleanup observations.

## Product behavior

- pspy has explicit run, chmod, and cleanup modes. Run mode is bounded by timeout and requires an explicit target-side pspy binary path.
- accesschk requires an explicit reviewed object, path, service, or principal and supports file, service, registry, and user/group review modes.
- searchsploit requires an explicit search query or exploit path and supports search, exact-match, path-print, and mirror modes.

## Proof boundary

These helpers produce privilege-escalation leads and references. pspy process output does not prove writeability or privilege escalation. accesschk permissions do not prove exploitability. searchsploit hits do not prove target applicability or safe exploitation. Separate validation and context Evidence are still required before Obol may treat any privilege, code execution, exploitability, or compromise fact as report-ready proof.

## Queue result

Together with the existing linpeas and winPEAS helper builders, this clears the visible privilege-escalation helper slice shown in the Tool Library for linpeas, winPEAS, pspy, accesschk, and searchsploit. It does not close the full modeled Tool Builder backlog.

## Compatibility

Obol remains static and browser-local. No command execution, backend, telemetry, account system, install prompt, local exploit execution, privilege escalation automation, or third-party service integration is added. Commands remain copy-only and human-reviewed.
