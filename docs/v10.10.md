# Obol v10.10

v10.10 is a product-hardening release that promotes Burp Suite out of legacy/example treatment and into first-class Tool Builder coverage.

## What changed

- Added a first-class Burp Suite guided workflow builder.
- Fixed the Burp Suite tool identity gap that made `#/tools/burp-suite` fall through as a legacy/example tool even though `burp suite` was present in the modeled inventory.
- Added guided proxy setup, browser proxying, target scope, sitemap capture, Repeater, Intruder, Scanner triage, and raw request/response import handoffs.
- Added executable Burp Evidence ingestion for Proxy history, raw HTTP request/response pairs, Repeater observations, Intruder result rows, Scanner issue details, sitemap/scope findings, vulnerability leads, and proxy/TLS failures.
- Kept Burp as a third-party GUI handoff instead of pretending Obol can drive the Burp GUI.

## Guided workflow contract

Burp Suite is not a terminal-first scanner. The v10.10 builder therefore produces a reviewed launch and handoff checklist instead of fake GUI automation.

The builder supports these workflow modes:

- Proxy listener and browser setup.
- Target scope and sitemap capture.
- Repeater request verification.
- Intruder payload-position handoff.
- Scanner issue triage.
- Raw request/response import.

The minimum preview starts from a real Burp launch plus the selected workflow, authorized target, proxy host, proxy port, and browser profile. Optional request source, payload position, wordlist, and paste-back checklist fields add guidance only when that workflow needs them.

## Evidence contract

The Burp Evidence owner recognizes decision-relevant pasted output without overclaiming:

- Burp GUI artifacts such as Proxy history, HTTP history, Target sitemap, Repeater, Intruder, and Scanner labels.
- Raw HTTP request/response pairs.
- Repeater observations.
- Intruder status/length/difference rows and payload-position context.
- Scanner issue detail with severity and confidence.
- Scope, redirect, cookie, auth, and session observations.
- Vulnerability-like behavior such as reflected input, SQL syntax errors, traversal leads, SSRF leads, deserialization leads, or command-injection leads.
- Proxy, TLS, certificate, connection, timeout, and other blocked/failure states.

These are conservative observations and leads. Captured traffic, Scanner alerts, reflected payloads, status-code changes, response-length deltas, cookies, redirects, and sitemap entries do not prove exploitability, authentication bypass, data access, code execution, or compromise without follow-up Evidence.

Remaining modeled groups still include network/host discovery, DNS/SNMP/AD collectors, remote execution/lateral movement, credential relay/capture helpers, pivot transports, privilege-escalation helpers, browser/request utilities beyond Burp Suite, cloud/container/database/service tooling, and controlled CVE/PoC wrappers.
