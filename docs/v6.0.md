## Evidence boundaries

The release deliberately keeps the following states separate:

- RMI registry discovery, vulnerability evidence, and an opened remote session.
- A sent Log4Shell JNDI probe, an explicit CVE/template match, and an independently observed callback.
- Tomcat/JBoss manager reachability, authenticated manager access, deployment attempts, and remote execution.
- Veeam product/service presence, CVE evidence, returned reusable credential material, and execution.
- Kerberos relay listener startup, successful relay, certificate/ticket material, and privilege.

No new v6.0 workflow promotes tool startup, service banners, generated artifacts, or connection attempts into administrator or SYSTEM facts.

## Tiered release validation

v6.0 changes release-branch CI so normal incremental development no longer produces a full regression run on every commit.

- Ordinary `release/obol-vX.Y` pushes run `tools/release-smoke.js`, which checks JavaScript syntax and verifies that local `index.html` asset references resolve.
- Commits containing `[preflight]` run `tools/release-preflight.js`, covering the coherent current-release snapshot without running the entire historical chain.
- Commits containing `[release-final]` run smoke, preflight, and the complete historical `test` job. Ready-for-review pull requests and `main` continue to run the complete protected test job.
- `tools/validate-historical-tests.js` rejects historical suites that hard-code mutable current-release README versions or exact live Build Next counts.

This reduces noisy red development history without relaxing merge readiness. The exact final head must still pass the release contract, historical regressions, quality-debt gate, README synchronization, and future-safety checks before merge.
