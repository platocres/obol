## Product output

The new Product Hardening extension is:

```text
data/product-hardening/credential-dump-remining-v9.61.js
```

It publishes these public-safe field-note outputs:

- `note-lsass-dump-artifact-proof-chain` — keeps dump creation, transfer/parse state, extracted material, cracking, validation, and cleanup as separate proof stages.
- `note-offline-parser-output-needs-material-classification` — prevents parser banners and logon-session blocks from being treated as usable credentials by themselves.
- `note-hash-crack-does-not-prove-service-access` — keeps cracked plaintext candidate state separate from scoped authentication proof.

It also publishes the analyzer ID:

```text
credential-dump-output-analyzer
```

The analyzer can classify pasted operator output into conservative facts such as:

- `credential.lsass_dump_artifact_observed`
- `credential.offline_dump_parser_output_observed`
- `credential.nt_hash_material_observed`
- `credential.hash_crack_plaintext_candidate_observed`
- `credential.validation_success_scoped`

Cracked material does not become access proof unless the pasted Evidence also contains scoped authentication success.

## Evidence and Next Steps boundary

This release adds Evidence ingestion for the credential-dump proof chain. The analyzer is deliberately conservative:

- a dump artifact only suggests an artifact-handling state;
- offline parser output only suggests parser review happened;
- NT material only suggests material requiring compatible routing;
- a crack result only suggests a plaintext candidate;
- scoped authentication success is required before the workflow can treat the material as access proof.

The output is visible through the path and credential context as field-note guidance and through Evidence ingestion as an activity/fact classifier. It does not execute commands.
