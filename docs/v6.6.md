# Obol v6.6

v6.6 is an architecture-consolidation release. It deliberately holds methodology and source-fidelity counts steady while making the project easier to understand and cheaper to extend.

## What changed

- Added `C.projectModel66(...)` as the single current projection for canonical progress, source-depth/source-fidelity progress, quality debt, Build Next, next priority, and recent release trend.
- Added `data/project-model-v6.6.js` as the current release/project metadata owner and `tools/current-runtime.js` as the shared Node-side loader used by current repository tooling.
- Rebuilt the default North Star Dashboard around a compact overview: current completion, source-audit progress, quality debt, queue size, recent progress, and the next priority are visible immediately.
- Kept engineering metrics, the atomic source-fidelity ledger, and the full Build Next queue available behind collapsed drill-downs instead of stacking them in the primary scan path.
- Split durable engineering documentation out of the README into `docs/ARCHITECTURE.md`, `docs/NORTH-STAR.md`, and `docs/PROOF-CONTRACT.md`.
- Kept the README as the project entry point, current snapshot, permanent North Star requirement surface, recent three-release summary, and generated Build Next snapshot.
- Updated README synchronization and release-quality validation to consume the consolidated project model instead of independently assembling or parsing current status.
- Changed the current release contract to be delta-based: v6.6 ships only its actual project-model, core, app, CSS, test, and documentation deltas rather than creating empty methodology/dashboard/Intake overlays solely because the version number changed.
- Established a permanent rule that new release overlays should represent behavior deltas rather than become parallel owners of project-wide truth.
- Made the historical v3.2 index-wiring regression future-safe by testing preserved script/style ordering and Nmap parser wiring instead of requiring an obsolete current-page version label.

## What did not change

- canonical methodology: **95 / 127 implemented, 32 partial, 0 gaps, 0 stale, 75% strict, 100% represented**;
- source fidelity: **1 / 17 source files atomized, 7 / 34 frozen partial baselines decomposed, 5 / 19 inventoried atomic units fidelity-complete**;
- Build Next: **41 items**, with zero implemented-quality repairs, zero mapped-delivery repairs, and zero canonical gaps;
- Evidence and proof semantics;
- browser-local workspace/state migration;
- command generation and human-run execution;
- Next Steps applicability;
- report lineage and proof readiness.

## Why historical runtime layers remain

The current browser runtime still loads many historical version overlays. Those layers contain accumulated behavior and are protected by historical regression tests. v6.6 does not remove them simply to make the file tree look clean.

Instead, v6.6 creates a consolidation boundary. Future compaction can replace one ownership area at a time, prove regression equivalence, and then remove only the layers that have genuinely become redundant.

This trades a risky rewrite for controlled reduction of technical debt while immediately fixing the parts users and developers have to reason about most often: project truth, Dashboard comprehension, README structure, and release-by-release bookkeeping.
