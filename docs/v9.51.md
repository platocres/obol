# Obol v9.51

v9.51 hardens the source-note re-mining handoff and dashboard tracking for the post-Orange product-hardening phase.

## Summary

This release does not mine new private notes. It makes the next notes work harder to misunderstand by turning source re-mining into the visible queue and dashboard priority.

The key change is that already-reviewed notes must be re-mined from the original private source notes under the expanded rubric before fresh pending-note packets become the default notes work.

## Source re-mining contract

The new `docs/NOTE-MINING-RUBRIC.md` defines full-spectrum source re-mining. Agents must return to the original private note rather than merely reviewing an existing public Field Note, prior rationale, prior disposition, or output ID.

Every re-mined note must be checked for:

- actual Next Steps / Orange path placement;
- tool cards;
- GUI switches, modes, and presets;
- scripts, one-liners, and command templates;
- terminal-output analyzers;
- Evidence expectations and proof boundaries;
- path movement logic;
- lesson boxes and rewritten examples;
- troubleshooting;
- cleanup and rollback;
- report guidance;
- product mechanics and product gaps;
- private-only boundaries.

## Actual Next Steps path requirement

Note-derived tools, scripts, one-liners, analyzers, lesson boxes, command templates, and branches are not considered fully productized if they live only in disconnected data, documentation, a dashboard-only list, or a hidden registry.

When a re-mining pass finds useful operator workflow material, it must be wired into the actual user-visible Next Steps / Orange path surface where the operator needs it. Valid destinations include an existing path point, child step, adjacent branch, existing or new tool card reachable from the path, Evidence analyzer, or contextual lesson box.

## Additive Orange baseline

The Orange-derived methodology path remains the baseline. Note re-mining is additive unless a separate migration item explicitly authorizes a structural replacement and proves equivalence.

Agents must not delete, narrow, or replace Orange path items during note work. They should attach to, extend, or branch from the existing path.

## No wrapper or layer shortcut

This release makes the no-wrapper rule explicit for notes, dashboard, path, tool, Evidence, and report work. Product-hardening changes should update stable current owners directly when possible rather than adding disposable overlays, wrappers, release-specific patch layers, or parallel registries that create future consolidation debt.

## Dashboard tracking

The existing Product Hardening Dashboard Notes Integration section now leads with source re-mining state instead of treating the legacy review funnel as the headline.

It shows:

- source re-mining gate;
- old-rubric-only notes;
- first-pass pending notes;
- actual path integration requirement;
- no disposable wrapper/layer shortcut requirement;
- full-spectrum extraction matrix;
- re-mining red flags;
- the older review, Field Note, binding, mechanic-conversion, theme, and gap metrics below the new gate.

## Compatibility

No workspace schema, command execution behavior, Evidence proof boundary, report generation behavior, or private-source boundary is intentionally changed.

Raw course prose, targets, flags, credentials, screenshots, exploit recipes, review-packet bodies, and private source paths remain outside public Obol.
