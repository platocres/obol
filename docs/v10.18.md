# Obol v10.18 — credential-helper modeled-tool slice

## What changed

- Implements the next compact modeled-tool burn-down slice for CeWL, crunch, hashid, and name-that-hash.
- Adds a stable current owner, `data/product-hardening/credential-helper-tool-builders-current.js`, instead of restoring disposable release-specific Tool Library layers.
- Promotes CeWL and crunch from modeled inventory into schema-driven wordlist helper builders.
- Promotes hashid and name-that-hash from modeled inventory into schema-driven hash-identification helper builders.
- Adds conservative Evidence recognition for target-derived wordlists, bounded generation plans, hash-identification candidates, inconclusive output, blocked/failure states, and partial helper output.

## Product behavior

- CeWL starts from the supplied authorized URL only. Depth, min/max word length, output file, numeric words, metadata, email harvesting, Basic auth, Cookie header, proxy, and verbosity are additive controls.
- crunch requires deliberate minimum and maximum length input before a command is valid. Charset, pattern, literal mode, output, compression, start/end blocks, and inverted output are explicit controls.
- hashid requires supplied hash material or a hash file before generating a command. Hashcat and John hint output are explicit toggles.
- name-that-hash / nth requires supplied hash material or a hash file before generating a command. Greppable and accessible text output are explicit toggles.

## Proof boundary

These helpers produce candidate material and routing hints. A generated wordlist does not prove a credential exists. A hash-identification result does not prove the true algorithm, recovered password, credential validity, or access. Downstream cracking and service-validation Evidence are still required before Obol can treat anything as report-ready proof.

## Queue result

This does not close the full modeled Tool Builder backlog. It burns down one obvious credential-helper slice from the remaining modeled inventory and leaves the active backlog in place for the next tool family.

## Compatibility

Obol remains static and browser-local. No command execution, backend, telemetry, account system, install prompt, password guessing automation, cracking execution, or third-party service integration is added. Commands remain copy-only and human-reviewed.
