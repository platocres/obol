# Obol v9.71 - action-spine guardrail, dynamic why-now, and AD/MSF re-mining

## Summary

v9.71 corrects the bad v9.70 card shape, adds dynamic why-now guidance for card routes, and builds the next Product Build Next queue item.

The main product rule is now explicit: a primary Next Steps card is an action step with lessons attached. Lessons, field notes, note summaries, and proof-boundary explanations are welcome on cards, but they must support a concrete command or GUI-tool action spine. A lesson-only or methodology-only item belongs in field notes, analyzer guidance, report wording, or an existing action-bearing card.

This release also preserves and implements the intended `why now` feature. Cards explain why a tool or command is useful at the current lab moment. What is forbidden is vague internal filler such as `fills an unresolved methodology gap`, source-mining provenance, release cleanup copy, or `UNKNOWN` tool scaffolding.

## Corrective cleanup

- Demotes `web-client-session-proof-chain` out of the primary card path.
- Preserves the useful client/session/XSS proof-boundary lessons as supporting context on existing web cards.
- Keeps the v9.70 client/session evidence analyzer available for pasted evidence review.
- Removes the v9.70 direct-route guard so the demoted card does not keep recreating itself.
- Normalizes `web-upload-inclusion-proof-chain` with real `tool/run/when/evidence` command entries instead of allowing a vague proof-chain card shape.
- Adds tests that fail `UNKNOWN` implementation/tool rows, blank commandless primary cards, internal methodology-gap filler, and primary note-derived cards without a concrete command or GUI action spine.

## Dynamic why-now delivery

Adds `data/product-hardening/dynamic-why-now-v9.71.js`, a shared card-route decorator and generator. The generator uses card prerequisites, produced facts, available workspace/fact state, current target hints when present, and the card's command or GUI-tool action to render a `Why this step now` section on retained primary cards.

The generated explanation follows this shape:

```text
current evidence/path state -> missing proof boundary -> command or GUI action -> produced fact or next path decision
```

The browser route smoke now requires exactly one dynamic why-now section on retained primary note-derived cards and their demoted aliases after canonicalization.
