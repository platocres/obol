# Obol v10.06

## What changed

v10.06 is a product-hardening release that restores the operator **scripts** experience on
the Tools route and starts the scripts/LOTL track. The script library carried rich usage guidance and contextual
builders in its data, but the current Tools owner had regressed to rendering only a name,
a one-line description, and the raw code. This release re-homes the full experience into
the stable current owner so the guidance the data already contains is visible again.

- `assets/tools-library-current.js` now renders each script with its category, its
  **When / Where / How** usage guidance, an **engagement-values** trail (each `{{param}}`
  the script references, shown with its current workspace value or `not set`), and — for
  scripts that declare a contextual builder — **GUI toggles, radios, and argument fields**
  that rebuild the command live. A search filter and per-script copy button are included.
- Scripts now **pre-fill target-collected parameters** (target IP, `lhost`/`lport`,
  domain, and a derived `base_dn`) into the command body from the browser-local workspace
  state, the same way a tool builder autofills collected material. Unset placeholders stay
  visible as `{{param}}` so a snippet reads as a template rather than a broken command.
- Builder control changes persist to the browser-local workspace (`C.updateScriptBuilder`)
  and re-render the previewed command without leaving the page.

This release also **decouples the pending Tool Builder batch labels from the site release
number**. The two remaining batches (shell/payload/privesc/transfer helpers, and the
implemented-tool Evidence cross-surface audit) are now named batches rather than
`v10.06`/`v10.07` headings, so tracks like the scripts work can advance the release version
without renumbering unfinished Tool Builder work. README, the canonical Tool Builder build
queue, and the dashboard queue projection are updated to match, and the v10.05 regression
suite is demoted off those version-coupled assertions.

Obol remains static and browser-local: no backend, telemetry, account system, install
prompt, or automatic command execution. Scripts stay offline, human-run copy/review
snippets.
