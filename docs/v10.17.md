# Obol v10.17 — route-aware product-hardening live-layer retirement

## What changed

- Makes product-hardening extension loading route-aware so the Tool Library no longer loads the full historical v9 product-hardening layer stack on cache-clear visits to `#/tools`.
- Keeps the compact current Tool Builder ownership live on Tools routes through `tool-builder-backlog-current.js` and `tool-builder-discovery-current.js`.
- Preserves the full historical product-hardening extension list for dashboard and non-Tools routes where older product-hardening route/card behavior may still be needed until it is separately compacted.
- Adds an explicit extension plan API so tests and future agents can tell the difference between historical release inventory and browser-live route loading.

## Why

After v10.16 and the follow-up current-owner Tool Builder work, Burp, network discovery, and AD/name-service builders were correctly consolidated into the compact discovery owner. The remaining visible layer problem came from `data/current-release.js`: loading the current release still injected the full v9 product-hardening extension list even when the operator opened the Tool Library.

That made a clean-cache `#/tools` visit look like Obol was still bootstrapping its archaeological record. v10.17 changes that behavior without deleting historical files or pretending all non-Tools product-hardening behavior has already been proven safe to retire.

## Product behavior

- `OBOL_RELEASE_IDENTITY.extensionPlan('tools')` now returns `mode: compact-tool-library`.
- The Tools route plan loads only the current Tool Builder backlog and discovery owners needed for the live Tool Library.
- `extensionPlan('dashboard')` and other non-Tools routes keep the full product-hardening list until their behavior is compacted and proven independently.
- The deferred-extension test path records the selected route-specific list instead of blindly recording every historical product-hardening fragment.

## Queue result

The Tool Builder backlog stays active. This release does not add another tool slice. It corrects the runtime/loading shape so future Tool Builder work can keep extending current owners without recreating a visible layer stack.

## Compatibility

Obol remains static and browser-local. No command execution, backend, telemetry, account system, install prompt, or third-party GUI automation is added. The change affects which product-hardening extension files are injected for the Tools route; historical files remain in the repository and in the full extension plan for routes that have not yet been compacted.
