# Obol v10.16

Product-hardening release v10.16 fixes the Tool Library layering regression after the modeled-tool burn-down releases. It compacts the recent Burp Suite and network/host discovery release owners into one current Tool Builder discovery owner and cleans the active Tool Builder queue so completed slices do not appear as pending work.

## What changed

- Added `data/product-hardening/tool-builder-discovery-current.js` as the current owner for Burp Suite plus masscan, Rustscan, naabu, fping, and nbtscan.
- Removed `data/product-hardening/burp-suite-tool-builder-v10.10.js` and `data/product-hardening/network-discovery-tool-builders-v10.15.js` from the live `data/current-release.js` extension list so the Tool Library no longer loads those release layers as part of normal startup.
- Kept Burp Suite as a first-class guided third-party GUI workflow with proxy setup, target scope, sitemap capture, Repeater, Intruder, Scanner triage, raw request/response import handoff, payload-position discipline, payload processing notes, grep/extract markers, scope/rate boundaries, and Burp Evidence ingestion.
- Kept masscan, Rustscan, naabu, fping, and nbtscan as implemented network/host discovery builders with minimum viable command generation, supplied/Evidence-derived prefill, additive controls, placeholder refusal, and network discovery Evidence ingestion.
- Cleaned the README Tool Builder queue and canonical Tool Builder queue doc so completed slices are not listed as active queue items and v10.15 is not described as the next modeled-tool build after it has merged.
- Added a current-owner hygiene rule: modeled-tool release slices must be folded into stable current owners or explicitly justified instead of accumulating live versioned Tool Library layers.

## Validation

- `tests/run-v10.16-tests.js` verifies that the current release loads the compact discovery owner, does not load the v10.10/v10.15 Tool Builder release layers live, preserves Burp and network builder behavior, preserves Evidence ingestion, keeps the v10.08 audit passing, and cleans the active queue wording.
- `tests/run-v10.10-tests.js` and `tests/run-v10.15-tests.js` now prove their historical behavior through the compact current owner instead of requiring old release layers to stay live forever.
- `tools/run-historical-contracts.js` wires v10.16 into the current-product regression phase.
- Generated release sync keeps README, CHANGELOG, index, and current-release projections aligned with v10.16.

## Compatibility

Obol remains static and browser-local: no backend, telemetry, account system, install prompt, third-party app control, or automatic command execution. The consolidation changes live ownership and loading shape only; it must not remove the user-facing Burp Suite, masscan, Rustscan, naabu, fping, or nbtscan builders or their Evidence behavior.
