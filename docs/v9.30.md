# Obol v9.30

## Themed Notes Burn-down begins

v9.30 starts the packet-based Notes Integration phase defined in `docs/NOTES-IMPACT.md`. The 556-note disposition item remains the umbrella requirement, while review work is performed as coherent subject packets and every modeled note records what public-safe product output it created or why contextual guidance is sufficient.

This release begins with the web upload and file-inclusion packet and reviews ten additional OffSec PEN-200 source notes from private bounded review material generated in `platocres/obol-source-notes`.

## Public-safe product outputs

Five new normalized outputs capture reusable lessons without publishing raw course text, lab targets, walkthroughs, flags, or private review bodies:

- resolve absolute, relative, and base-directory path behavior before widening traversal depth;
- derive likely file-read targets from observed platform, server, webroot, and error context instead of a fixed path cookbook;
- verify that the HTTP client preserves path transformations when traversal testing depends on dot-segments or encoded characters;
- treat file-valued parameters as traversal candidates, not proof, until one stable file-read response is reviewed;
- preserve the separate overwrite-impact boundary for non-executable uploads and require independent proof that a write actually occurred.

Four reviewed sources were explicitly superseded because their durable LFI, wrapper, RFI, and executable-upload lessons were already owned by the v9.26 through v9.28 normalized guidance. One lab-specific record remains private-reference-only.

## First note-driven product mechanics change

The v9.30 review produces the first explicitly declared code-level Notes Integration product change. The current curl Tool Builder now exposes **Preserve URL path (`--path-as-is`)** so an operator can stop curl from normalizing away dot-segments when a path-resolution or traversal hypothesis depends on the exact outgoing path.

The control remains human-run and reviewable. It does not infer traversal success, file readability, or impact. Returned HTTP behavior still has to be reviewed through Evidence before Obol records a durable fact.

## Dashboard compatibility

Notes Integration advances to schema 1.4.0. The stable Dashboard route owner now accepts compatible notes-review schemas at or above the v1.3 contract instead of freezing readiness to exactly v1.3.0. This keeps the v9.29 current-owner Dashboard architecture intact as note review evolves.

## Validation

The packet umbrella and `notes-packet-web-upload-inclusion` remain queued until their actual completion criteria are satisfied. v9.30 is measurable packet progress, not a premature packet close.
