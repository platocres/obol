## Public-safe product outputs

The first v9.30 wave added normalized guidance for path resolution, stack-derived file-read hypotheses, request-path preservation, file-valued parameter triage, and non-executable upload overwrite proof.

Packet closeout adds three more normalized outputs:

- temporary operator-hosted transfer endpoints are treated as engagement infrastructure with constrained exposure and cleanup expectations;
- web shells are treated as temporary command channels that require explicit command-result Evidence and cleanup rather than durable-access assumptions;
- server-side file write is a distinct fact from reachability, interpretation, configuration effect, authentication impact, or code execution.

Recipe-heavy payload catalogs, target-specific assessments, credentials, flags, and walkthrough outcomes remain private-reference-only instead of being copied into public Obol.

## First note-driven product mechanics change

The packet produced the first explicitly declared code-level Notes Integration product change. The current curl Tool Builder exposes **Preserve URL path (`--path-as-is`)** so an operator can prevent curl from normalizing away dot-segments when a path-resolution or traversal hypothesis depends on the exact outgoing path.

The control remains human-run and reviewable. It does not infer traversal success, file readability, or impact. Returned HTTP behavior still has to be reviewed through Evidence before Obol records a durable fact.

The packet records that product gap as closed and retains proof references to `assets/tool-builder-current.js` and `tests/run-v9.30-tests.js`.
